# 좋은 코딩 기법

## 좋은 소프트웨어 코드의 6가지 공통점

- 쉽게 읽을 수 있다 
  - 코드는 작성하는 시간보다 읽는 시간이 훨씬 크다
- 주석이 잘 작성되어 있다
  - 코드만으로 이해하기 어려운 부분 설명
- 코드 구조가 간결하다 
  - 가독성 향상
  - 복잡성 낮아 버그 줄일 수 있음
- 쉽게 변경할 수 있다
- 활용을 위해 관리할 수 있어야 한다 
  - 하드코딩된 값은 지양
  - 변경 추적
- 제 기능을 해야 한다 

## 좋은 코드 작성을 위한 규칙

- 최적화보다는 가독성이 우선
- 아키텍처 우선 개발
  - 모듈화
  - 테스트 및 디버깅 
- 테스트 커버리지 고려
- 간단하고 단순하게 코딩
- 주석은 보조적으로 사용
- 강한 응집과 느슨한 결합 추구 
- 코드 리뷰가 항상 좋은 것은 아니다
  - 각 팀원이 맡은 부분을 완전히 이해하는 것이 더 낫다
- 리팩토링은 작동하지 않는다 
  - 나중에 리팩토링할 생각하지 말고 처음부터 구조화된 코드 작성
- 한 번에 작성하지 말고 반복적으로 개발하라
- 자동화 도구를 사용하라

리뷰를 안 하면 내가 맡은 부분만 알고 전체적인 이해가 떨어지는 것 아닌가?
