# 구조 모델링

> 소프트웨어가 어떤 요소들로 이루어질 수 있는가 

> 어떤 객체들이 있고 그들 간의 관계는 어떠한지 정의 

> 클래스 다이어그램으로 표현 

## 객체 식별

> 유스 케이스 설명서를 이용해 객체를 식별하고 클래스로 정의 

> 클래스는 클래스명, 속성, 연산의 3요소로 구성 

- 문장 분석
  - 유스 케이스 설명서 문장 구성 요소 분석
  - 명사는 클래스, 동사는 연산, 형용사는 속성, 고유 명사는 인스턴스 등으로 매핑
- 일반 객체 목록
  - 도메인별로 나타나는 일반적 용어들을 목록화하고 클래스로 사용 
- 브레인스토밍
  - 프로젝트 관련자의 생각으로부터 객체 도출
  - 제약 없이 브레인스토밍해 다양한 객체 나열 
- 패턴 적용
  - 객체의 나열과 객체 간 관계를 미리 정의해놓은 패턴을 이용해 클래스로 사용

## 클래스 명세

> 클래스 명세는 CRC 카드를 이용해 작성

- 기본 정보 명세 
  - 앞면 : 클래스 이름, 식별자, 타입, 설명, 책임, 협력 관계, 관련 유스 케이스
- 속성 및 연산 명세 
  - 뒷면 : 클래스 속성, 연산, 관계 

## 클래스 다이어그램 작성

> 소프트웨어의 구조를 나타내는 클래스 다이어그램 작성 

- 일반화 관계 : 클래스들을 추상화하여 보편적인 클래스로 나타낸 관계 
- 집합 관계 : 다수의 클래스가 모여 하나의 집합체를 이루는 관계
- 연관 관계 : 그 외 관계 

- 속성 가시성 : 변수 접근 범위 (private, protected, public)
- 관계 기수성 : 두 클래스 간 몇 개의 인스턴스가 나타낼 수 있는가
