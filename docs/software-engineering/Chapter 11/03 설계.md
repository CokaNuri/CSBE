# 물리 구조 설계

> 컴포넌트를 구현할 기술을 정하고, 컴포넌트를 운영 환경의 하드웨어 플랫폼에 어떻게 배치할지 설계

## 배치 다이어그램 작성

> 어떤 패키지를 클라이언트에 배치하고 어떤 패키지를 서버에 배치할지 정의

![](deploy.png){ width=750, height=900 }

### 고려하는 아키텍처 환경

| 아키텍처 | 특징 |
|---|---|
| 서버 기반 | 처리를 서버가 담당 |
| 클라이언트 기반 | 처리를 클라이언트가 담당 |
| 클라이언트-서버 기반 | 처리를 양쪽이 나누어 담당 |
| 피어투피어 | 각 노드가 대등하게 서로 요청·응답 |
| 독립 운영 | 단독 환경에서 운영 |

### 모델 선택 시 고려 요소

- 개발 비용
- 개발 용이성
- 보안 통제
- 확장성
- 비기능적 요구사항 


## 기술 환경 명세

> 하드웨어 및 소프트웨어에 대한 세부 사항 명세<br>
> 이후 구현으로 이어짐

### 명세 항목

| 항목 | 명세 내용 |
|---|---|
| 하드웨어 | 서버·단말의 CPU, 메모리, 디스크, 스토리지 구성, 이중화 여부 |
| 운영체제 | 각 계층에 설치할 OS 종류와 버전 |
| 소프트웨어 | 웹 서버, WAS, DBMS, 미들웨어, 브라우저 등 구동 소프트웨어와 버전 |
| 네트워크 | 프로토콜과 포트, 방화벽, 부하 분산 장비 |

### 계층별 기술 환경 예시

| 구분 | 클라이언트 | 웹 서버 | 애플리케이션 서버 | DB 서버 |
|---|---|---|---|---|
| 하드웨어 | PC, 노트북, 스마트폰, 태블릿, 키오스크 | x86 랙 서버, L4/L7 스위치 | x86 랙 서버 | 고사양 서버 + 스토리지 |
| 운영체제 | Windows 11, macOS, Android, iOS | Linux, Windows Server | Linux | Linux, Unix |
| 소프트웨어 | 웹 브라우저, 전용 앱 | Apache HTTP Server, Nginx| Tomcat, JBoss, WebLogic, WebSphere, JEUS | Oracle, MySQL, MariaDB, PostgreSQL |
| 네트워크 | 인터넷, Wi-Fi, LTE/5G | HTTP/HTTPS(80·443) | 내부망, HTTP/AJP | 내부망, 방화벽 격리, DB 전용 포트 |

## 🔑 최종 정리 

하위 계층인 **DM**은 **자료 구조 설계**<br>

상위 계층인 **HCI**는 **사용자 인터페이스 설계**<br>

이후 **물리 구조 설계**<br>
패키지를 클라이언트와 서버 중 어디에 둘지 배치 다이어그램으로 정하고, 서버 기반 등의 아키텍처 중 적절한 모델을 선택

마지막으로 **기술 환경 명세**로 하드웨어와 소프트웨어 세부 사항을 확정하면 설계가 끝나고 구현으로 넘어감

> **한 줄 요약:** 계층별로 DM은 DB 테이블로, HCI는 화면으로 채운 뒤, 패키지를 어디에 배치할지 정하고 기술 환경을 명세하면 설계가 끝나고 구현이 시작
