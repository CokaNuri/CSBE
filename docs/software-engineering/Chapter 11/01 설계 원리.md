# 설계 원리

> **설계**: 객체지향 분석 이후, 분석 결과물을 소프트웨어 관점의 산출물로 전환하는 과정
>
> 모듈화와 설계 패턴을 이용해 **유지보수성**과 **성능**을 향상시킨다

---

## 설계의 기본 원리

| 원리 | 설명 | 얻는 효과 |
|---|---|---|
| 추상화  | 핵심 특징만 가려내어 추출하고, 나머지 세부사항은 감춰 대표적인 특징으로만 표현 | 복잡도 감소 |
| 단계적 상세화  | 상위 개념에서 출발해 클래스 멤버·제약사항 설계, 메서드 내부 로직 설계처럼 점점 구체화 | 하향식(Top-down) 구체화 |
| 모듈화  | 시스템을 독립적인 기능 단위로 분할 | 재사용성·확장성·유지보수성 향상 |
| 정보 은닉  | 참조 범위(접근 제한자) 설정을 통해 외부에 꼭 필요한 사항만 공개 | 결합도 감소, 변경 영향 최소화 |
| 관심사 분리  | 사용자 인터페이스, 자료 구조, 로직 등으로 관심사를 나누어 설계 | 변경의 국소화 |

---

## 분석 결과물을 설계 결과물로 발전시키는 방법

| 구분 | 나누는 기준 | 쪼갠 뒤 남는 관계 | 키워드 |
|---|---|---|---|
| 팩토링  | 모델 간 **유사점 / 차별점** | 일반화 관계, 집합 관계 | 중복 제거·재사용 |
| 파티셔닝  | 모델의 **크기 / 기능 단위** | 대등한 수준의 서브모듈 | 모듈화 |
| 계층화  | 구성 요소의 **성격 / 역할** | 상위 → 하위 방향의 의존을 갖는 층 | MVC 아키텍처 |

### 팩토링
- 모델을 유사점이나 차별점에 따라 별도의 모듈로 분리하는 과정
- 결과는 **일반화 과정**과 **집합 관계**로 정의됨

### 파티셔닝
- 큰 모델을 세부 모델로 나누는 과정
- **모듈화** 개념을 그대로 적용

### 계층화
- 시스템 구성 요소들을 서로 다른 특징의 그룹으로 분리하는 과정
- 대표적인 예: **MVC 아키텍처** — 사용자 인터페이스, 로직 처리, 데이터로 분리

한 줄로: 팩토링은 닮은 것끼리 뽑아내기, 파티셔닝은 큰 것을 옆으로 자르기, 계층화는 성격별로 위아래로 쌓기.

## 설계 단계의 산출물 흐름

| 단계 | 입력 | 산출물 |
|---|---|---|
| 클래스 다이어그램의 설계 모델화 | 분석 단계 클래스 다이어그램 | 클래스 내 상세 정보 + 메서드 내부 로직 |
| 패키지 구조 설계 | 클래스 다이어그램 | 패키지 다이어그램 |
| 화면·데이터 설계 | 클래스 다이어그램 | UI 클래스, DB 테이블 |
| 물리 구조 설계 | 시스템 구성 | 배치 다이어그램 |
| 구현 환경 확정 | 전체 설계 | 기술 스펙 정의 |

---

## 🔑 최종 정리 

분석 결과물은 "무엇을 만들 것인가"까지만 말해준다. 그대로는 코드로 옮길 수 없다. <br>
그래서 설계는 추상화로 핵심만 남기고, 단계적 상세화로 점점 구체화하며, 모듈화로 나누고, 정보 은닉으로 감추고, 관심사 분리로 성격이 다른 것을 섞지 않는다.

> **한 줄 요약:** 설계란 분석 결과를 쪼개고 감추어 유지보수 가능한 구조로 바꾼 뒤, 다이어그램 산출물로 확정하는 과정
