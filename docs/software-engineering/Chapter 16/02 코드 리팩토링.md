# 코드 리팩토링

> 코드 기능은 그대로 두고, 내부 구조를 개선하는 것

- 가독성과 이해도 향상
- 유지보수성 향상
- 결함 발견이 쉬워지고 확장에 유리해짐

### 사례 1. 메서드 추출 + 조건 분리 + 매직 넘버 상수화 - R26 + R34


**Before**

```java
public boolean hasValidChoices() {
    if (choices.size() != 4 ) {
        return false;
    }
    if (choices.stream().anyMatch(choice -> choice == null || choice.isBlank())) {
        return false;
    }
    if (choices.stream().distinct().count() != choices.size()) {
        return false;
    }
    return choices.stream().filter(choice -> choice.equals(answer)).count() == 1;
}
```

**After**

```java
public static final int CHOICES_NUMBER = 4;          // R26

public boolean hasValidChoices() {                    // R34
    return hasRequiredChoiceCount()
            && hasNoBlankChoice()
            && hasNoDuplicateChoice()
            && containsAnswer();
}

private boolean hasRequiredChoiceCount() { return choices.size() == CHOICES_NUMBER; }
private boolean hasNoBlankChoice()       { return choices.stream().noneMatch(String::isBlank); }
private boolean hasNoDuplicateChoice()   { return choices.stream().distinct().count() == choices.size(); }
private boolean containsAnswer()         { return answer != null && choices.contains(answer); }
```

### R38. 중첩 조건을 가드절로 대체

> 정상 경로를 들여쓰기 깊이에서 꺼내는 기법 <br>
> 예외·특이 케이스는 위에서 먼저 처리하고 반환

```java
// Before — 진짜 하려는 일(주문 취소)이 3단계 안쪽에 숨어 있음
public void cancelOrder(Order order) {
    if (order != null) {
        if (order.getStatus() == OrderStatus.PAID) {
            if (!order.isShipped()) {
                order.cancel();
                refundService.refund(order);
            } else {
                throw new AlreadyShippedException();
            }
        } else {
            throw new NotCancelableException();
        }
    } else {
        throw new OrderNotFoundException();
    }
}

// After — 못 하는 경우를 먼저 걸러내고, 정상 흐름은 맨 아래 한 덩어리
public void cancelOrder(Order order) {
    if (order == null) throw new OrderNotFoundException();
    if (order.getStatus() != OrderStatus.PAID) throw new NotCancelableException();
    if (order.isShipped()) throw new AlreadyShippedException();

    order.cancel();
    refundService.refund(order);
}
```


### R39. 조건을 다형성으로 대체

> 타입에 따라 갈리는 switch/if를 서브타입의 오버라이딩으로 옮긴다

> 새 타입이 추가될 때 조건문을 찾아다니며 고치지 않아도 된다

```java
// Before — 결제 수단이 추가될 때마다 이 switch를 찾아 고쳐야 함
public int calculateFee(PaymentType type, int amount) {
    switch (type) {
        case CARD:     return (int) (amount * 0.025);
        case TRANSFER: return 300;
        case POINT:    return 0;
    }
    throw new IllegalArgumentException("지원하지 않는 결제 수단입니다.");
}

// After — 각 결제 수단이 자기 수수료 계산을 책임짐
public interface PaymentMethod {
    int calculateFee(int amount);
}

public class CardPayment implements PaymentMethod {
    public int calculateFee(int amount) { return (int) (amount * 0.025); }
}

public class TransferPayment implements PaymentMethod {
    public int calculateFee(int amount) { return 300; }
}

public class PointPayment implements PaymentMethod {
    public int calculateFee(int amount) { return 0; }
}

// 호출부는 분기 없이 한 줄
int fee = paymentMethod.calculateFee(amount);
```


### R12. 클래스 추출

> 한 클래스가 두 가지 이상의 책임을 지고 있을 때 나눈다

```java
// Before — 주문 처리 서비스가 알림 문구 조립까지 담당
@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderRepository orderRepository;
    private final SmsSender smsSender;

    public void placeOrder(Order order) {
        orderRepository.save(order);
        String message = "[주문완료] " + order.getItemName()
                + " " + order.getQuantity() + "개, 총 " + order.getTotalPrice() + "원";
        smsSender.send(order.getPhoneNumber(), message);
    }
}

// After — 문구 조립은 별도 클래스로 분리, 서비스는 흐름만 담당
@Component
public class OrderMessageFormatter {
    public String orderCompleted(Order order) {
        return "[주문완료] " + order.getItemName()
                + " " + order.getQuantity() + "개, 총 " + order.getTotalPrice() + "원";
    }
}

@Service
@RequiredArgsConstructor
public class OrderService {
    private final OrderRepository orderRepository;
    private final OrderMessageFormatter messageFormatter;
    private final SmsSender smsSender;

    public void placeOrder(Order order) {
        orderRepository.save(order);
        smsSender.send(order.getPhoneNumber(), messageFormatter.orderCompleted(order));
    }
}
```

### R28. 집합 캡슐화

> 컬렉션 getter가 내부 리스트를 그대로 넘기면 외부에서 마음대로 추가·삭제할 수 있어 캡슐화가 깨진다

> 읽기 전용으로 노출하고, 변경은 도메인 메서드로만 열어 준다

```java
// Before — 외부에서 항목을 직접 넣으면 총액이 갱신되지 않아 상태가 깨짐
public class Order {
    private final List<OrderItem> items = new ArrayList<>();
    private int totalPrice;

    public List<OrderItem> getItems() { return items; }
}
// 호출부: order.getItems().add(newItem);   ← totalPrice는 그대로

// After — 변경은 도메인 메서드로만, 그 안에서 총액도 함께 갱신
public class Order {
    private final List<OrderItem> items = new ArrayList<>();
    private int totalPrice;

    public List<OrderItem> getItems() { return List.copyOf(items); }

    public void addItem(OrderItem item) {
        items.add(item);
        recalculateTotalPrice();
    }

    public void removeItem(String itemId) {
        items.removeIf(item -> item.getId().equals(itemId));
        recalculateTotalPrice();
    }

    private void recalculateTotalPrice() {
        totalPrice = items.stream().mapToInt(OrderItem::getPrice).sum();
    }
}
```
