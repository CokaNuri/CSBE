# 탐색기반 소프트웨어 공학

> 메타 휴리스틱을 기반으로 방대한 탐색 공간으로부터 최적의 솔루션을 찾는 방법

> 모든 경우를 다 검색하려고 하면 너무 많은 시간과 비용이 요구됨

## 탐색기반 소프트웨어 공학의 의미

> 유전자 알고리즘, 시뮬레이티드 어닐링, 타부 검색과 같은 메타 휴리스틱 검색 기술을 이용해 문제 해결

- 소프트웨어 공학의 문제는 대부분 **최적화 문제**로 연결된다
- 선형 프로그래밍이나 동적 프로그래밍 같은 기술은 대규모 소프트웨어 공학 문제를 해결하는 데 실용적이지 않다
- 너무 커서 전부 탐색할 수 없는 공간으로부터 **최적에 가깝거나 충분히 좋은 솔루션**을 찾는 것이 목적

<details><summary>메타 휴리스틱이란?</summary>

휴리스틱은 최적해를 보장하지는 못하지만 경험적으로 쓸 만한 해를 빠르게 찾는 방법 <br> 
메타 휴리스틱은 특정 문제에 종속되지 않고, 어떤 문제에도 적용할 수 있도록 일반화한 상위 수준의 탐색 전략
</details>

### 대표적인 메타 휴리스틱 기법

| 기법 | 아이디어 | 특징 |
|---|---|---|
| 랜덤 검색 | 해를 무작위로 뽑아 평가 | 가장 단순, 비교 기준(baseline)으로 사용 |
| 힐 클라이밍 | 현재 해의 이웃 중 더 나은 쪽으로만 이동 | 빠르지만 지역 최적해에 갇히기 쉬움 |
| 시뮬레이티드 어닐링 | 초기에는 나쁜 해로의 이동도 확률적으로 허용, 점차 확률을 낮춤 | 지역 최적해 탈출 가능 |
| 유전자 알고리즘 | 여러 해를 집단으로 두고 선택·교차·돌연변이로 세대 진화 | 넓은 공간을 병렬로 탐색 |
| 타부 검색 | 최근 방문한 해를 금지 목록에 넣어 재방문 차단 | 같은 곳을 맴도는 현상 방지 |

<details><summary>랜덤 검색은 무엇이고 왜 쓰는가?</summary>

탐색 공간에서 해를 무작위로 뽑아 적합도를 평가하고, 그중 가장 좋은 것을 남기는 가장 단순한 방법 <br>
성능 자체는 좋지 않지만, 새로 제안한 알고리즘이 정말 효과가 있는지 비교할 기준선으로 사용
</details>

<details><summary>힐 클라이밍은 무엇인가?</summary>

산을 오를 때 항상 더 높은 쪽으로만 발을 내딛는 방식 <br> 
현재 해의 이웃 해들을 평가해 지금보다 나은 것이 있으면 그쪽으로 이동하고, 더 나은 이웃이 없으면 멈춘다<br> 
구현이 쉽고 빠르지만, 주변보다만 높으면 멈추기 때문에 진짜 정상이 아닌 봉우리, 즉 지역 최적해에 갇히기 쉽다

</details>

<details><summary>시뮬레이티드 어닐링과 유전자 알고리즘, 타부 검색은 어떻게 다른가?</summary>

시뮬레이티드 어닐링은 금속을 서서히 식히는 과정에서 이름을 따왔다. 초기에는 더 나쁜 해로 이동하는 것도 확률적으로 허용해 넓게 탐색하다가, 온도가 내려가면서 그 확률을 줄여 점점 좋은 해 근처에 정착한다.

유전자 알고리즘은 하나의 해가 아니라 해의 집단을 유지한다. 적합도가 높은 해를 선택해 교차시키고 일부를 돌연변이시켜 다음 세대를 만든다. 여러 지점을 동시에 탐색하므로 지역 최적해에 덜 취약하다.

타부 검색은 최근에 방문한 해나 이동을 타부 리스트에 넣어 일정 기간 재방문을 금지한다. 같은 자리를 왔다 갔다 하는 순환을 막고 새로운 영역으로 밀어내는 것이 목적이다.
</details>

### 솔루션의 품질 측정

> 적합도 함수, 비용 함수, 목적 함수를 사용해 잠재적 솔루션의 품질을 측정

| 함수 | 의미 | 방향 |
|---|---|---|
| 적합도 함수 | 해가 얼마나 좋은지를 수치로 표현 | 최대화 |
| 비용 함수 | 해가 치르는 대가(오차, 시간, 자원 등)를 수치로 표현 | 최소화 |
| 목적 함수 | 문제가 달성하려는 목표를 수식으로 정의 | 문제에 따라 최대·최소 |

<details><summary>세 함수는 서로 다른 것인가?</summary>

본질적으로는 같은 역할을 하며, 부르는 관점만 다르다. 해의 품질을 하나의 숫자로 환산해 서로 비교할 수 있게 만드는 장치다. 좋을수록 값이 커지도록 정의하면 적합도 함수, 나쁠수록 값이 커지도록 정의하면 비용 함수라 부르고, 최적화 문제에서 목표 자체를 나타내는 일반적인 이름이 목적 함수다. 적합도 = -비용 처럼 부호만 뒤집어 서로 변환할 수 있다.
</details>

<details><summary>탐색기반 기법을 적용하려면 무엇을 준비해야 하는가?</summary>

두 가지가 핵심이다. 첫째, 해를 알고리즘이 다룰 수 있는 형태로 표현하는 방법(예: 테스트 케이스를 숫자 배열로). 둘째, 그 해의 품질을 숫자로 매기는 적합도 함수. 여기에 이웃 해를 만드는 연산자(교차, 돌연변이 등)까지 정의하면 어떤 메타 휴리스틱이든 그대로 붙여 쓸 수 있다.
</details>

### 탐색 과정

1. 랜덤하게 선택된 초기 상태에서 시작
2. 이웃하는 솔루션을 선택
3. 솔루션의 적합도를 평가
4. 현재보다 좋은 적합도라면, 현재 상태를 이웃 상태로 옮김
5. 이 과정을 반복
6. 지역 최댓값이나 전역 최댓값을 탐색

<details><summary>지역 최댓값과 전역 최댓값의 차이는?</summary>

지역 최댓값은 주변 이웃들보다는 높지만 전체에서 보면 최고가 아닌 봉우리이고, 전역 최댓값은 탐색 공간 전체에서 가장 높은 지점이다. 힐 클라이밍처럼 더 나은 쪽으로만 움직이는 방법은 지역 최댓값에 도달하면 멈춰 버린다. 시뮬레이티드 어닐링이나 유전자 알고리즘은 일시적으로 나쁜 해를 허용하거나 여러 지점을 동시에 탐색해 이 함정에서 빠져나오려 한다.
</details>

## 탐색기반 소프트웨어 공학의 적용

> 소프트웨어 개발 전 과정에 적용 가능 — 그중에서도 **테스트**에 가장 활발하게 적용

| 단계 | 적용 내용 |
|---|---|
| 계획 | 비용, 업무 규모, 스케줄, 작업 할당 등에 대한 예측 활동 |
| 분석 | 비용과 사용자 만족도, 리스크 등을 고려해 좋은 대안 탐색 |
| 설계 | 적절한 아키텍처 및 설계 패턴을 찾기 위해 최적화 알고리즘 적용 |
| 구현 | 구현된 프로그램을 실행 속도와 자원 사용 측면에서 최적화 |
| 테스트 | 테스트 케이스 자동 생성, 테스트 케이스 최소화, 테스트 케이스 우선순위 결정 |
| 유지보수 | 버그 탐색 및 자동 수정 |

<details><summary>왜 테스트 분야에 가장 활발하게 적용되는가?</summary>

적합도 함수를 정의하기가 쉽기 때문이다. 예를 들어 테스트 케이스 생성에서는 코드 커버리지나 목표 분기까지의 거리를 그대로 적합도로 쓸 수 있고, 결과도 실행만 시켜 보면 자동으로 측정된다. 반면 설계나 분석 단계는 "좋은 설계"를 수치로 환산하기 어려워 적합도 함수를 만들기가 훨씬 까다롭다. 측정이 자동화되고 객관적일수록 탐색기반 기법이 잘 들어맞는다.
</details>
