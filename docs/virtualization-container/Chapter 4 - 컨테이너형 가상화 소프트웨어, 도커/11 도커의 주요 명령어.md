# 도커의 주요 명령어

> 필수 명령어 소개 — 컨테이너와 이미지를 다루는 기본 명령과 도커 파일

## 도커 명령어를 사용할 수 있는 환경

| 환경 | 내용 |
|---|---|
| 리눅스 | 도커 엔진을 직접 설치 — 서버 운영 환경의 기본 |
| Windows / macOS | **도커 데스크톱** 설치 — 내부의 리눅스 가상 머신에서 도커 엔진 실행 |
| 클라우드 | 가상 서버에 도커 설치, 또는 브라우저에서 쓰는 클라우드 셸 |
| 온라인 실습 환경 | Play with Docker — 설치 없이 브라우저에서 실습 |

```bash
docker version     # 클라이언트와 서버(데몬)의 버전 확인
docker info        # 도커 환경 정보 (컨테이너·이미지 수, 스토리지 드라이버 등)
```

---

## 도커 명령어의 기본

```
docker [대상] [동작] [옵션] [인수]

예) docker container run -d -p 8080:80 nginx
           └ 대상 ┘  └동작┘ └── 옵션 ──┘ └인수(이미지)┘
```

- 대상 : `container`, `image`, `network`, `volume` 등 — 도커 객체 단위
- 기존 방식의 짧은 명령도 그대로 사용 가능 (`docker container run` = `docker run`)
- `docker --help`, `docker run --help` : 사용법 확인

## 컨테이너의 시작/분리/표시/정지/삭제

| 작업 | 명령 | 내용 |
|---|---|---|
| 시작 | `docker run [옵션] 이미지` | 컨테이너 생성 + 시작 (이미지가 없으면 자동 pull) |
| 분리 | `docker run -d` / `Ctrl+P, Ctrl+Q` | 백그라운드 실행 / 접속한 컨테이너에서 빠져나오기(컨테이너는 계속 실행) |
| 표시 | `docker ps` | 실행 중인 컨테이너 목록 (`-a` : 정지된 것 포함) |
| 접속 | `docker exec -it 컨테이너 bash` | 실행 중인 컨테이너에서 명령 실행 |
| 로그 | `docker logs 컨테이너` | 컨테이너의 출력 확인 (`-f` : 계속 따라가기) |
| 정지 | `docker stop 컨테이너` | 컨테이너 정지 |
| 삭제 | `docker rm 컨테이너` | 정지된 컨테이너 삭제 (`-f` : 실행 중이어도 삭제) |

**run의 주요 옵션**

| 옵션 | 의미 |
|---|---|
| `-d` | 백그라운드(분리 모드)로 실행 |
| `-it` | 터미널을 연결해 대화형으로 실행 |
| `--name 이름` | 컨테이너 이름 지정 |
| `-p 호스트포트:컨테이너포트` | 포트 공개 |
| `-v 볼륨:경로` | 볼륨 마운트 |
| `-e 변수=값` | 환경 변수 설정 |
| `--rm` | 정지 시 자동 삭제 |

```bash
docker run -d --name web -p 8080:80 nginx    # 시작
docker ps                                    # 표시
docker stop web                              # 정지
docker rm web                                # 삭제
```

## 컨테이너 이미지의 생성/표시/삭제

| 작업 | 명령 | 내용 |
|---|---|---|
| 내려받기 | `docker pull 이미지:태그` | 레지스트리에서 이미지 다운로드 |
| 생성 | `docker commit 컨테이너 이미지:태그` | 컨테이너의 현재 상태를 이미지로 저장 |
| 생성 | `docker build -t 이미지:태그 .` | 도커 파일로 이미지 빌드 |
| 표시 | `docker images` | 로컬에 있는 이미지 목록 |
| 이력 | `docker history 이미지` | 이미지를 구성하는 레이어 확인 |
| 이름 붙이기 | `docker tag 원본 새이름:태그` | 이미지에 다른 이름·태그 부여 |
| 올리기 | `docker push 이미지:태그` | 레지스트리에 이미지 업로드 |
| 삭제 | `docker rmi 이미지` | 이미지 삭제 (그 이미지로 만든 컨테이너가 있으면 불가) |

## 도커 파일로 컨테이너 이미지 생성

> 도커 파일(Dockerfile) : 이미지를 만드는 절차를 순서대로 적은 텍스트 파일

| 명령 | 역할 |
|---|---|
| `FROM` | 베이스 이미지 지정 |
| `WORKDIR` | 작업 디렉터리 지정 |
| `COPY` / `ADD` | 호스트의 파일을 이미지로 복사 |
| `RUN` | **빌드 시** 실행할 명령 (패키지 설치 등) |
| `ENV` | 환경 변수 설정 |
| `EXPOSE` | 컨테이너가 사용하는 포트 명시 |
| `CMD` / `ENTRYPOINT` | **컨테이너 시작 시** 실행할 명령 |

```dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["python", "app.py"]
```

```bash
docker build -t myapp:1.0 .            # 현재 디렉터리의 Dockerfile로 빌드
docker run -d -p 8000:8000 myapp:1.0   # 만든 이미지로 컨테이너 실행
```

## 도커 명령어를 사용하는 곳

| 장면 | 사용 예 |
|---|---|
| 개발 PC | DB·캐시 등 개발 환경을 컨테이너로 준비, 이미지 빌드와 동작 확인 |
| CI/CD 파이프라인 | 코드가 올라오면 자동으로 build → 테스트 → push |
| 운영 서버 | 이미지를 pull해 컨테이너 실행, 로그·상태 확인 |
| 장애 조사 | `logs`, `exec`, `inspect`, `stats` 로 원인 파악 |

- 여러 컨테이너를 함께 다룰 때는 **도커 컴포즈**(`docker compose up`)로 정의 파일 하나에 묶어 실행
- 쿠버네티스를 쓰는 운영 환경에서는 컨테이너 조작은 kubectl이 맡고, docker 명령은 주로 **이미지 빌드**에 사용

<details><summary>RUN과 CMD는 둘 다 명령을 실행하는데 무엇이 다를까?</summary>

RUN은 이미지를 빌드할 때 실행되어 그 결과가 이미지의 레이어로 저장된다. 패키지 설치처럼 환경을 만드는 작업에 쓴다. <br>
CMD는 빌드 때는 실행되지 않고, 그 이미지로 컨테이너를 시작할 때 실행할 기본 명령을 지정한다. <br>
즉 RUN은 "이미지에 무엇을 넣을지", CMD는 "컨테이너가 무엇을 할지"를 정한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 도커 명령은 `docker [대상] [동작]` 형태로, run·ps·stop·rm으로 컨테이너를 시작·표시·정지·삭제하고 pull·build·images·rmi·push로 이미지를 다루며, 도커 파일에 FROM·RUN·COPY·CMD 등으로 생성 절차를 적어 build하는 것이 이미지 생성의 기본이다
