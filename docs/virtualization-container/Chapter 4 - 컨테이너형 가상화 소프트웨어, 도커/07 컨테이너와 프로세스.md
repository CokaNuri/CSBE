# 컨테이너와 프로세스

> 프로세스별로 컨테이너 나누기 — 하나의 컨테이너에는 하나의 역할만 담고, 남겨야 할 데이터는 볼륨에 둔다

## 하나의 컨테이너에 하나의 프로세스가 기준

- 컨테이너는 **메인 프로세스(PID 1)** 가 실행되는 동안만 살아 있음
- 그래서 웹 서버·애플리케이션·데이터베이스를 한 컨테이너에 몰아넣지 않고 **역할별로 컨테이너를 분리**

```
[나쁜 예]  컨테이너 1개 : 웹 서버 + 애플리케이션 + DB

[좋은 예]  컨테이너 A : 웹 서버 (Nginx)
           컨테이너 B : 애플리케이션
           컨테이너 C : DB (MySQL)        ← 컨테이너끼리는 네트워크로 통신
```

- "프로세스 1개"는 엄밀한 규칙이라기보다 **하나의 컨테이너 = 하나의 관심사**라는 원칙
  (웹 서버가 워커 프로세스를 여러 개 띄우는 것은 문제없음)

---

## 프로세스별로 컨테이너를 나눌 때 장점

| 장점 | 내용 |
|---|---|
| 독립적인 갱신 | 애플리케이션만 바꿀 때 DB 컨테이너는 그대로 둠 |
| 독립적인 확장 | 부하가 걸리는 컨테이너만 수를 늘림 |
| 장애 격리 | 한 프로세스의 문제가 다른 컨테이너로 번지지 않음 |
| 재사용 | 공식 이미지(nginx, mysql 등)를 그대로 조합해 사용 |
| 관리 단순화 | 컨테이너 상태 = 프로세스 상태 → 감시·재시작·로그 수집이 명확 |
| 이미지 경량화 | 필요한 것만 담아 크기가 작고 취약점도 줄어듦 |

---

## 프로세스별로 컨테이너를 나눌 때 단점

| 단점 | 내용 |
|---|---|
| 컨테이너 수 증가 | 관리 대상이 늘어 구성이 복잡해짐 |
| 컨테이너 간 연결 필요 | 네트워크·기동 순서·의존 관계를 따로 설정 |
| 장애 원인 추적 | 여러 컨테이너에 걸친 로그를 모아서 봐야 함 |
| 통신 오버헤드 | 같은 호스트 안에서도 네트워크를 거쳐 통신 |

- 해결 수단 : 여러 컨테이너를 한 파일로 정의하는 **도커 컴포즈**, 다수 호스트의 컨테이너를 관리하는 **오케스트레이션 도구**(스웜 모드, 쿠버네티스)

---

## 볼륨이란

> 볼륨(volume) : 컨테이너의 데이터를 **컨테이너 밖(호스트)** 에 보관하는 저장 영역 — 컨테이너를 삭제해도 데이터가 남음

- 컨테이너에서 쓴 데이터는 컨테이너 레이어에 기록 → 컨테이너를 삭제하면 **함께 사라짐**
- 볼륨을 컨테이너의 디렉터리에 연결(마운트)하면 그 경로의 데이터는 호스트에 저장

| 종류 | 저장 위치 | 특징 | 용도 |
|---|---|---|---|
| 볼륨 | 도커가 관리하는 영역 (`/var/lib/docker/volumes`) | 도커 명령으로 관리, 호스트 경로에 의존하지 않음 | DB 데이터 등 영속 데이터 (**권장**) |
| 바인드 마운트 | 사용자가 지정한 호스트 경로 | 호스트의 파일을 그대로 공유 | 개발 중 소스 코드 공유, 설정 파일 전달 |
| tmpfs 마운트 | 호스트의 메모리 | 컨테이너가 멈추면 사라짐 | 임시 데이터, 디스크에 남기면 안 되는 정보 |

```bash
docker volume create db-data                       # 볼륨 생성
docker run -d -v db-data:/var/lib/mysql mysql      # 볼륨을 컨테이너 경로에 마운트
docker run -d -v $(pwd)/html:/usr/share/nginx/html nginx   # 바인드 마운트
```

- 여러 컨테이너가 같은 볼륨을 마운트해 **데이터 공유**도 가능

<details><summary>DB 컨테이너를 새 버전 이미지로 교체하면 데이터는 어떻게 될까?</summary>

데이터 디렉터리를 볼륨에 두었다면 기존 컨테이너를 삭제하고 새 이미지로 컨테이너를 만들어 같은 볼륨을 마운트하면 데이터가 그대로 이어진다. <br>
볼륨 없이 컨테이너 레이어에만 저장했다면 컨테이너 삭제와 함께 데이터도 사라진다. <br>
이처럼 컨테이너(실행 환경)와 데이터(상태)를 분리해 두어야 컨테이너를 일회용으로 다룰 수 있다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 컨테이너는 하나의 프로세스(역할)만 담는 것이 기준이며, 이렇게 나누면 갱신·확장·장애 격리가 쉬워지는 대신 컨테이너 수와 연결 설정이 늘어나고, 컨테이너를 삭제해도 남아야 하는 데이터는 볼륨이나 바인드 마운트로 컨테이너 밖에 보관한다
