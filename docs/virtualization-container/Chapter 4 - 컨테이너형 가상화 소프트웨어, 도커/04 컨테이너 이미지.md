# 컨테이너 이미지

> 컨테이너를 실행하기 위한 템플릿 — 애플리케이션과 실행 환경을 하나로 묶은 읽기 전용 파일 묶음

## 컨테이너 이미지란

> 컨테이너 이미지 : 컨테이너 실행에 필요한 **파일 시스템과 설정 정보**를 모아 둔 읽기 전용 템플릿

| 이미지에 담기는 것 | 예 |
|---|---|
| OS의 사용자 공간 | 셸, 기본 명령어, 라이브러리 |
| 미들웨어·런타임 | Nginx, JDK, Python |
| 애플리케이션 | 소스 코드, 실행 파일 |
| 메타데이터 | 실행할 명령, 환경 변수, 공개할 포트 |

**이미지와 컨테이너의 관계**

| 구분 | 이미지 | 컨테이너 |
|---|---|---|
| 성격 | 템플릿 (정적) | 실행 중인 인스턴스 (동적) |
| 변경 | 읽기 전용 | 쓰기 가능한 레이어가 추가됨 |
| 비유 | 클래스, 붕어빵 틀 | 객체, 붕어빵 |

- 하나의 이미지로 **여러 컨테이너**를 생성 가능
- 이미지는 여러 **레이어**가 겹쳐진 구조 → 같은 레이어는 이미지끼리 공유

## 컨테이너 이미지의 생성

| 방법 | 내용 | 특징 |
|---|---|---|
| 도커 파일로 빌드 (`docker build`) | 절차를 적은 도커 파일을 읽어 자동 생성 | **권장** — 재현 가능, 버전 관리 가능 |
| 컨테이너에서 생성 (`docker commit`) | 실행 중인 컨테이너를 수정한 뒤 그 상태를 이미지로 저장 | 어떤 작업을 했는지 기록이 남지 않음 |

```dockerfile
FROM ubuntu:22.04                      # 베이스 이미지
RUN apt-get update && apt-get install -y nginx   # 패키지 설치
COPY index.html /var/www/html/         # 파일 복사
CMD ["nginx", "-g", "daemon off;"]     # 컨테이너 시작 시 실행할 명령
```

- **베이스 이미지** : 새 이미지를 만들 때 토대가 되는 이미지 — 그 위에 변경 사항을 레이어로 쌓음

## 컨테이너 이미지의 배포

```
개발 PC                    레지스트리                  운영 서버
build → 이미지 ──push──▶  이미지 저장소  ──pull──▶  이미지 → run → 컨테이너
```

| 단계 | 명령 | 내용 |
|---|---|---|
| 빌드 | `docker build` | 도커 파일로 이미지 생성 |
| 업로드 | `docker push` | 이미지를 레지스트리에 등록 |
| 다운로드 | `docker pull` | 레지스트리에서 이미지 내려받기 |
| 실행 | `docker run` | 이미지로 컨테이너 생성·시작 |

- 이미지 자체를 전달하므로 받는 쪽에서 환경을 다시 구축할 필요가 없음
- 이미 가진 레이어는 건너뛰고 **없는 레이어만** 전송

## 컨테이너 이미지는 운영 체제 설치 디스크와 같은 것일까?

| 구분 | OS 설치 디스크 (ISO) | 컨테이너 이미지 |
|---|---|---|
| 내용 | 커널을 포함한 OS 전체 + 설치 프로그램 | 커널을 **제외한** 파일 + 애플리케이션 |
| 사용 방법 | 설치 과정을 거쳐야 사용 | 설치 없이 **바로 실행** |
| 결과물 | 범용 OS 환경 | 특정 애플리케이션을 위한 환경 |
| 크기 | GB 단위 | 수 MB ~ 수백 MB |
| 구조 | 하나의 덩어리 | 레이어의 겹침 |

- 설치 디스크는 "OS를 설치하기 위한 재료", 컨테이너 이미지는 "이미 구성이 끝난 실행 환경의 스냅숏"
- 가상 서버의 **머신 이미지**(AMI 등)와 역할은 비슷하지만, 커널을 포함하지 않아 훨씬 가벼움

<details><summary>docker commit보다 도커 파일로 이미지를 만드는 것이 권장되는 이유는?</summary>

commit은 컨테이너 안에서 손으로 작업한 결과만 저장하므로 어떤 절차로 만들어졌는지 알 수 없고 똑같이 다시 만들기도 어렵다. <br>
도커 파일은 생성 절차가 텍스트로 남아 Git으로 변경 이력을 관리하고 코드 리뷰도 할 수 있다. <br>
또한 CI 도구가 도커 파일을 읽어 자동으로 빌드할 수 있어 자동 빌드·배포와 잘 맞는다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 컨테이너 이미지는 커널을 제외한 OS 사용자 공간·미들웨어·애플리케이션·실행 설정을 레이어로 묶은 읽기 전용 템플릿으로, 주로 도커 파일로 빌드해 레지스트리에 push/pull하는 방식으로 배포하며, 설치 과정 없이 바로 실행된다는 점에서 OS 설치 디스크와 다르다
