# 도커가 주목받는 이유

> 도커의 역사와 발전을 되돌아보자 — 사내 도구에서 출발해 컨테이너 표준(OCI)의 토대가 되기까지

## 도커의 역사

| 연도 | 사건 |
|---|---|
| 2008 | PaaS 사업자 dotCloud 설립 — 자사 서비스 기반으로 컨테이너 기술 사용 |
| 2013 | 사내 컨테이너 기술을 **도커**라는 이름의 오픈 소스로 공개, 회사명도 Docker, Inc.로 변경 |
| 2014 | 도커 1.0 출시 — LXC 의존을 벗어나 자체 라이브러리(libcontainer) 사용 |
| 2015 | **OCI** 설립, 도커가 컨테이너 런타임(runC)과 이미지 형식을 기증 |
| 2016 | 도커 엔진에 **스웜 모드** 내장 — 클러스터 관리 기능 제공 |
| 2017 | containerd를 CNCF에 기증, 도커 프로젝트의 오픈 소스 부분을 Moby로 분리 |
| 2019 | 도커 엔터프라이즈 사업을 Mirantis에 매각 — 개발자 도구에 집중 |

---

## 도커의 주목도

- 공개 직후부터 개발자 커뮤니티에서 빠르게 확산
- AWS·구글·마이크로소프트 등 주요 클라우드 사업자가 도커 컨테이너를 실행하는 서비스를 잇달아 제공
- 도커 허브에 공개 이미지가 쌓이면서 **생태계**가 형성 → 이용자가 늘수록 더 편리해지는 구조
- 쿠버네티스 등 오케스트레이션 도구도 도커 이미지를 전제로 발전

---

## 도커가 주목받는 이유

| 이유 | 내용 |
|---|---|
| 쉬운 사용법 | 복잡한 커널 기능(네임스페이스, cgroups)을 `docker run` 한 줄로 사용 |
| 이미지라는 배포 단위 | 애플리케이션 + 실행 환경을 하나로 묶어 그대로 전달 |
| 도커 파일 | 환경 구축 절차를 코드로 기록 → 누구나 같은 이미지 생성 |
| 도커 허브 | 이미지를 올리고 내려받는 공유의 장 |
| 차분 관리(레이어) | 바뀐 부분만 전송·저장 → 빠른 배포 |
| 시대적 요구 | 데브옵스·마이크로서비스·클라우드의 확산과 맞물림 |

**기존 컨테이너 기술(LXC 등)과 차이**

| 구분 | 기존 컨테이너 기술 | 도커 |
|---|---|---|
| 초점 | 가벼운 가상 머신처럼 OS 환경을 격리 | **애플리케이션** 단위의 패키징과 배포 |
| 환경 구성 | 수작업 설정 | 도커 파일로 자동화 |
| 공유 | 표준 방법 없음 | 이미지 + 레지스트리 |

---

## 컨테이너 기술의 발전을 지원하는 OCI

> OCI(Open Container Initiative) : 컨테이너의 **업계 표준**을 정하기 위해 2015년 리눅스 재단 산하에 설립된 단체

- 도커, CoreOS, 구글, 마이크로소프트, 레드햇 등이 참여
- 특정 기업의 기술에 종속되지 않도록 **런타임과 이미지 형식을 표준화**

| 표준 | 내용 |
|---|---|
| 런타임 명세 (runtime-spec) | 컨테이너를 어떻게 실행할지 — 참조 구현이 **runC** |
| 이미지 명세 (image-spec) | 컨테이너 이미지의 형식 |
| 배포 명세 (distribution-spec) | 레지스트리와 이미지를 주고받는 방법 |

```
도커로 빌드한 이미지 (OCI 형식)
   → Podman, containerd, CRI-O 등 OCI를 따르는 어떤 런타임에서도 실행 가능
```

<details><summary>도커가 핵심 기술을 OCI에 기증한 것이 왜 중요할까?</summary>

표준이 없으면 컨테이너 도구마다 이미지 형식과 실행 방식이 달라져 서로 호환되지 않는다. <br>
도커가 런타임(runC)과 이미지 형식을 기증해 표준이 만들어지면서, 어떤 도구로 만든 이미지든 어떤 런타임에서든 실행할 수 있게 되었다. <br>
그 결과 이용자는 특정 기업에 종속되지 않고, 도커 이외의 다양한 컨테이너 기술도 같은 생태계 안에서 발전할 수 있었다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 도커는 2013년 dotCloud의 사내 기술이 오픈 소스로 공개된 뒤, 쉬운 명령어·이미지·도커 파일·도커 허브로 컨테이너를 애플리케이션 배포 단위로 만들어 급속히 확산되었고, 런타임과 이미지 형식을 OCI에 기증해 컨테이너 표준의 토대가 되었다
