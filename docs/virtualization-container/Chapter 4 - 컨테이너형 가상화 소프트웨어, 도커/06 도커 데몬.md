# 도커 데몬

> 도커 엔진을 지원하는 가장 중요한 요소 — 호스트에 상주하며 컨테이너와 이미지를 실제로 관리하는 서버 프로세스

## 도커 엔진을 구성하는 세 구성 요소

| 구성 요소 | 역할 |
|---|---|
| 도커 데몬 (dockerd) | 백그라운드에서 상주하는 **서버** — API 요청을 받아 도커 객체를 생성·관리 |
| 도커 API (REST API) | 데몬에 작업을 지시하는 **인터페이스** |
| 도커 클라이언트 (docker CLI) | 사용자의 명령을 API 요청으로 바꿔 데몬에 전달 |

```
┌──────────────┐   REST API    ┌──────────────┐       ┌────────────┐
│ 도커 클라이언트 │ ───────────▶ │   도커 데몬    │ ────▶ │ containerd │ ──▶ runC ──▶ 컨테이너
│ (docker CLI) │ ◀─────────── │   (dockerd)  │       └────────────┘
└──────────────┘     응답      └──────┬───────┘
                                      │ pull / push
                                      ▼
                                   레지스트리
```

- 데몬 : 사용자와 직접 상호 작용하지 않고 백그라운드에서 계속 동작하는 프로세스
- 실제 컨테이너 실행은 데몬이 **containerd → runC** 에 위임

---

## 도커 객체란

> 도커 객체 : 도커 데몬이 생성하고 관리하는 대상

| 객체 | 내용 |
|---|---|
| 이미지 | 컨테이너를 만들기 위한 읽기 전용 템플릿 |
| 컨테이너 | 이미지를 실행한 인스턴스 |
| 네트워크 | 컨테이너끼리 또는 컨테이너와 외부가 통신하기 위한 가상 네트워크 |
| 볼륨 | 컨테이너의 데이터를 영속적으로 보관하는 저장 영역 |

- 그 밖에 스웜 모드에서는 서비스, 노드 등도 객체로 다룸
- `docker image ...`, `docker container ...`, `docker network ...`, `docker volume ...` 처럼 명령어도 객체 단위로 구성

## 도커 데몬과 통신

| 통신 방법 | 내용 | 용도 |
|---|---|---|
| 유닉스 소켓 | `/var/run/docker.sock` 파일을 통한 통신 | 같은 호스트의 클라이언트 (기본값) |
| TCP 소켓 | 네트워크를 통한 통신 (2375 평문, 2376 TLS) | **원격 호스트**의 데몬 조작 |

- 클라이언트와 데몬이 **같은 호스트에 없어도** 됨 → PC의 docker 명령으로 원격 서버의 컨테이너 조작 가능
- docker CLI뿐 아니라 API를 사용하는 프로그램(SDK, 도커 컴포즈, CI 도구)도 데몬과 통신 가능

## 여러 구성 요소로 나누어져 있을 때의 장점

| 장점 | 내용 |
|---|---|
| 원격 조작 | 클라이언트만 설치하면 다른 호스트의 데몬을 조작 |
| 다양한 클라이언트 | API만 맞으면 CLI·GUI·자동화 도구 등 무엇이든 사용 가능 |
| 독립적인 교체·갱신 | 구성 요소별로 개선·교체가 쉬움 (런타임을 containerd·runC로 분리) |
| 재사용 | 분리된 containerd는 도커 없이 쿠버네티스에서도 사용 |
| 안정성 | 데몬을 재시작해도 실행 중인 컨테이너를 유지하도록 구성 가능 (live restore) |

<details><summary>도커 소켓(/var/run/docker.sock)을 컨테이너에 마운트하면 왜 위험할까?</summary>

도커 소켓에 접근할 수 있다는 것은 도커 데몬에 어떤 명령이든 내릴 수 있다는 뜻이다. <br>
데몬은 보통 root 권한으로 동작하므로, 소켓을 가진 컨테이너는 호스트의 디렉터리를 마운트한 새 컨테이너를 띄우는 식으로 호스트 전체를 장악할 수 있다. <br>
TCP로 데몬을 공개할 때 TLS 인증 없이 여는 것도 같은 이유로 위험하다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 도커 엔진은 상주 서버인 도커 데몬, 작업을 지시하는 REST API, 명령을 전달하는 도커 클라이언트로 구성되고, 데몬은 이미지·컨테이너·네트워크·볼륨이라는 도커 객체를 관리하며, 유닉스 소켓이나 TCP로 통신하도록 역할이 나뉘어 있어 원격 조작과 다양한 도구 연동이 가능하다
