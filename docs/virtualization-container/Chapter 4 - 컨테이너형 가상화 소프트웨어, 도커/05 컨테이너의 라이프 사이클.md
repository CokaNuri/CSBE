# 컨테이너의 라이프 사이클

> 컨테이너 생성에서 삭제까지 — 컨테이너는 만들고, 실행하고, 멈추고, 버리는 일회용 실행 환경

## 라이프 사이클이란

> 라이프 사이클 : 컨테이너가 **생성되어 삭제될 때까지** 거치는 상태의 흐름

- 컨테이너는 필요할 때 만들고 필요 없으면 버리는 것이 기본 사고방식
- 문제가 생기면 고치지 않고 **삭제 후 이미지에서 다시 생성** (불변 인프라)
- 따라서 남겨야 하는 데이터는 컨테이너 밖(볼륨)에 저장

| 상태 | 의미 |
|---|---|
| 생성 (created) | 컨테이너가 만들어졌지만 아직 프로세스는 시작되지 않음 |
| 실행 (running) | 컨테이너 안의 프로세스가 동작 중 |
| 일시 정지 (paused) | 프로세스가 일시 중단된 상태 — 메모리 내용은 유지 |
| 정지 (exited) | 프로세스가 종료됨 — 컨테이너 레이어의 파일은 남아 있음 |
| 삭제 (removed) | 컨테이너가 제거됨 — 컨테이너 레이어의 변경 내용도 사라짐 |

---

## 컨테이너의 상태 변화

```
                 docker create            docker start
  이미지 ───────────────────▶ 생성 ─────────────────▶ 실행 ◀──────────┐
     │                                                │  ▲           │
     └────────────── docker run ──────────────────────┘  │           │ docker
                    (create + start)        docker pause │ unpause   │ start / restart
                                                      ▼  │           │
                                                    일시 정지         │
                                                                     │
                 docker rm                 docker stop / kill        │
  삭제 ◀───────────────────── 정지 ◀──────────────────── 실행 ───────┘
                               (프로세스가 스스로 끝나도 정지 상태가 됨)
```

| 명령 | 상태 변화 | 내용 |
|---|---|---|
| `docker create` | 이미지 → 생성 | 컨테이너만 만들고 시작하지 않음 |
| `docker start` | 생성·정지 → 실행 | 컨테이너 시작 |
| `docker run` | 이미지 → 실행 | create + start를 한 번에 |
| `docker pause` / `unpause` | 실행 ↔ 일시 정지 | 프로세스 일시 중단 / 재개 |
| `docker stop` | 실행 → 정지 | SIGTERM을 보내 정상 종료, 일정 시간 뒤 SIGKILL |
| `docker kill` | 실행 → 정지 | SIGKILL로 즉시 강제 종료 |
| `docker restart` | 실행 → 정지 → 실행 | 재시작 |
| `docker rm` | 정지 → 삭제 | 컨테이너 삭제 (`-f`를 붙이면 실행 중에도 삭제) |

**정지와 삭제의 차이**

| 구분 | 정지 | 삭제 |
|---|---|---|
| 프로세스 | 종료 | 종료 |
| 컨테이너에서 변경한 파일 | **남아 있음** — 다시 start하면 그대로 | **사라짐** |
| `docker ps` | `-a` 옵션을 붙여야 보임 | 보이지 않음 |
| 디스크 사용 | 계속 차지 | 반환 |

- 컨테이너의 수명 = **메인 프로세스(PID 1)의 수명** — 메인 프로세스가 끝나면 컨테이너도 정지
- `docker run --rm` : 정지와 동시에 자동 삭제
- `--restart` 옵션 : 프로세스가 비정상 종료되거나 호스트가 재부팅되었을 때 자동 재시작 정책 지정

<details><summary>컨테이너를 삭제해도 이미지는 남을까? 데이터는?</summary>

컨테이너를 삭제해도 그 컨테이너를 만든 이미지는 그대로 남아, 같은 이미지로 언제든 새 컨테이너를 만들 수 있다. <br>
사라지는 것은 컨테이너가 실행 중에 기록한 변경 내용(컨테이너 레이어)이다. <br>
데이터베이스 파일이나 업로드 파일처럼 남겨야 하는 데이터는 볼륨에 저장해야 컨테이너를 삭제해도 유지된다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 컨테이너는 생성 → 실행 → (일시 정지) → 정지 → 삭제의 라이프 사이클을 가지며 create/start/run/pause/stop/rm 명령으로 상태가 바뀌고, 정지 상태에서는 변경 내용이 남지만 삭제하면 사라지므로 컨테이너는 언제든 버리고 다시 만드는 일회용으로 다루고 필요한 데이터는 볼륨에 보관한다
