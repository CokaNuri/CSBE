# 도커

> 사실상 컨테이너 기술의 표준 — 컨테이너를 만들고, 배포하고, 실행하는 일련의 과정을 하나의 도구로 제공

## 도커란

> 도커(Docker) : 컨테이너형 가상화 기술을 이용해 애플리케이션을 **빌드·배포·실행**하는 오픈 소스 플랫폼

- 2013년 dotCloud(현 Docker, Inc.)가 공개
- 애플리케이션과 실행에 필요한 라이브러리·설정을 **컨테이너 이미지**로 묶어 어디서나 같은 환경으로 실행
- 컨테이너 기술 자체는 이전부터 있었지만, 도커가 **이미지 형식·배포 방법·간단한 명령어**를 제공하면서 널리 퍼짐

| 용어 | 의미 |
|---|---|
| 컨테이너 이미지 | 컨테이너 실행에 필요한 파일·설정을 담은 템플릿 |
| 컨테이너 | 이미지를 실행한 격리된 프로세스 |
| 도커 파일 | 이미지를 만드는 절차를 적은 텍스트 파일 |
| 레지스트리 | 이미지를 저장·공유하는 저장소 (도커 허브 등) |

---

## 도커의 장점

| 장점 | 내용 |
|---|---|
| 환경 통일 | 개발·테스트·운영 환경을 같은 이미지로 구성 → "내 PC에서는 되는데" 문제 해소 |
| 가볍고 빠름 | 게스트 OS가 없어 초 단위로 기동, 자원 소비가 적음 |
| 이식성 | 도커가 동작하는 곳이면 온프레미스·클라우드 어디서나 실행 |
| 코드로 환경 관리 | 도커 파일로 환경 구축 절차를 기록 → 재현·버전 관리 가능 |
| 이미지 공유 | 도커 허브에 공개된 이미지를 내려받아 바로 사용 |
| 빠른 배포·롤백 | 이미지를 교체하는 것만으로 배포, 이전 이미지로 되돌리기도 쉬움 |

---

## 도커 엔진이란

> 도커 엔진(Docker Engine) : 컨테이너와 이미지를 생성·관리하는 도커의 **핵심 소프트웨어** — 클라이언트-서버 구조

| 구성 요소 | 역할 |
|---|---|
| 도커 데몬 (dockerd) | 호스트에 상주하며 이미지·컨테이너·네트워크·볼륨을 실제로 관리하는 서버 |
| REST API | 데몬에 작업을 요청하는 인터페이스 |
| 도커 클라이언트 (docker CLI) | 사용자가 입력한 명령을 API로 데몬에 전달 |

```
사용자 ─ docker 명령 ─▶ 도커 클라이언트 ─ REST API ─▶ 도커 데몬 ─▶ 컨테이너 / 이미지
```

**도커 엔진과 도커 데스크톱**

| 구분 | 도커 엔진 | 도커 데스크톱 |
|---|---|---|
| 대상 OS | 리눅스 | Windows, macOS, 리눅스 |
| 구성 | 데몬 + CLI | 도커 엔진 + GUI + 리눅스 가상 머신 + 쿠버네티스 등 |
| 용도 | 서버 운영 환경 | 개발자 PC |

<details><summary>도커는 가상 머신을 대체하는 기술일까?</summary>

대체가 아니라 가상화의 단위가 다르다. 가상 머신은 하드웨어를 가상화해 OS 전체를 실행하고, 도커는 호스트 커널을 공유하며 프로세스의 실행 환경만 격리한다. <br>
그래서 도커는 가볍고 빠르지만 호스트와 다른 종류의 커널은 사용할 수 없고 격리 수준도 상대적으로 낮다. <br>
실제로는 클라우드의 가상 서버 위에 도커를 올려 두 기술을 함께 쓰는 구성이 일반적이다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 도커는 애플리케이션과 실행 환경을 컨테이너 이미지로 묶어 어디서나 동일하게 빌드·배포·실행하게 해 주는 컨테이너 기술의 사실상 표준으로, 환경 통일·가벼움·이식성이 장점이며, 그 핵심인 도커 엔진은 도커 데몬·REST API·도커 클라이언트로 구성된다
