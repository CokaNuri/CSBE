# 도커 허브

> 컨테이너 이미지를 공유할 수 있는 서비스 — 도커가 운영하는 세계 최대의 컨테이너 레지스트리

## 도커 허브란

> 도커 허브(Docker Hub) : 도커사가 운영하는 **클라우드형 컨테이너 레지스트리 서비스**

- `docker pull nginx` 처럼 레지스트리를 지정하지 않으면 기본으로 도커 허브에서 내려받음
- 계정을 만들면 자신의 이미지를 올려 공개하거나 비공개로 보관 가능

| 이미지 종류 | 내용 |
|---|---|
| 도커 공식 이미지 (Official Image) | 도커가 검증·관리하는 이미지 — `nginx`, `ubuntu`, `mysql` 처럼 사용자명이 없음 |
| 검증된 게시자 (Verified Publisher) | 소프트웨어 제공 기업이 직접 배포하는 이미지 |
| 일반 사용자 이미지 | 누구나 올린 이미지 — `사용자명/이미지명` 형태, 신뢰성은 직접 확인 필요 |

| 기능 | 내용 |
|---|---|
| 이미지 검색·공유 | 공개된 이미지를 찾아 바로 사용 |
| 공개/비공개 리포지터리 | 공개 범위 설정 (무료 계정은 비공개 수에 제한) |
| 자동 빌드 | GitHub 등의 소스가 바뀌면 이미지 자동 생성 (유료) |
| 취약점 스캔 | 이미지에 포함된 알려진 취약점 검사 |
| 웹훅 | 이미지가 올라오면 다른 서비스에 알림 → 배포 자동화 |

---

## 컨테이너 레지스트리란

> 컨테이너 레지스트리 : 컨테이너 이미지를 **저장하고 배포**하는 서버(서비스)

```
개발자 ── docker push ──▶ 레지스트리 ── docker pull ──▶ 운영 서버 / 다른 개발자 / CI 도구
```

| 구분 | 퍼블릭 레지스트리 | 프라이빗 레지스트리 |
|---|---|---|
| 공개 범위 | 누구나 접근 | 인증된 사용자만 |
| 용도 | 오픈 소스·공식 이미지 배포 | 사내 애플리케이션 이미지 보관 |
| 예 | 도커 허브 | 클라우드의 레지스트리 서비스, 자체 구축 |

- 레지스트리가 없으면 이미지를 파일로 저장(`docker save`)해 직접 옮겨야 함 → 레지스트리가 **배포의 중심**

## 리포지터리와 태그

| 용어 | 의미 |
|---|---|
| 레지스트리 | 리포지터리들을 모아 둔 서버 |
| 리포지터리 | **같은 이름의 이미지**를 버전별로 모아 둔 곳 |
| 태그 | 리포지터리 안에서 이미지를 구분하는 이름 — 주로 버전 |

```
docker.io / library / nginx : 1.27
└레지스트리┘ └네임스페이스┘ └리포지터리┘ └태그┘

docker pull nginx            →  docker.io/library/nginx:latest 와 같음
```

- 태그를 생략하면 `latest` 로 간주 — "가장 최신"이라는 보장이 아니라 **기본 태그 이름**일 뿐
- 같은 태그에 다른 이미지를 덮어쓸 수 있음 → 운영 환경에서는 `latest` 대신 **명확한 버전 태그** 사용
- 내용까지 고정하려면 **다이제스트**(`nginx@sha256:...`)로 지정

```bash
docker tag myapp:1.0 myuser/myapp:1.0    # 리포지터리 이름에 맞춰 태그 부여
docker login                              # 도커 허브 로그인
docker push myuser/myapp:1.0              # 업로드
```

## 도커 허브 이외의 컨테이너 레지스트리 서비스

| 서비스 | 제공 | 특징 |
|---|---|---|
| Amazon ECR | AWS | ECS·EKS와 연동, IAM으로 접근 제어 |
| Artifact Registry (구 Container Registry) | Google Cloud | GKE·Cloud Run과 연동 |
| Azure Container Registry (ACR) | Microsoft Azure | AKS·ACI와 연동 |
| GitHub Container Registry (ghcr.io) | GitHub | 소스 저장소·GitHub Actions와 연동 |
| Quay.io | Red Hat | 취약점 스캔, OpenShift와 연동 |
| Harbor | CNCF (오픈 소스) | 자체 서버에 구축하는 프라이빗 레지스트리 |

- 클라우드에서 컨테이너를 실행할 때는 **같은 클라우드의 레지스트리**를 쓰면 전송이 빠르고 권한 관리가 쉬움

<details><summary>도커 허브의 이미지를 그대로 운영 환경에 써도 될까?</summary>

공식 이미지나 검증된 게시자의 이미지는 비교적 안전하지만, 일반 사용자가 올린 이미지에는 취약한 패키지나 악성 코드가 포함될 수 있다. <br>
출처와 갱신 여부를 확인하고, 태그를 버전이나 다이제스트로 고정하며, 취약점 스캔을 거친 뒤 사용하는 것이 좋다. <br>
또한 도커 허브에는 내려받기 횟수 제한이 있어, 운영 환경에서는 필요한 이미지를 사내 레지스트리에 복제해 두기도 한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 도커 허브는 공식 이미지를 비롯한 수많은 이미지를 공유하는 도커의 기본 컨테이너 레지스트리이며, 레지스트리 안에서 이미지는 리포지터리(이름)와 태그(버전)로 식별되고, ECR·Artifact Registry·ACR·GHCR·Harbor 등 용도에 맞는 다른 레지스트리도 사용할 수 있다
