# 주요 컨테이너 기술

> 컨테이너 = 도커가 아니다 — OCI 표준 덕분에 도커 이외에도 다양한 컨테이너 엔진·런타임이 존재

## 도커 이외의 컨테이너 기술

| 기술 | 개발 | 특징 |
|---|---|---|
| Podman | Red Hat | **데몬 없이** 동작, 일반 사용자 권한(루트리스)으로 실행, 도커와 명령어 호환 |
| LXC / LXD | Canonical 등 | OS 전체를 컨테이너로 실행하는 **시스템 컨테이너** — 가벼운 가상 머신처럼 사용 |
| containerd | CNCF | 도커에서 분리된 컨테이너 런타임 — 쿠버네티스의 표준 런타임 |
| CRI-O | Red Hat 등 | 쿠버네티스 전용 경량 런타임 |
| rkt | CoreOS | 보안을 중시한 런타임 — 현재는 개발 종료 |

**컨테이너 종류**

| 구분 | 애플리케이션 컨테이너 | 시스템 컨테이너 |
|---|---|---|
| 단위 | 컨테이너 하나 = 프로세스(앱) 하나 | 컨테이너 하나 = OS 환경 전체 |
| 사용 방식 | 버리고 새로 만듦 | 가상 머신처럼 접속해 관리 |
| 예 | Docker, Podman | LXC/LXD |

**도커와 Podman**

| 구분 | Docker | Podman |
|---|---|---|
| 구조 | 데몬(dockerd)이 상주하며 컨테이너 관리 | 데몬 없음 — 명령이 직접 컨테이너 실행 |
| 권한 | 데몬이 root로 동작 (루트리스 모드도 지원) | 기본이 루트리스 |
| 단일 장애 지점 | 데몬이 멈추면 영향 | 없음 |
| 파드 | 미지원 | 쿠버네티스처럼 여러 컨테이너를 **파드**로 묶음 |

## 컨테이너디와 크라이오

> 컨테이너 실행은 여러 계층으로 나뉘며, containerd와 CRI-O는 그중 **고수준 런타임**에 해당

| 계층 | 역할 | 예 |
|---|---|---|
| 컨테이너 엔진 | 사용자 명령 처리, 이미지 빌드 | Docker, Podman |
| 고수준 런타임 | 이미지 내려받기·관리, 컨테이너 생명 주기 관리 | **containerd**, **CRI-O** |
| 저수준 런타임 | 네임스페이스·cgroups를 설정해 실제로 컨테이너 프로세스 생성 | runC, crun |

```
docker 명령 → dockerd → containerd → runC → 컨테이너
kubelet ──CRI──▶ containerd 또는 CRI-O → runC → 컨테이너
```

| 구분 | containerd | CRI-O |
|---|---|---|
| 출신 | 도커의 내부 구성 요소를 분리해 CNCF에 기증 | 쿠버네티스용으로 처음부터 개발 |
| 용도 | 도커, 쿠버네티스 등 범용 | 쿠버네티스 전용 |
| 특징 | 널리 쓰이고 기능이 풍부 | 필요한 기능만 담아 가볍고 단순 |
| 채택 | 주요 클라우드의 관리형 쿠버네티스 | Red Hat OpenShift |

**CRI (Container Runtime Interface)**

- 쿠버네티스가 컨테이너 런타임을 호출하는 **표준 인터페이스**
- CRI를 구현한 런타임이면 무엇이든 쿠버네티스에서 사용 가능
- 도커는 CRI를 직접 지원하지 않아 중간 변환 계층(dockershim)이 필요했음 → 쿠버네티스 1.24에서 제거

<details><summary>쿠버네티스가 도커 지원을 중단했는데 도커로 만든 이미지는 계속 쓸 수 있을까?</summary>

쓸 수 있다. 도커로 빌드한 이미지는 OCI 표준 형식이므로 containerd나 CRI-O가 그대로 실행한다. <br>
바뀐 것은 쿠버네티스가 컨테이너를 실행할 때 도커 엔진을 거치지 않게 된 것뿐이다. <br>
개발자는 여전히 도커로 이미지를 만들고, 운영 환경에서는 containerd가 그 이미지를 실행하는 구성이 일반적이다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 컨테이너 기술에는 도커 외에도 데몬 없이 루트리스로 동작하는 Podman, OS 전체를 담는 시스템 컨테이너인 LXC가 있고, 실행 계층은 엔진·고수준 런타임·저수준 런타임(runC)으로 나뉘며, 쿠버네티스는 CRI를 통해 범용 런타임인 containerd나 쿠버네티스 전용 경량 런타임인 CRI-O를 사용한다
