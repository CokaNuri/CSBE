# 컨테이너와 서버리스의 비교

> 서비스 개발의 두 가지 주요 흐름 — 실행 환경을 **직접 묶어 가져가는** 컨테이너와, 실행 환경을 **사업자에게 맡기는** 서버리스

## 서버리스란

> 서버리스 : 개발자가 서버를 **준비·관리하지 않고** 코드만 올리면 실행되는 클라우드 이용 형태

- 서버가 없는 것이 아니라 서버의 구축·확장·패치를 **클라우드 사업자가 전담** → 이용자는 의식할 필요가 없음

| 종류 | 내용 | 예 |
|---|---|---|
| FaaS (Function as a Service) | **함수** 단위의 코드를 이벤트 발생 시 실행 | AWS Lambda, Cloud Functions, Azure Functions |
| BaaS (Backend as a Service) | 인증·DB·스토리지 등 백엔드 기능을 서비스로 제공 | Firebase, Amazon Cognito |

**FaaS의 동작**

```
이벤트 발생 (HTTP 요청, 파일 업로드, 메시지 도착, 정해진 시각)
   → 사업자가 실행 환경을 준비
   → 함수 실행
   → 처리 종료 후 실행 환경 해제
```

- **이벤트 구동** : 요청이 있을 때만 실행, 없으면 실행 환경도 없음
- 과금 : 실행 횟수 × 실행 시간 × 메모리 — 실행되지 않으면 비용 0

## 서버리스의 장단점

| 장점 | 단점 |
|---|---|
| 서버 구축·패치·감시 불필요 → 코드에 집중 | **콜드 스타트** — 한동안 호출이 없다가 실행되면 환경 준비로 지연 |
| 요청량에 따라 **자동 확장** (0까지 축소) | 실행 시간·메모리·패키지 크기 **제한** |
| 쓴 만큼만 과금 — 한가한 시간에 비용 없음 | 상태를 유지할 수 없음 (stateless) → 외부 저장소 필요 |
| 빠른 개발·출시 | 사업자 고유 방식에 묶임 (**벤더 종속**) |
| 고가용성을 사업자가 보장 | 로컬 테스트·디버깅·감시가 어려움 |
| | 항상 높은 부하가 걸리면 오히려 비쌈 |

<details><summary>콜드 스타트는 왜 생기고 어떻게 줄일까?</summary>

서버리스는 요청이 없으면 실행 환경을 해제한다. 그 뒤 요청이 오면 환경을 새로 만들고 코드를 불러와야 해서 첫 응답이 늦어진다. <br>
패키지 크기를 줄이고 기동이 빠른 언어를 쓰거나, 실행 환경을 미리 준비해 두는 설정(프로비저닝)을 사용하면 줄일 수 있다. <br>
다만 미리 준비하면 그만큼 비용이 들어 "쓴 만큼만 과금"의 이점이 줄어든다.
</details>

## 컨테이너와 서버리스의 차이

| 구분 | 컨테이너 | 서버리스 (FaaS) |
|---|---|---|
| 배포 단위 | 이미지 (앱 + 실행 환경) | 함수 (코드) |
| 실행 환경 | 이용자가 직접 정의 — 자유도 높음 | 사업자가 제공 — 지원 언어·버전 제한 |
| 실행 방식 | 상시 기동해 요청 대기 | 이벤트가 있을 때만 기동 |
| 실행 시간 | 제한 없음 | 제한 있음 (수 분~수십 분) |
| 확장 | 설정 필요 (오케스트레이션) | 자동 |
| 운용 부담 | 기반(클러스터·노드) 관리 필요 | 거의 없음 |
| 과금 | 기동 중인 자원에 대해 | 실행한 만큼 |
| 이식성 | 높음 — 어디서나 실행 | 낮음 — 사업자 종속 |
| 상태 | 유지 가능 | 유지 불가 |

**어울리는 용도**

| 컨테이너 | 서버리스 |
|---|---|
| 상시 요청을 받는 웹·API 서비스 | 가끔 발생하는 이벤트 처리 (파일 변환, 알림 발송) |
| 오래 걸리는 처리, 상태가 필요한 처리 | 짧게 끝나는 처리 |
| 특수한 라이브러리·실행 환경이 필요한 경우 | 요청량 변동이 크거나 예측하기 어려운 경우 |
| 기존 애플리케이션 이전, 멀티 클라우드 | 소규모 팀의 빠른 개발, 정기 실행 작업 |

**둘의 접점 — 서버리스 컨테이너**

- 컨테이너 이미지를 올리면 기반 관리 없이 실행·자동 확장해 주는 서비스
- 예 : AWS Fargate, Google Cloud Run, Azure Container Apps
- 컨테이너의 **자유도·이식성** + 서버리스의 **운용 부담 경감**

## 🔑 최종 정리

> 한 줄 요약: 서버리스는 서버 관리를 사업자에게 맡기고 이벤트가 있을 때만 함수를 실행해 쓴 만큼만 과금하는 방식으로 운용 부담이 적고 자동 확장되지만 콜드 스타트·실행 제한·벤더 종속이 있고, 컨테이너는 실행 환경을 직접 정의해 자유도와 이식성이 높은 대신 기반 관리가 필요하며, 둘을 결합한 서버리스 컨테이너도 있다
