# 서비스

> 컨테이너에 접속하는 창구인 엔드포인트를 제공

## 서비스란

> 서비스 : 같은 역할을 하는 파드 집합에 **가상 IP 주소를 부여하는 객체

- 파드는 다시 만들어질 때마다 IP 주소가 바뀌고, 스케일링으로 개수도 변함
- 접속하는 쪽이 파드 IP를 직접 알아야 한다면 매번 설정을 바꿔야 함
- 서비스가 고정 주소로 요청을 받아 뒤의 파드로 전달 → 접속하는 쪽은 서비스만 알면 됨

---

## 서비스의 구조

| 요소 | 내용 |
|---|---|
| 셀렉터 | 요청을 전달할 파드를 **레이블**로 선택 (예: `app=web`) |
| ClusterIP | 서비스에 부여되는 클러스터 내부용 가상 IP |
| 엔드포인트 | 셀렉터에 해당하는 파드들의 실제 IP·포트 목록 — 파드 증감에 따라 자동 갱신 |



---

## 서비스 유형

| 유형 | 접속 가능 범위 | 내용 |
|---|---|---|
| ClusterIP | 클러스터 **내부** | 기본값 — 내부용 가상 IP만 부여 |
| NodePort | 클러스터 외부 | 모든 노드의 **특정 포트**(30000~32767)를 열어 `노드IP:포트`로 접속 |
| LoadBalancer | 클러스터 외부 | 클라우드의 **로드 밸런서**를 자동 생성해 외부 IP 부여 |
| ExternalName | (외부로 나가는 방향) | 서비스 이름을 **외부 도메인 이름**으로 연결 (DNS CNAME) |

- 포함 관계 : LoadBalancer ⊃ NodePort ⊃ ClusterIP — 상위 유형은 하위 유형의 기능을 포함

---

## 서비스에 의한 로드 밸런싱

- 서비스는 받은 요청을 엔드포인트의 파드들에 **분산** 전달
- 파드가 늘거나 줄면 엔드포인트가 자동 갱신 → 설정 변경 없이 분산 대상이 바뀜
- 준비되지 않은(헬스 체크 실패) 파드는 엔드포인트에서 제외
- L4(IP·포트) 수준의 분산 — URL 경로·호스트명 기준의 L7 분산은 **인그레스**(Ingress)가 담당

---

## 각 서비스의 구분

| 상황 | 적합한 유형 |
|---|---|
| 웹 서버 → DB처럼 클러스터 내부끼리 통신 | ClusterIP |
| 개발·테스트 중 간단히 외부에서 접속 | NodePort |
| 클라우드에서 운영 서비스를 외부에 공개 | LoadBalancer |
| 클러스터 안에서 외부 DB·API를 서비스 이름으로 참조 | ExternalName |

- LoadBalancer는 서비스마다 로드 밸런서가 생겨 비용 발생 → 서비스가 많으면 인그레스 하나로 묶어 공개



---

## 🔑 최종 정리

> 한 줄 요약: 서비스는 레이블 셀렉터로 고른 파드 집합에 고정 IP와 DNS 이름을 부여하고 요청을 분산하는 접속 창구로, 내부 통신용 ClusterIP, 노드 포트를 여는 NodePort, 클라우드 로드 밸런서를 쓰는 LoadBalancer, 외부 도메인을 가리키는 ExternalName 유형을 용도에 따라 구분해 사용한다
