# 서비스

> 컨테이너에 접속하는 창구인 엔드포인트를 제공

## 서비스란

> 서비스 : 컨테이너에 접속하기 위한 창구인 **엔드포인트**를 제공하는 방식

- 외부에서 컨테이너에 접속할 때 컨테이너에 직접 접속하는 것이 아니라 엔드포인트를 통해 **간접적으로** 접속

| 구분 | 컨테이너에 접속하는 방법 |
|---|---|
| 도커 | 컨테이너를 실행할 때 컴퓨터 포트와 컨테이너 포트를 **바인딩**  |
| 쿠버네티스 | 서비스에 접속 → 대상 컨테이너로 전환 |

- 쿠버네티스에서는 레플리카셋과 디플로이먼트의 구조에 따라 파드가 **실행과 정지를 반복**
- 이러한 상황에서도 대상 컨테이너에 정확하게 접속할 수 있게 하는 방법이 서비스

---

## 서비스의 구조

> **가상 IP 주소**와 **네트워크 주소 변환**을 조합해 서비스 작동 방식을 구현

| 용어 | 내용 |
|---|---|
| 가상 IP 주소 | 물리적 또는 가상 컴퓨터에 할당할 수 없는 IP 주소이자 **엔드포인트** |
| 네트워크 주소 변환 | IP 주소를 다른 IP 주소로 변환하는 기술 |

- 가상 IP 주소에 접속하면 네트워크 주소 변환에 따라 대상 컨테이너로 전달

---

## 서비스 유형


| 서비스 유형 | 특징 |
|---|---|
| ClusterIP | 클러스터 **내부**에만 접속할 수 있는 가상 IP 주소가 생성됨 |
| NodePort | 클러스터의 모든 노드의 **지정된 포트**에 대한 접속이 컨테이너로 전달되며 클러스터 외부에서도 접속 가능 |
| LoadBalancer | 클라우드 서비스의 **로드 밸런서**에 대한 접속이 컨테이너로 전송되며 클러스터 외부에서도 접속 가능 |
| ExternalName | 서비스에 대한 접속이 **지정된 호스트**로 전달됨 |

---

## 서비스에 의한 로드 밸런싱

| 서비스의 역할 | 내용 |
|---|---|
| 엔드포인트 제공 | 컨테이너에 접속하기 위한 창구 |
| 로드 밸런싱 | 엔드포인트에 대한 접속을 여러 컴퓨터에서 실행되는 **같은 유형의 컨테이너로 분배**  |

- ExternalName 이외의 서비스 : 쿠버네티스가 **자동으로** 로드 밸런싱을 수행
- ExternalName : 대상 호스트가 로드 밸런싱을 수행하도록 사용자가 **직접 구성**해야 함

---

## 각 서비스의 구분

| 상황 | 적합한 유형 |
|---|---|
| 웹 서버 → DB처럼 클러스터 내부끼리 통신 | ClusterIP |
| 개발·테스트 중 간단히 외부에서 접속 | NodePort |
| 클라우드에서 운영 서비스를 외부에 공개 | LoadBalancer |
| 클러스터 안에서 외부 DB·API를 서비스 이름으로 참조 | ExternalName |



---

## 🔑 최종 정리

> 한 줄 요약: 서비스는 컨테이너에 접속하는 창구인 엔드포인트를 제공하는 방식으로, 가상 IP 주소와 네트워크 주소 변환을 조합해 접속을 대상 파드로 전환하고 같은 유형의 컨테이너로 분배한다
