# 쿠버네티스의 주요 명령어

> 매니페스트에 원하는 상태를 적고 `kubectl`로 클러스터에 전달 — 필수 명령어 소개

## 선언형 기술로 클러스터 조작

| 구분 | 명령형 | 선언형 |
|---|---|---|
| 방식 | "무엇을 **하라**"를 순서대로 지시 | "이런 **상태**여야 한다"를 기술 |
| 예 | `kubectl create`, `kubectl scale` | `kubectl apply -f 파일` |
| 특징 | 간단한 작업에 편리 | 파일로 남아 이력 관리·재현 가능 |

> 매니페스트 : 객체의 원하는 상태를 적은 **YAML 파일**

| 필드 | 내용 |
|---|---|
| apiVersion | 사용할 API 버전 (`v1`, `apps/v1` 등) |
| kind | 객체 종류 (Pod, ReplicaSet, Deployment, Service) |
| metadata | 이름, 레이블 등 식별 정보 |
| spec | 원하는 상태의 구체적 내용 |

---

## 매니페스트에서 객체를 선택하는 방법

- **레이블** : 객체에 붙이는 키-값 쌍 (`app: web`)
- **셀렉터** : 레이블 조건으로 대상 객체를 고름 → 레플리카셋·디플로이먼트·서비스가 자기 파드를 찾는 방법

```yaml
spec:
  selector:
    matchLabels:
      app: web        # 이 레이블을 가진 파드가 대상
  template:
    metadata:
      labels:
        app: web      # 만들어지는 파드에 붙는 레이블 (셀렉터와 일치해야 함)
```

---

## 쿠버네티스 명령어를 사용할 수 있는 환경

- `kubectl` : 마스터의 API 서버에 요청을 보내는 명령줄 도구 — 접속 정보는 kubeconfig(`~/.kube/config`)에 저장

| 환경 | 내용 |
|---|---|
| 로컬 학습용 | Minikube, kind, Docker Desktop의 쿠버네티스 |
| 직접 구축 | kubeadm 등으로 서버에 설치 |
| 클라우드 관리형 | EKS, GKE, AKS |

- 기본 형식 : `kubectl [동작] [객체 종류] [이름] [옵션]`

## 파드의 생성/확인/명령어 실행/변경/삭제

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: web
  labels:
    app: web
spec:
  containers:
    - name: nginx
      image: nginx:1.25
      ports:
        - containerPort: 80
```

```bash
kubectl apply -f pod.yaml          # 생성 (변경 시에도 동일)
kubectl get pods -o wide           # 목록 확인 (IP·노드 포함)
kubectl describe pod web           # 상세 정보·이벤트
kubectl logs web                   # 로그
kubectl exec -it web -- /bin/bash  # 컨테이너 안에서 명령어 실행
kubectl delete pod web             # 삭제
```

## 레플리카셋의 생성/확인/변경/삭제

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: web-rs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: nginx
          image: nginx:1.25
```

```bash
kubectl apply -f rs.yaml
kubectl get rs
kubectl scale rs web-rs --replicas=5   # 개수 변경 (또는 파일 수정 후 apply)
kubectl delete rs web-rs               # 관리하던 파드도 함께 삭제
```

---

## 디플로이먼트의 생성/확인/변경/삭제

- 매니페스트는 레플리카셋과 거의 같고 `kind: Deployment`만 다름

```bash
kubectl apply -f deploy.yaml
kubectl get deployments
kubectl set image deployment/web nginx=nginx:1.26   # 이미지 변경 → 롤링 업데이트
kubectl rollout status deployment/web               # 진행 상황
kubectl rollout history deployment/web              # 변경 이력
kubectl rollout undo deployment/web                 # 롤백
kubectl delete deployment web
```

## 서비스의 생성/확인/변경/삭제

```yaml
apiVersion: v1
kind: Service
metadata:
  name: web-svc
spec:
  type: NodePort
  selector:
    app: web
  ports:
    - port: 80          # 서비스가 받는 포트
      targetPort: 80    # 파드의 포트
      nodePort: 30080   # 노드에 여는 포트
```

```bash
kubectl apply -f svc.yaml
kubectl get svc
kubectl describe svc web-svc   # 엔드포인트(연결된 파드) 확인
kubectl delete svc web-svc
```

<details><summary>kubectl create와 kubectl apply는 무엇이 다를까?</summary>

`create`는 객체를 새로 만드는 명령형 명령이라 같은 이름의 객체가 이미 있으면 오류가 난다. <br>
`apply`는 파일의 내용을 원하는 상태로 보고, 없으면 만들고 있으면 달라진 부분만 반영한다. <br>
같은 파일을 몇 번 적용해도 결과가 같아 파일을 Git으로 관리하는 선언형 운영에 적합하다.
</details>

> 한 줄 요약: 쿠버네티스는 apiVersion·kind·metadata·spec으로 원하는 상태를 적은 매니페스트를 kubectl apply로 적용하는 선언형 조작이 기본이고, 레이블과 셀렉터로 대상 객체를 연결하며, get·describe·logs·exec·scale·rollout·delete 등의 명령으로 파드·레플리카셋·디플로이먼트·서비스를 확인하고 변경한다
