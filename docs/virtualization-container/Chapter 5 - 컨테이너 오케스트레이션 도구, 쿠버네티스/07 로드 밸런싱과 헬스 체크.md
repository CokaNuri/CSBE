# 로드 밸런싱과 헬스 체크

> 정상적으로 실행되지 않는 컨테이너에 요청을 분배하지 않도록 해 **시스템의 가용성을 향상**

---

## 가용성이란

> 가용성 : 시스템이 멈추지 않고 계속 서비스를 제공할 수 있는 정도

- 가동률 = 시스템 정상 가동 시간 ÷ 전체 시스템 가동 시간
- **단일 장애 지점**(SPOF) — 여기가 멈추면 시스템 전체가 멈춤
- 가용성을 높이는 기본 : **이중화** + **장애 감지 후 자동 전환**

---

## 쿠버네티스의 로드 밸런싱

> 쿠버네티스는 **서비스**라는 방식으로 로드 밸런싱을 실시

- 클러스터 내에 서비스를 생성하면 엔드포인트가 되는 IP 주소가 생성됨
- 이 IP 주소를 대상으로 하는 패킷은 서비스 뒤에 있는 파드로 전달
- 서비스 뒤에 여러 파드가 있는 경우 **순서대로** 각 파드에 패킷을 전달 → **라운드 로빈**(RR, Round Robin)

| 구성 요소 | 역할 |
|---|---|
| iptables | **네트워크 주소 변환** 기능으로 패킷을 파드로 전달 |
| kube-proxy | 에이전트 프로그램 — 패킷을 전송하는 방법을 결정하는 **규칙을 필요에 따라 변경** |

```
마스터   [ kube-api-server ]
              ▲   │ 패킷 전송 규칙을 취득
              │   ▼
워커     [ kube-proxy ] ──취득한 정보로 변경──▶ [ iptables (주소 변경) ] ◀──패킷── 파드
                                                      │
                                                      │ 주소 변경에 의해 패킷을 해당 파드로 보냄
                                                      ▼
                                              파드     파드     파드
```

**iptables와 IPVS**

- iptables 대신 **IPVS**를 사용할 수 있음 — 서비스 수가 10,000개를 초과하는 대규모 클러스터에서는 IPVS가 좋음

| 구분 | iptables | IPVS |
|---|---|---|
| 정체 | 리눅스의 네트워크 관리 도구 — netfilter 설정을 변경 | 리눅스 커널에 내장된 로드 밸런싱 기능 |
| 기반 | netfilter | netfilter |
| 속도 | 상대적으로 느림 | 설정 내용을 해시 테이블에 보존, 커널 모드에서 동작 → **더 빠름** |

- netfilter : 패킷 필터링 및 네트워크 주소 변환을 수행하는 리눅스의 기능

## 쿠버네티스의 헬스 체크

> 클러스터를 구성하는 시스템의 에이전트 프로그램 **kubelet**이 같은 시스템에서 실행 중인 파드의 상태를 **정기적으로 확인**

| 확인 방법 | 정상으로 판단하는 기준 |
|---|---|
| 명령어 실행 | 파드에 포함된 컨테이너에서 지정된 명령어를 실행 → 명령어 성공(종료 코드가 0) |
| TCP 통신 | 연결 가능 |
| HTTP 통신 | 상태 코드가 200대 또는 300대 |

```
워커
  [ kubelet ]
     │  ▲
     │  │ 명령어의 실행 결과나 상태 코드로 판단
     ▼  │
  명령어 실행 또는 TCP/HTTP 통신
  파드 (컨테이너)
```

- 정상 및 비정상의 판단 결과를 기반으로 **파드를 다시 시작**하거나 **서비스에서 요청 전송을 중지** → 클러스터를 정상 상태로 유지

## 🔑 최종 정리

> 한 줄 요약: 로드 밸런싱과 헬스 체크를 조합하면 시스템 가용성을 높일 수 있으며, 쿠버네티스에서는 kube-proxy가 iptables(또는 IPVS) 규칙을 변경해 서비스로 온 패킷을 라운드 로빈으로 파드에 전달하는 로드 밸런싱을 실현하고, kubelet이 명령어 실행이나 TCP/HTTP 통신으로 파드의 상태를 정기적으로 확인해 헬스 체크를 구현한다
