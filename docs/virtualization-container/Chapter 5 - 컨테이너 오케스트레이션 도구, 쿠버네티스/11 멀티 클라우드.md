# 멀티 클라우드

> 한 사업자에 묶이지 않고 **여러 클라우드에서 쿠버네티스를 사용**하는 구성

## 멀티 클라우드란

> 멀티 클라우드 : **둘 이상의 클라우드 사업자**의 서비스를 조합해 사용하는 형태

| 용어 | 내용 |
|---|---|
| 멀티 클라우드 | 여러 퍼블릭 클라우드를 함께 사용 (예: AWS + GCP) |
| 하이브리드 클라우드 | 퍼블릭 클라우드 + 온프레미스(또는 프라이빗 클라우드)를 연결해 사용 |

- 두 용어는 겹쳐 쓰이기도 함 — 핵심은 **환경이 하나가 아니라는 것**

---

## 멀티 클라우드의 필요성

| 이유 | 내용 |
|---|---|
| 벤더 종속 회피 | 한 사업자의 가격 인상·정책 변경·서비스 종료에 휘둘리지 않음 |
| 가용성 향상 | 한 클라우드에 대규모 장애가 나도 다른 클라우드에서 서비스 지속 |
| 장점의 조합 | 사업자마다 강한 분야(데이터 분석, AI, 기업용 서비스 등)를 골라 사용 |
| 비용 최적화 | 용도별로 더 저렴한 쪽 선택, 가격 협상력 확보 |
| 규제·지역 대응 | 데이터 보관 위치 규정, 특정 지역의 리전 유무에 맞춰 선택 |

| 단점 | 내용 |
|---|---|
| 운영 복잡 | 사업자마다 콘솔·API·용어·권한 체계가 다름 |
| 인력 부담 | 여러 클라우드의 지식이 필요 |
| 통신 비용·지연 | 클라우드 간 데이터 전송에 요금과 지연 발생 |
| 보안 관리 | 정책과 감시를 환경마다 맞춰야 함 |

## 쿠버네티스를 사용한 멀티 클라우드

- 쿠버네티스는 어느 클라우드에서나 **같은 API·매니페스트·kubectl**로 동작
- 클라우드마다 다른 인프라(가상 서버, 로드 밸런서, 스토리지)를 쿠버네티스가 **추상화**
- 컨테이너 이미지 + 매니페스트만 있으면 다른 클라우드의 클러스터에도 그대로 배포 → **이식성**

```
        같은 매니페스트 / 같은 컨테이너 이미지
     ┌──────────┬──────────┬──────────┐
     ▼          ▼          ▼          ▼
 EKS (AWS)  GKE (GCP)  AKS (애저)  온프레미스 클러스터
```

- 주의 : 클러스터는 클라우드마다 **따로** 존재 → 여러 클러스터를 한꺼번에 관리할 수단이 필요
- 로드 밸런서·스토리지 설정, 관리형 DB 같은 클라우드 고유 서비스 부분은 여전히 차이가 남음

## 멀티 클라우드 구축을 지원하는 도구

| 도구 | 제공 | 특징 |
|---|---|---|
| Anthos (현 GKE Enterprise) | 구글 | GKE를 기반으로 온프레미스·타 클라우드의 클러스터까지 **일관되게 관리** |
| Azure Arc | 마이크로소프트 | 애저 밖의 서버·쿠버네티스 클러스터를 애저 포털에서 관리 |
| Amazon EKS Anywhere | AWS | 온프레미스에서 EKS와 같은 방식의 클러스터 운영 |
| Rancher | SUSE | 오픈 소스 — 여러 클라우드·온프레미스의 클러스터를 하나의 화면에서 관리 |
| Red Hat OpenShift | Red Hat | 기업용 쿠버네티스 플랫폼 — 어느 환경에서나 같은 플랫폼 제공 |
| Terraform | HashiCorp | 여러 클라우드의 인프라를 **코드**로 정의·구축 (IaC) |

**이 도구들이 공통으로 제공하는 것**

- 여러 클러스터의 통합 조회·감시
- 정책·설정의 일괄 적용
- 인증·권한의 통합 관리

<details><summary>쿠버네티스를 쓰면 클라우드를 완전히 자유롭게 옮길 수 있을까?</summary>

애플리케이션(컨테이너와 매니페스트)은 거의 그대로 옮길 수 있다. <br>
그러나 관리형 DB, 메시지 큐, 인증 서비스처럼 클라우드 고유 서비스에 의존하는 부분과 저장된 데이터는 쉽게 옮겨지지 않는다. <br>
이식성을 높이려면 고유 서비스 의존을 줄이거나, 의존 부분을 분리해 교체할 수 있게 설계해야 한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 멀티 클라우드는 벤더 종속 회피·가용성 향상·장점 조합을 위해 여러 클라우드를 함께 쓰는 형태로 운영이 복잡해지는 단점이 있으며, 어디서나 같은 방식으로 동작하는 쿠버네티스가 이식성의 토대가 되고 Anthos·Azure Arc·Rancher 등이 여러 클러스터의 통합 관리를 지원한다
