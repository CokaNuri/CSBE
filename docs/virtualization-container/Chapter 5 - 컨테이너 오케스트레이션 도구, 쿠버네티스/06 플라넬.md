# 플라넬

> 서로 다른 노드에 있는 파드끼리 통신할 수 있게 해 주는 **오버레이 네트워크** — 컨테이너 간 상호 접속을 지원하는 기술

## 파드 내 통신

- 같은 파드의 컨테이너들은 **네트워크 네임스페이스를 공유** → IP 주소가 하나
- 서로 `localhost:포트번호`로 통신
- 같은 파드 안에서는 포트 번호가 겹치면 안 됨

```
┌──────────── 파드 (10.244.1.5) ────────────┐
│  [웹 컨테이너 :80] ◀─localhost─▶ [앱 컨테이너 :8080] │
└────────────────────────────────────────────┘
```

---

## 파드 간 통신

> 쿠버네티스의 네트워크 원칙 : 모든 파드는 **NAT 없이** 서로의 IP 주소로 직접 통신할 수 있어야 함

| 경우 | 통신 방법 |
|---|---|
| 같은 노드의 파드끼리 | 노드 내부의 가상 브리지를 통해 통신 |
| 다른 노드의 파드끼리 | 노드를 넘어가는 네트워크가 필요 — 쿠버네티스 자체에는 구현이 없음 |

- 쿠버네티스는 규칙만 정하고 구현은 **CNI**(Container Network Interface) 플러그인에 맡김
- 대표 CNI 플러그인 : 플라넬, 칼리코(Calico), 실리움(Cilium), 위브넷(Weave Net)

---

## 플라넬이란

> 플라넬(flannel) : 노드들에 걸친 **가상 네트워크(오버레이 네트워크)**를 만들어 파드 간 통신을 구현하는 CNI 플러그인

- 구조가 단순하고 설정이 쉬워 널리 쓰임
- 클러스터 전체용 주소 범위(예: `10.244.0.0/16`)를 정하고, 노드마다 **서브넷**(예: `10.244.1.0/24`)을 나누어 할당
- 파드는 자기 노드의 서브넷에서 IP를 받음 → 클러스터 전체에서 IP가 겹치지 않음
- 노드를 넘는 패킷은 **VXLAN** 등으로 캡슐화해 상대 노드로 전달

```
노드 A (192.168.0.10)                    노드 B (192.168.0.11)
 파드 10.244.1.5                           파드 10.244.2.7
      │                                        ▲
   flannel ── 캡슐화 [노드A→노드B | 파드→파드] ── flannel (캡슐 해제)
```

---

## flanneld란

> flanneld : 각 노드에서 동작하는 플라넬의 **에이전트(데몬)**

| 하는 일 | 내용 |
|---|---|
| 서브넷 할당 | 자기 노드가 쓸 파드용 서브넷을 받아 설정 |
| 정보 공유 | 어느 서브넷이 어느 노드에 있는지를 쿠버네티스 API(etcd)에 기록·조회 |
| 경로 설정 | 다른 노드의 서브넷으로 가는 경로와 캡슐화 규칙을 노드에 설정 |

- 보통 **데몬셋**으로 배포 → 모든 노드에 하나씩 자동 실행

| 백엔드(전달 방식) | 내용 |
|---|---|
| VXLAN | 기본값 — 패킷을 캡슐화해 전달, 대부분의 환경에서 동작 |
| host-gw | 캡슐화 없이 노드를 게이트웨이로 삼아 라우팅 — 빠르지만 노드가 같은 L2 네트워크에 있어야 함 |

## 플라넬과 서비스의 차이

| 구분 | 플라넬 | 서비스 |
|---|---|---|
| 목적 | 파드끼리 IP로 **도달할 수 있게** 함 (연결성) | 파드 집합에 **고정 창구**를 제공 |
| 대상 | 개별 파드의 IP | 파드 그룹 (레이블로 선택) |
| 제공 기능 | 노드 간 가상 네트워크 | 고정 IP·DNS 이름, 로드 밸런싱 |
| 구현 주체 | CNI 플러그인 (flanneld) | 쿠버네티스 객체 + kube-proxy |
| 계층 | 아래 — 통신의 토대 | 위 — 토대 위에서 동작 |

- 서비스가 요청을 다른 노드의 파드로 전달할 때 그 길이 되는 것이 플라넬의 네트워크 → **둘은 대체 관계가 아니라 함께 사용**

<details><summary>플라넬이 있어 파드 IP로 직접 통신할 수 있는데도 서비스가 필요한 이유는?</summary>

파드는 다시 만들어질 때마다 IP가 바뀌고, 같은 역할의 파드가 여러 개 있을 수 있다. <br>
플라넬은 IP를 알면 도달하게 해 줄 뿐, 어떤 IP로 가야 하는지와 여러 파드에 나누어 보내는 일은 해 주지 않는다. <br>
그래서 고정된 이름과 로드 밸런싱을 제공하는 서비스를 그 위에 둔다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 같은 파드의 컨테이너는 localhost로, 다른 파드와는 파드 IP로 통신하며, 플라넬은 노드마다 서브넷을 할당하고 각 노드의 flanneld가 VXLAN 캡슐화 경로를 설정해 노드를 넘는 파드 간 통신을 가능하게 하는 오버레이 네트워크이고, 서비스는 그 위에서 고정 창구와 로드 밸런싱을 제공한다
