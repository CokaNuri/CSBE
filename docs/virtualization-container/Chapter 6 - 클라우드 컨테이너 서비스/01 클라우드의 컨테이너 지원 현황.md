# 클라우드의 컨테이너 지원 현황

> 주요 클라우드(AWS·GCP·애저)는 모두 **오케스트레이션 서비스**, **쿠버네티스 서비스**, **서버리스 컨테이너 실행 환경**, **레지스트리**를 제공

## AWS의 컨테이너 서비스

| 서비스 | 분류 | 내용 |
|---|---|---|
| Amazon ECS | 오케스트레이션 | AWS **독자** 컨테이너 오케스트레이션 서비스 |
| Amazon EKS | 쿠버네티스 | 관리형 쿠버네티스 서비스 |
| AWS Fargate | 서버리스 실행 환경 | 서버 관리 없이 컨테이너 실행 — ECS·EKS의 실행 기반으로 사용 |
| Amazon ECR | 레지스트리 | 컨테이너 이미지 저장소 |

- 독자 방식(ECS)과 표준 방식(EKS)을 **둘 다** 제공하는 것이 특징

---

## GCP의 컨테이너 서비스

| 서비스 | 분류 | 내용 |
|---|---|---|
| GKE (Google Kubernetes Engine) | 쿠버네티스 | 관리형 쿠버네티스 서비스 — 쿠버네티스를 만든 구글이 제공 |
| Cloud Run | 서버리스 실행 환경 | 컨테이너 이미지를 올리면 바로 실행, 요청이 없으면 0까지 축소 |
| Artifact Registry | 레지스트리 | 컨테이너 이미지·패키지 저장소 (이전의 Container Registry 후속) |
| Anthos | 멀티·하이브리드 클라우드 | 온프레미스·타 클라우드의 클러스터까지 통합 관리 |

- 독자 오케스트레이션 서비스 없이 **쿠버네티스 중심**으로 구성

---

## 애저의 컨테이너 서비스

| 서비스 | 분류 | 내용 |
|---|---|---|
| AKS (Azure Kubernetes Service) | 쿠버네티스 | 관리형 쿠버네티스 서비스 |
| ACI (Azure Container Instances) | 서버리스 실행 환경 | 서버 없이 컨테이너(그룹)를 바로 실행 |
| ACR (Azure Container Registry) | 레지스트리 | 컨테이너 이미지 저장소 |

- AKS와 ACI를 **가상 쿠블릿**으로 연결해 함께 쓸 수 있음

---

## 각 클라우드에서 제공하는 컨테이너 서비스

| 분류 | AWS | GCP | 애저 |
|---|---|---|---|
| 독자 오케스트레이션 | ECS | - | - |
| 관리형 쿠버네티스 | EKS | GKE | AKS |
| 서버리스 컨테이너 | Fargate | Cloud Run | ACI |
| 레지스트리 | ECR | Artifact Registry | ACR |

**관리형 서비스에서 사업자가 맡는 범위**

```
            직접 구축        관리형 쿠버네티스      서버리스 컨테이너
컨테이너      이용자            이용자               이용자
워커 노드     이용자            이용자(일부 자동화)    사업자
컨트롤 플레인  이용자            사업자               사업자
물리 인프라   이용자            사업자               사업자
```

## 어떤 클라우드 서비스를 사용해야 할까?

| 상황 | 어울리는 선택 |
|---|---|
| 이미 쓰고 있는 클라우드가 있음 | 그 클라우드의 서비스 — 기존 네트워크·권한·감시 체계와 연계 |
| 쿠버네티스 지식·자산을 활용, 멀티 클라우드 고려 | 관리형 쿠버네티스 (EKS / GKE / AKS) |
| AWS만 쓰고 단순하게 운영 | ECS |
| 노드 관리 없이 컨테이너만 실행 | 서버리스 컨테이너 (Fargate / Cloud Run / ACI) |
| 요청량 변동이 크고 한가한 시간이 김 | 0까지 축소되는 Cloud Run 등 |

- 기능 차이보다 **기존 환경, 팀의 기술, 운용 부담, 비용**이 판단 기준

<details><summary>쿠버네티스를 직접 설치하지 않고 관리형 서비스를 쓰는 이유는?</summary>

쿠버네티스의 컨트롤 플레인(API 서버, etcd 등)은 구축·이중화·버전 업그레이드·백업이 까다롭다. <br>
관리형 서비스는 이 부분을 사업자가 운영하고 가용성까지 보장하므로, 이용자는 워커 노드와 애플리케이션에 집중할 수 있다. <br>
쿠버네티스 API는 그대로라서 매니페스트와 kubectl 사용법은 직접 구축한 경우와 같다.
</details>

## 🔑 최종 정리

> 한 줄 요약: AWS는 독자 오케스트레이션인 ECS와 쿠버네티스 서비스 EKS, 서버리스 실행 환경 Fargate를, GCP는 GKE와 Cloud Run을, 애저는 AKS와 ACI를 제공하며, 어느 것을 쓸지는 기존 클라우드 환경·팀의 기술·운용 부담·비용을 기준으로 정한다
