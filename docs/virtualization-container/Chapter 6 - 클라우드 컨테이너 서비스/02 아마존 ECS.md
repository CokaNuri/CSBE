# 아마존 ECS

> AWS가 독자적으로 만든 **컨테이너 오케스트레이션 서비스** — 쿠버네티스 없이 AWS 안에서 컨테이너를 배치·관리

## 아마존 ECS란

> Amazon ECS (Elastic Container Service) : 컨테이너의 배치·실행·확장·복구를 자동화하는 AWS의 관리형 서비스

- 컨트롤 플레인은 AWS가 운영 → 이용자는 설치·관리할 필요 없음 (컨트롤 플레인 자체는 무료)
- 로드 밸런서(ELB), 권한(IAM), 네트워크(VPC), 감시(CloudWatch) 등 **AWS 서비스와 긴밀히 연계**
- 이미지는 ECR이나 도커 허브 등에서 가져옴

---

## 아마존 ECS의 작동 방식

| 구성 요소 | 내용 | 쿠버네티스 대응 |
|---|---|---|
| 클러스터 | 태스크·서비스가 실행되는 논리적 그룹 | 클러스터 |
| 태스크 정의 | 사용할 이미지, CPU·메모리, 포트, 환경 변수 등을 적은 **설계도** (JSON) | 매니페스트 (파드 템플릿) |
| 태스크 | 태스크 정의로 실행된 **컨테이너 묶음** (1개 이상) | 파드 |
| 서비스 | 태스크를 지정한 개수만큼 **유지**하고 로드 밸런서와 연결 | 디플로이먼트 + 서비스 |

```
태스크 정의 ──▶ 서비스 (원하는 태스크 수 = 3)
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      태스크     태스크     태스크      ← 하나가 멈추면 서비스가 새로 실행
     (컨테이너) (컨테이너) (컨테이너)
        └────── 클러스터 ──────┘
```

**시작 유형 — 태스크를 어디에서 실행할 것인가**

| 구분 | EC2 시작 유형 | Fargate 시작 유형 |
|---|---|---|
| 실행 기반 | 이용자가 준비한 EC2 인스턴스 | AWS가 관리하는 서버리스 기반 |
| 서버 관리 | OS 패치·확장 등 이용자 담당 | 불필요 |
| 과금 | EC2 인스턴스 기동 시간 | 태스크가 쓴 vCPU·메모리 × 시간 |
| 자유도 | 높음 (인스턴스 종류, GPU, 호스트 접근) | 제한적 |

## 아마존 ECS의 장단점

| 장점 | 단점 |
|---|---|
| 개념이 단순해 배우기 쉬움 | AWS 전용 → **벤더 종속**, 다른 클라우드로 이전 어려움 |
| AWS 서비스와 연계가 쉬움 | 쿠버네티스 생태계(헬름, 오퍼레이터 등)의 도구를 쓸 수 없음 |
| 컨트롤 플레인 무료, 운영 불필요 | 쿠버네티스보다 세밀한 제어·확장 기능이 적음 |
| Fargate와 결합하면 서버 관리도 불필요 | 쿠버네티스에 비해 자료·사용자가 적음 |

## 쿠버네티스가 있다면 아마존 ECS는 불필요할까?

- 불필요하지 않음 — **목적이 다름**

| 구분 | ECS | EKS (쿠버네티스) |
|---|---|---|
| 방식 | AWS 독자 | 오픈 소스 표준 |
| 학습 부담 | 낮음 | 높음 |
| 이식성 | AWS 전용 | 멀티 클라우드·온프레미스 가능 |
| 컨트롤 플레인 비용 | 없음 | 클러스터당 과금 |
| 어울리는 경우 | AWS만 사용, 소규모 팀, 단순한 구성 | 쿠버네티스 자산 보유, 멀티 클라우드, 복잡한 요구 |

<details><summary>태스크와 서비스는 어떻게 구분해서 쓸까?</summary>

태스크만 단독으로 실행하면 처리가 끝나거나 멈췄을 때 그대로 종료된다. 일괄 처리(배치)처럼 한 번 실행하고 끝나는 작업에 쓴다. <br>
서비스는 지정한 수의 태스크가 항상 실행되도록 감시하다가 태스크가 멈추면 새로 실행하고, 로드 밸런서에 등록까지 해 준다. <br>
웹 서버나 API처럼 계속 떠 있어야 하는 애플리케이션은 서비스로 실행한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 아마존 ECS는 AWS 독자의 컨테이너 오케스트레이션 서비스로, 태스크 정의(설계도)로 태스크(컨테이너 묶음)를 실행하고 서비스가 그 개수를 유지하며, EC2 또는 Fargate 시작 유형으로 실행하고, AWS 연계가 쉽고 단순하지만 AWS에 종속되므로 쿠버네티스(EKS)와는 요구에 따라 구분해 쓴다
