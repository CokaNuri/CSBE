# ACI

> 애저의 **서버리스 컨테이너 실행 환경** — 가상 머신도 클러스터도 없이 컨테이너를 몇 초 만에 실행

## ACI란

> ACI (Azure Container Instances) : 서버를 준비하지 않고 컨테이너를 바로 실행할 수 있는 애저 서비스

- 가상 머신 구축, 오케스트레이션 도구 도입 없이 **명령 한 번**으로 컨테이너 실행
- 컨테이너에 할당할 CPU·메모리를 지정하고 **초 단위**로 과금
- 리눅스·윈도우 컨테이너 모두 지원
- 공인 IP 주소와 DNS 이름을 부여해 인터넷에 바로 공개 가능

---

## ACI의 작동 방식

> ACI의 기본 단위는 **컨테이너 그룹** — 같은 호스트에서 함께 실행되는 컨테이너의 모음

```
┌──────────── 컨테이너 그룹 ────────────┐
│  IP 주소 · DNS 이름 (그룹에 하나)       │
│                                      │
│  [앱 컨테이너 :80]  [사이드카 컨테이너]  │ ← localhost로 서로 통신
│          └────── 볼륨 공유 ──────┘     │
└──────────────────────────────────────┘
```

| 컨테이너 그룹의 특징 | 내용 |
|---|---|
| 공유 자원 | 생명 주기, 네트워크(IP·포트), 스토리지 볼륨 |
| 그룹 내 통신 | localhost로 통신 |
| 쿠버네티스 대응 | **파드**와 같은 개념 |
| 용도 | 앱 + 로그 수집·감시 등 보조 컨테이너(사이드카) 구성 |

- 볼륨 : Azure Files 공유를 마운트해 데이터 영속화 (컨테이너 자체는 상태를 유지하지 않음)
- 재시작 정책 : 항상(Always) / 실패 시(OnFailure) / 안 함(Never) — 일괄 처리는 OnFailure·Never 사용

---

## 컨테이너 그룹의 배포 방식

| 방식 | 내용 | 어울리는 경우 |
|---|---|---|
| Azure CLI·포털 | 명령이나 화면에서 옵션을 지정해 바로 생성 | 컨테이너 1개짜리 간단한 실행 |
| YAML 파일 | 컨테이너 그룹의 구성을 YAML로 기술해 배포 | **컨테이너만** 여러 개 배포할 때 — 간결 |
| ARM 템플릿 | 애저 리소스를 JSON으로 정의하는 표준 템플릿 (Bicep으로도 작성) | 스토리지 등 **다른 애저 리소스와 함께** 배포할 때 |

```
az container create --resource-group <그룹> --file container-group.yaml
```

- 여러 컨테이너로 된 그룹은 CLI 옵션만으로는 표현하기 어려워 YAML이나 ARM 템플릿 사용

## ACI의 위치

> ACI는 오케스트레이션 도구가 아니라 **컨테이너를 실행하는 가장 단순한 부품**

| 구분 | ACI | AKS |
|---|---|---|
| 성격 | 컨테이너(그룹) 단위 실행 | 클러스터 단위 오케스트레이션 |
| 자동 복구·스케일링·롤링 업데이트 | 없음 (재시작 정책 정도) | 있음 |
| 서비스 디스커버리·로드 밸런싱 | 없음 | 있음 |
| 기동 | 수 초 | 클러스터 구축 필요 |
| 운용 부담 | 거의 없음 | 노드·클러스터 관리 필요 |

**어울리는 용도**

- 일괄 처리, 빌드·테스트 등 **실행하고 끝나는** 작업
- 개발·검증용의 간단한 애플리케이션
- AKS의 가상 노드를 통한 **급증한 부하의 수용**(버스팅) — 오케스트레이션은 AKS, 실행은 ACI

<details><summary>ACI만으로 규모 있는 웹 서비스를 운영하기 어려운 이유는?</summary>

ACI는 컨테이너 그룹을 하나씩 실행할 뿐, 여러 개를 묶어 부하를 분산하거나 요청량에 맞춰 개수를 자동으로 조절하는 기능이 없다. <br>
새 버전으로 무중단 교체하는 롤링 업데이트나 장애 시 다른 곳에서 다시 띄우는 기능도 직접 구현해야 한다. <br>
그래서 이런 기능이 필요하면 AKS를 쓰거나, 오케스트레이션까지 포함한 서버리스 서비스인 Azure Container Apps를 사용한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: ACI는 서버·클러스터 없이 컨테이너를 초 단위 과금으로 바로 실행하는 애저의 서버리스 컨테이너 환경으로, 파드에 해당하는 컨테이너 그룹 단위로 동작하고 CLI·YAML·ARM 템플릿으로 배포하며, 오케스트레이션 기능이 없으므로 단순한 작업이나 AKS의 버스팅 용도로 쓰인다
