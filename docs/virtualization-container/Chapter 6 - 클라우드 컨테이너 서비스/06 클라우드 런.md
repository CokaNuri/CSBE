# 클라우드 런

> GCP의 **서버리스 컨테이너 실행 환경** — 컨테이너 이미지를 올리면 서버·클러스터 없이 바로 실행

## 클라우드 런이란

> Cloud Run : 컨테이너 이미지를 배포하면 실행·확장·HTTPS 주소 제공까지 자동으로 해 주는 완전 관리형 서비스

- 오픈 소스 **Knative**(쿠버네티스 위에서 서버리스를 구현하는 프로젝트)의 API와 호환
- 컨테이너로 만들 수 있으면 **언어·라이브러리에 제한 없음**
- 조건 : 컨테이너가 지정된 포트(환경 변수 `PORT`)에서 요청을 받아야 함

---

## 클라우드 런의 작동 방식

```
컨테이너 이미지 ──배포──▶ 서비스 (고유한 HTTPS URL)
                            │
                        리비전 (배포할 때마다 생성되는 불변 버전)
                            │
        요청 증가 ──▶ 인스턴스 자동 증가
        요청 없음 ──▶ 인스턴스 0개 (과금 없음)
```

| 용어 | 내용 |
|---|---|
| 서비스 | 요청을 받는 단위 — URL이 하나 부여됨 |
| 리비전 | 배포할 때마다 만들어지는 **변경 불가능한 버전** — 이전 리비전으로 되돌리기 쉬움 |
| 인스턴스 | 리비전을 실행하는 컨테이너 — 요청량에 따라 자동 증감 |
| 작업 (Job) | 요청을 받지 않고 실행 후 종료하는 일괄 처리용 |

- **트래픽 분할** : 리비전별로 요청 비율을 지정 (예: 새 버전 10%, 기존 버전 90%) → 카나리 배포
- **동시 실행 수** : 인스턴스 하나가 동시에 처리할 요청 수를 설정 — 초과하면 인스턴스 추가

---

## 클라우드 런의 장점과 단점

| 장점 | 단점 |
|---|---|
| 클러스터·노드 관리 불필요 | **콜드 스타트** — 0개에서 기동할 때 첫 응답 지연 |
| 요청이 없으면 **0까지 축소** → 비용 0 | 요청 처리 시간 제한 있음 |
| 요청 처리 중인 시간만 과금 | 상태를 유지할 수 없음 (stateless) → 외부 저장소 필요 |
| 컨테이너라서 이식성 높음, 언어 제한 없음 | 쿠버네티스만큼 세밀한 제어 불가 (네트워크·스케줄링 등) |
| HTTPS, 리비전 관리, 트래픽 분할 기본 제공 | 항상 높은 부하가 걸리면 상시 기동 방식보다 비쌀 수 있음 |

- 콜드 스타트 완화 : **최소 인스턴스 수**를 1 이상으로 설정 (대신 대기 비용 발생)

## 안토스란

> Anthos : 구글 클라우드, 온프레미스, 다른 클라우드의 쿠버네티스 클러스터를 **하나로 통합 관리**하는 플랫폼

```
              Anthos (통합 관리·정책·서비스 메시)
        ┌──────────┬──────────┬──────────┐
        ▼          ▼          ▼          ▼
     GCP(GKE)   온프레미스     AWS        애저
```

| 기능 | 내용 |
|---|---|
| 멀티 클러스터 관리 | 여러 환경의 클러스터를 한 콘솔에서 확인·조작 |
| 설정 동기화 | Git에 둔 설정·정책을 모든 클러스터에 일괄 적용 |
| 서비스 메시 | Istio 기반으로 서비스 간 통신의 제어·암호화·관측 |

- 하이브리드 클라우드·멀티 클라우드를 **같은 방식**으로 운영하기 위한 기반
- 현재는 GKE Enterprise라는 이름으로 통합되어 제공

<details><summary>Cloud Run과 Cloud Functions(FaaS)는 어떻게 다를까?</summary>

Cloud Functions는 함수 코드만 올리고 실행 환경은 구글이 정해 준 런타임을 쓴다. <br>
Cloud Run은 컨테이너 이미지를 올리므로 언어·OS 패키지·라이브러리를 자유롭게 고를 수 있고, 한 인스턴스가 여러 요청을 동시에 처리할 수 있다. <br>
둘 다 0까지 축소되고 쓴 만큼 과금되지만, 자유도와 이식성은 Cloud Run이, 간편함은 Cloud Functions가 앞선다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 클라우드 런은 Knative 기반의 서버리스 컨테이너 실행 환경으로, 이미지를 배포하면 리비전 단위로 관리되고 요청량에 따라 0까지 자동 확장·축소되어 쓴 만큼만 과금되지만 콜드 스타트와 상태 유지 불가라는 제약이 있으며, 안토스는 여러 클라우드와 온프레미스의 쿠버네티스 클러스터를 통합 관리하는 플랫폼이다
