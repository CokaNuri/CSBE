# AWS Fargate

> AWS의 **서버리스 컨테이너 실행 환경** — 서버(EC2)를 준비·관리하지 않고 컨테이너만 실행

## AWS Fargate란

> AWS Fargate : 컨테이너를 실행할 서버를 AWS가 대신 준비·관리해 주는 실행 기반

- 단독으로 쓰는 서비스가 아니라 **ECS·EKS의 실행 기반(데이터 플레인)** 으로 선택해 사용
- 이용자는 태스크(파드)에 필요한 **vCPU와 메모리만 지정** → 서버의 종류·대수·OS 패치를 신경 쓰지 않음

```
        ECS / EKS (무엇을 몇 개 실행할지 관리)
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
   EC2 방식              Fargate 방식
 이용자가 서버 관리      AWS가 서버 관리
 [EC2][EC2][EC2]       (서버가 보이지 않음)
  컨테이너 배치          태스크마다 격리된 실행 환경
```

| 구분 | EC2 | Fargate |
|---|---|---|
| 서버 준비·확장 | 이용자 | AWS |
| OS 패치·보안 관리 | 이용자 | AWS |
| 과금 단위 | 인스턴스 기동 시간 (비어 있어도 과금) | 태스크가 요청한 vCPU·메모리 × 실행 시간 |
| 격리 | 한 인스턴스에 여러 태스크 | 태스크마다 전용 실행 환경 |
| 제약 | 거의 없음 | GPU, 특권 컨테이너, 데몬셋, 호스트 접근 등 제한 |

**장단점**

| 장점 | 단점 |
|---|---|
| 서버 운용 부담 없음 | 같은 자원이면 EC2보다 단가가 높은 편 |
| 필요한 만큼만 자원을 써서 낭비가 적음 | 서버에 접속해 조사하거나 세부 설정을 바꿀 수 없음 |
| 태스크 단위 격리로 보안에 유리 | 기동이 EC2 위 컨테이너보다 느릴 수 있음 |

## AWS Lambda와 차이점

> 둘 다 서버리스지만 **실행 단위와 실행 방식**이 다름

| 구분 | AWS Fargate | AWS Lambda |
|---|---|---|
| 분류 | 서버리스 **컨테이너** | 서버리스 **함수** (FaaS) |
| 실행 단위 | 컨테이너 (태스크) | 함수 |
| 실행 방식 | 기동 후 계속 실행 — 상시 대기 가능 | 이벤트가 발생할 때만 실행 |
| 실행 시간 | 제한 없음 | 최대 15분 |
| 실행 환경 | 컨테이너 이미지로 자유롭게 정의 | 지원 런타임 중심 (컨테이너 이미지도 가능하나 제약 있음) |
| 확장 | 태스크 수 조정 (자동 확장 설정 필요) | 요청 수에 따라 자동 |
| 과금 | 태스크 실행 시간 × vCPU·메모리 | 요청 횟수 + 실행 시간 × 메모리 |
| 요청이 없을 때 | 태스크가 떠 있으면 과금 | 과금 없음 |

**어울리는 용도**

| Fargate | Lambda |
|---|---|
| 상시 요청을 받는 웹·API 서버 | 파일 업로드·메시지 도착 등 이벤트 처리 |
| 오래 걸리는 일괄 처리 | 짧게 끝나는 처리, 정기 실행 작업 |
| 기존 컨테이너 애플리케이션 이전 | 요청이 드문드문 발생하는 기능 |

<details><summary>Fargate를 쓰면 무조건 EC2보다 이득일까?</summary>

그렇지 않다. Fargate는 같은 vCPU·메모리 기준으로 EC2보다 단가가 높은 편이라, 항상 높은 부하로 자원을 꽉 채워 쓰는 서비스라면 EC2가 저렴할 수 있다. <br>
반대로 부하 변동이 크거나 자원이 남는 시간이 많다면 쓴 만큼만 과금되는 Fargate가 유리하다. <br>
여기에 서버 운용에 드는 인력 비용까지 함께 따져서 판단한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: AWS Fargate는 ECS·EKS의 실행 기반으로 선택하는 서버리스 컨테이너 실행 환경으로, 서버 관리 없이 태스크에 필요한 vCPU·메모리만 지정해 쓴 만큼 과금되며, 이벤트 발생 시에만 최대 15분 실행되는 함수 단위의 Lambda와 달리 컨테이너를 실행 시간 제한 없이 상시 실행할 수 있다
