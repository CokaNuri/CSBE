# 아마존 EKS

> AWS의 **관리형 쿠버네티스 서비스** — 컨트롤 플레인을 AWS가 운영하고 이용자는 표준 쿠버네티스를 그대로 사용

## 아마존 EKS란

> Amazon EKS (Elastic Kubernetes Service) : AWS에서 쿠버네티스 클러스터를 손쉽게 실행할 수 있게 해 주는 관리형 서비스

- 쿠버네티스 **적합성 인증**을 받은 표준 쿠버네티스 → 기존 매니페스트·kubectl·헬름 등을 그대로 사용
- 마스터(컨트롤 플레인)의 구축·이중화·패치·업그레이드를 AWS가 담당
- IAM(인증), VPC(네트워크), ELB(로드 밸런서), EBS(스토리지) 등 AWS 서비스와 연계

---

## 아마존 EKS의 작동 방식

```
kubectl ──▶ ┌─ 컨트롤 플레인 (AWS 관리) ─┐
            │ API 서버 · etcd · 스케줄러 │
            └────────────┬─────────────┘
                         │
          ┌──────────────┼──────────────┐
          ▼              ▼              ▼
       워커 노드       워커 노드       Fargate
        (EC2)          (EC2)        (서버리스)
       파드 파드       파드 파드        파드
          └──── 이용자의 VPC 안에서 실행 ────┘
```

**워커 노드를 준비하는 방법**

| 방식 | 내용 |
|---|---|
| 자체 관리형 노드 | 이용자가 EC2 인스턴스를 직접 만들고 클러스터에 등록·관리 |
| 관리형 노드 그룹 | 노드의 생성·업데이트·종료를 AWS가 자동화 (EC2는 이용자 계정에 생성) |
| Fargate | 노드 없이 파드 단위로 서버리스 실행 |

- 파드 네트워크 : VPC CNI 플러그인으로 파드에 **VPC의 IP 주소**를 직접 할당

## 리전과 가용 영역

| 용어 | 내용 |
|---|---|
| 리전 | 데이터 센터가 모여 있는 **지리적 지역** (예: 서울 리전) |
| 가용 영역 (AZ) | 리전 안에서 전원·네트워크가 서로 독립된 **데이터 센터 그룹** |

- EKS의 컨트롤 플레인은 한 리전의 **여러 가용 영역에 분산** 배치 → 한 영역에 장애가 나도 계속 동작
- 워커 노드도 여러 가용 영역에 나누어 두면 영역 장애에 대비 가능

```
              리전
┌────────┬────────┬────────┐
│ AZ - a │ AZ - b │ AZ - c │
│ 마스터  │ 마스터  │ 마스터  │  ← AWS가 자동 분산
│ 워커   │ 워커    │ 워커   │  ← 이용자가 분산 배치
└────────┴────────┴────────┘
```

## 아마존 EKS의 장단점

| 장점 | 단점 |
|---|---|
| 표준 쿠버네티스 → 이식성, 풍부한 생태계 활용 | 쿠버네티스 자체의 **학습 부담**이 큼 |
| 컨트롤 플레인의 운영·고가용성을 AWS가 보장 | 클러스터당 컨트롤 플레인 **요금** 발생 |
| AWS 서비스(IAM, VPC, ELB)와 연계 | 워커 노드·애드온·버전 업그레이드는 이용자가 챙겨야 함 |
| 온프레미스·타 클라우드와 같은 방식으로 운영 가능 | ECS보다 구성이 복잡 |

<details><summary>EKS를 쓰면 쿠버네티스 버전 업그레이드를 신경 쓰지 않아도 될까?</summary>

그렇지 않다. 쿠버네티스는 주기적으로 새 버전이 나오고 오래된 버전은 지원이 끝난다. <br>
EKS는 컨트롤 플레인 업그레이드를 버튼 하나로 처리해 주지만, 언제 올릴지 결정하고 워커 노드와 애드온을 맞춰 올리는 것은 이용자의 몫이다. <br>
업그레이드 전에 사용 중인 API가 새 버전에서 제거되지 않았는지도 확인해야 한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 아마존 EKS는 AWS가 컨트롤 플레인을 여러 가용 영역에 분산해 운영해 주는 관리형 쿠버네티스 서비스로, 워커 노드는 EC2(자체 관리·관리형 노드 그룹)나 Fargate로 준비하며, 표준 쿠버네티스의 이식성과 생태계를 누릴 수 있지만 학습 부담과 컨트롤 플레인 요금이 따른다
