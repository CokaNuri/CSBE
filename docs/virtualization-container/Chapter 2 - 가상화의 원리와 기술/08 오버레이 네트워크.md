# 오버레이 네트워크

> 오버레이 네트워크 : 물리 네트워크(언더레이) 위에 **터널**로 만든 가상 네트워크 — VLAN의 약점을 극복하는 기술

## 오버레이 네트워크란

| 용어 | 내용 |
|---|---|
| 언더레이 | 실제 장비·배선으로 이루어진 물리 네트워크 (IP 통신만 되면 됨) |
| 오버레이 | 언더레이 위에 논리적으로 덧씌운 가상 네트워크 |

- 가상 서버는 오버레이만 보고 통신 → 언더레이가 어떻게 생겼는지 몰라도 됨
- 물리 장비 설정을 바꾸지 않고 **양 끝단(서버)**의 설정만으로 가상 네트워크를 생성·변경

**VLAN의 약점과 극복**

| VLAN의 약점 | 오버레이(VXLAN)의 해결 |
|---|---|
| ID 12비트 → 4,094개 | VNI **24비트** → 약 1,600만 개 |
| L2 범위에 묶임 | L3(IP) 네트워크를 넘어 L2 네트워크 연장 |
| 경로상의 모든 스위치 설정 필요 | 끝단만 설정, 중간 장비는 IP 전달만 |
| 가상 서버 이동 시 설정 변경 | 다른 서버·데이터 센터로 이동해도 같은 네트워크 유지 |

---

## 터널링이란

> 터널링 : 패킷을 **다른 프로토콜의 패킷 안에 통째로 넣어**(캡슐화) 전송하는 기술

```
송신 측:  [원래 프레임]  →  [새 헤더 | 원래 프레임]   (캡슐화)
                              ↓ 물리 네트워크는 새 헤더만 보고 전달
수신 측:  [새 헤더 | 원래 프레임]  →  [원래 프레임]   (역캡슐화)
```

- 중간 장비 입장에서는 평범한 IP 패킷 → 안에 무엇이 들었는지 신경 쓰지 않음
- 양 끝단이 마치 직접 연결된 것처럼 동작

**VXLAN (Virtual eXtensible LAN)**

| 요소 | 내용 |
|---|---|
| 캡슐화 | L2 이더넷 프레임을 **UDP/IP 패킷**에 넣음 (L2 over L3) |
| VNI | 가상 네트워크를 구분하는 24비트 식별자 |
| VTEP | 캡슐화·역캡슐화를 수행하는 터널의 끝점 — 하이퍼바이저의 가상 스위치나 물리 스위치 |

| 터널링 프로토콜 | 특징 |
|---|---|
| VXLAN | UDP 기반, 가장 널리 쓰임 |
| GRE / NVGRE | IP 안에 직접 캡슐화 |
| Geneve | 확장 가능한 헤더를 가진 후속 규격 |

**주의점**

- 헤더가 추가되어 패킷이 커짐 → **MTU** 조정 필요 (초과 시 단편화로 성능 저하)
- 캡슐화·역캡슐화 처리 부하
- 물리 네트워크에서는 내부 통신 내용이 보이지 않아 장애 분석이 어려움

<details><summary>컨테이너 환경에서도 오버레이 네트워크를 쓸까?</summary>

쓴다. 여러 호스트에 흩어진 컨테이너들이 마치 같은 네트워크에 있는 것처럼 통신해야 하기 때문이다. <br>
도커 스웜의 오버레이 네트워크나 쿠버네티스의 일부 네트워크 플러그인이 VXLAN으로 호스트 간 터널을 만들어 <br>
컨테이너가 어느 호스트에 있든 고유한 IP로 서로 통신하게 한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 오버레이 네트워크는 물리 네트워크(언더레이) 위에 터널링으로 가상 네트워크를 덧씌우는 기술로, L2 프레임을 UDP/IP로 캡슐화하는 VXLAN이 대표적이며 24비트 VNI로 약 1,600만 개의 네트워크를 만들고 L3를 넘어 확장할 수 있어 VLAN의 한계를 극복하지만 MTU와 처리 부하에 주의해야 한다
