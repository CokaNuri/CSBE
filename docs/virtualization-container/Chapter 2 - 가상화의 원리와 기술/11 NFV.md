# NFV

> NFV (Network Functions Virtualization) : 라우터·방화벽·로드 밸런서 같은 **네트워크 기기의 기능을 소프트웨어로 구현**해 범용 서버의 가상 환경에서 실행하는 기술

## NFV란

- 기존 : 기능마다 **전용 하드웨어**(어플라이언스) 구매·설치 → 비싸고 증설·변경이 느림
- NFV : 범용 서버 + 가상화 위에 네트워크 기능을 **가상 머신·컨테이너**로 올림

| 구분 | 전용 장비 | NFV |
|---|---|---|
| 하드웨어 | 기능별 전용 기기 | 범용 서버 (x86) |
| 도입 | 장비 조달·설치 | 소프트웨어 배포 (수 분) |
| 확장 | 장비 교체·추가 | 자원 할당 변경, 인스턴스 추가 |
| 성능 | 전용 칩으로 고성능 | 소프트웨어 처리로 상대적으로 낮을 수 있음 |
| 비용 | 초기 비용 큼 | 장비·공간·전력 절감 |

| 장점 | 단점 |
|---|---|
| 장비 비용·설치 공간·전력 절감 | 전용 장비보다 처리 성능이 낮을 수 있음 |
| 서비스의 신속한 도입·변경 | 물리 서버 장애 시 여러 기능이 동시에 중단 |
| 수요에 따른 유연한 확장·축소 | 가상화 기반까지 포함해 운용이 복잡 |
| 제조사 종속 완화 | 여러 제품 간 상호 운용성 검증 필요 |

**SDN과의 관계**

| 구분 | SDN | NFV |
|---|---|---|
| 대상 | 네트워크의 **제어** | 네트워크 **기기의 기능** |
| 핵심 | 제어와 전송의 분리, 중앙 제어 | 기능과 전용 하드웨어의 분리 |
| 주도 | 데이터 센터·연구 분야 | 통신 사업자 (ETSI) |

- 서로 독립적이지만 **보완 관계** — NFV로 만든 가상 기능들을 SDN으로 연결·제어

## NFV를 구성하는 아키텍처

> ETSI(유럽 전기 통신 표준 협회)가 정의한 구조 — 세 부분으로 구성

| 구성 요소 | 역할 |
|---|---|
| NFVI (NFV 인프라) | VNF를 실행하는 기반 — 물리 자원(서버·스토리지·네트워크) + 가상화 계층(하이퍼바이저) |
| VNF (가상 네트워크 기능) | 소프트웨어로 구현된 네트워크 기능 — 가상 라우터, 가상 방화벽, 가상 로드 밸런서 등 |
| MANO (관리·오케스트레이션) | NFVI와 VNF 전체를 관리·자동화 |

**MANO의 구성**

| 요소 | 역할 |
|---|---|
| NFVO (오케스트레이터) | 여러 VNF를 조합한 네트워크 서비스 전체의 생성·관리 |
| VNFM (VNF 관리자) | 개별 VNF의 생성·확장·종료 (생명 주기) 관리 |
| VIM (가상 인프라 관리자) | NFVI의 자원 관리·할당 (예: OpenStack) |

```
              ┌──────────────┐
[ VNF ][ VNF ][ VNF ]   ←─── │    MANO      │
[       NFVI        ]   ←─── │ NFVO/VNFM/VIM│
(가상화 계층 + 물리 자원)     └──────────────┘
```

<details><summary>서비스 체이닝이란 무엇일까?</summary>

트래픽이 여러 네트워크 기능을 정해진 순서대로 거치도록 연결하는 것이다. (예: 방화벽 → 침입 탐지 → 로드 밸런서) <br>
전용 장비 시절에는 케이블로 순서대로 연결해야 했지만, <br>
NFV로 기능을 가상화하고 SDN으로 경로를 제어하면 소프트웨어 설정만으로 이용자·서비스마다 다른 순서를 구성할 수 있다.
</details>

## 🔑 최종 정리

> 한 줄 요약: NFV는 전용 장비로 제공되던 라우터·방화벽 등의 네트워크 기능을 범용 서버의 가상 환경에서 소프트웨어(VNF)로 실행해 비용을 줄이고 도입·확장을 빠르게 하는 기술로, 실행 기반인 NFVI, 가상화된 기능인 VNF, 전체를 관리하는 MANO(NFVO·VNFM·VIM)로 구성되며 SDN과 보완 관계에 있다
