# 클라우드의 서버 가상화

> AWS·GCP·Azure는 각각 **가상 서버를 빌려주는 IaaS 서비스**를 제공 — 이용자는 하이퍼바이저를 의식하지 않고 사양만 골라 사용

## 아마존 EC2

> Amazon Elastic Compute Cloud — AWS의 가상 서버 서비스, 가상 서버를 **인스턴스**라고 부름

| 요소 | 내용 |
|---|---|
| 인스턴스 유형 | CPU·메모리 조합을 정한 사양 — 범용, 컴퓨팅 최적화, 메모리 최적화 등 (예: `t3.micro`) |
| AMI | 인스턴스를 만드는 템플릿 이미지 (OS + 설정) |
| EBS | 인스턴스에 붙이는 블록 스토리지 (가상 디스크) |
| 보안 그룹 | 인스턴스 단위의 가상 방화벽 |
| Auto Scaling | 부하에 따라 인스턴스 수를 자동 증감 |

- 과금 : 온디맨드(쓴 만큼), 예약·절감 플랜(장기 약정 할인), 스팟(남는 자원을 싸게, 중단 가능)
- 하이퍼바이저 : 초기에는 Xen → 현재는 KVM 기반의 **Nitro**

---

## GCE

> Google Compute Engine — GCP의 가상 서버 서비스

| 특징 | 내용 |
|---|---|
| 머신 유형 | 미리 정의된 유형 + vCPU·메모리를 직접 지정하는 **커스텀 머신 유형** |
| 라이브 마이그레이션 | 호스트 점검 시 VM을 멈추지 않고 다른 호스트로 이동 |
| 과금 | 초 단위, 오래 쓰면 자동으로 할인 (지속 사용 할인) |
| 영구 디스크 | VM에 붙이는 블록 스토리지 |
| 관리형 인스턴스 그룹 | 동일한 VM 여러 대를 묶어 자동 확장·복구 |

- 하이퍼바이저 : KVM 기반

---

## 가상 머신

> Azure Virtual Machines — Microsoft Azure의 가상 서버 서비스

| 특징 | 내용 |
|---|---|
| VM 크기 | 용도별 시리즈 (범용, 컴퓨팅, 메모리 최적화 등) |
| 관리 디스크 | VM에 붙이는 블록 스토리지 |
| 가용성 집합 / 가용성 영역 | VM을 서로 다른 랙·데이터 센터에 분산 배치 |
| 가상 머신 확장 집합 | 동일한 VM 여러 대의 자동 확장 |
| Windows 친화성 | Windows Server·Active Directory 등 Microsoft 제품과의 연계, 기존 라이선스 활용 |

- 하이퍼바이저 : Hyper-V 기반

## 세 서비스 비교

| 구분 | AWS | GCP | Azure |
|---|---|---|---|
| 서비스 이름 | Amazon EC2 | Compute Engine (GCE) | Virtual Machines |
| 가상 서버 명칭 | 인스턴스 | VM 인스턴스 | 가상 머신 |
| 이미지 | AMI | 이미지 | 이미지 |
| 블록 스토리지 | EBS | 영구 디스크 | 관리 디스크 |
| 자동 확장 | Auto Scaling 그룹 | 관리형 인스턴스 그룹 | 가상 머신 확장 집합 |

<details><summary>클라우드의 가상 서버를 "애완동물이 아니라 가축처럼" 다루라는 말은 무슨 뜻일까?</summary>

물리 서버는 이름을 붙이고 고장 나면 고쳐 쓰는 애완동물처럼 다뤘다. <br>
클라우드의 가상 서버는 이미지로 언제든 똑같이 만들 수 있으므로, 문제가 생기면 고치지 않고 버리고 새로 만든다. <br>
서버 한 대에 의존하지 않도록 설계해야 자동 확장·자동 복구의 이점을 살릴 수 있다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 클라우드의 서버 가상화 서비스는 AWS의 EC2, GCP의 Compute Engine, Azure의 Virtual Machines가 대표적이며, 모두 사양(인스턴스 유형)과 이미지를 골라 가상 서버를 만들고 블록 스토리지를 붙여 쓰며 자동 확장으로 대수를 조절하는 구조로, 이름과 세부 기능만 다르다
