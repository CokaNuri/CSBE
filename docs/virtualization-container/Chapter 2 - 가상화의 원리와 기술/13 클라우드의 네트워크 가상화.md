# 클라우드의 네트워크 가상화

> AWS·GCP·Azure는 클라우드 안에 **이용자 전용의 격리된 가상 네트워크**를 만드는 서비스를 제공 — 그 안에 가상 서버를 배치

## 아마존 VPC

> Amazon Virtual Private Cloud — AWS 안에 논리적으로 격리된 이용자 전용 네트워크

| 요소 | 내용 |
|---|---|
| VPC | IP 주소 범위(CIDR)를 지정해 만드는 가상 네트워크 — **리전** 단위 |
| 서브넷 | VPC를 나눈 작은 네트워크 — **가용 영역(AZ)** 단위 |
| 라우트 테이블 | 서브넷의 통신 경로 지정 |
| 인터넷 게이트웨이 | VPC와 인터넷을 연결 |
| NAT 게이트웨이 | 프라이빗 서브넷에서 인터넷으로 **나가는** 통신만 허용 |
| 보안 그룹 | **인스턴스** 단위 방화벽 — 상태 저장(응답 통신 자동 허용) |
| 네트워크 ACL | **서브넷** 단위 방화벽 — 상태 비저장 |

| 서브넷 종류 | 내용 | 배치 대상 |
|---|---|---|
| 퍼블릭 서브넷 | 인터넷 게이트웨이로 가는 경로가 있음 | 웹 서버, 로드 밸런서 |
| 프라이빗 서브넷 | 인터넷에서 직접 접근 불가 | 애플리케이션 서버, DB |

- 다른 네트워크와 연결 : VPC 피어링(VPC 간), Site-to-Site VPN, Direct Connect(전용선)

## VPC

> Google Cloud VPC — GCP의 가상 네트워크

| 특징 | 내용 |
|---|---|
| 글로벌 리소스 | VPC 하나가 **전 세계 리전**에 걸침 — 리전 간 통신에 별도 연결 불필요 |
| 서브넷 | **리전** 단위 (여러 영역에 걸침) |
| 방화벽 규칙 | VPC 단위로 정의, 태그·서비스 계정으로 적용 대상 지정 |
| Cloud NAT | 외부 IP 없는 VM의 인터넷 방향 통신 |
| 공유 VPC | 여러 프로젝트가 하나의 VPC를 함께 사용 |

- 다른 네트워크와 연결 : VPC 네트워크 피어링, Cloud VPN, Cloud Interconnect(전용선)

---

## 가상 네트워크

> Azure Virtual Network (VNet) — Azure의 가상 네트워크

| 특징 | 내용 |
|---|---|
| VNet | 주소 공간을 지정해 만드는 가상 네트워크 — **리전** 단위 |
| 서브넷 | VNet을 나눈 네트워크 (리전 내 가용성 영역 전체에 걸침) |
| 네트워크 보안 그룹 (NSG) | 서브넷 또는 NIC 단위의 통신 허용·거부 규칙 |
| NAT Gateway | 프라이빗 자원의 인터넷 방향 통신 |

- 다른 네트워크와 연결 : VNet 피어링, VPN Gateway, ExpressRoute(전용선)

## 세 서비스 비교

| 구분 | AWS | GCP | Azure |
|---|---|---|---|
| 서비스 이름 | Amazon VPC | VPC | Virtual Network (VNet) |
| 네트워크 범위 | 리전 | 글로벌 | 리전 |
| 서브넷 범위 | 가용 영역 | 리전 | 리전 |
| 방화벽 | 보안 그룹, 네트워크 ACL | 방화벽 규칙 | 네트워크 보안 그룹 |
| VPN 연결 | Site-to-Site VPN | Cloud VPN | VPN Gateway |
| 전용선 연결 | Direct Connect | Cloud Interconnect | ExpressRoute |

<details><summary>DB 서버를 프라이빗 서브넷에 두는 이유는?</summary>

DB에는 인터넷에서 직접 접근할 필요가 없고, 접근 경로 자체가 없으면 공격받을 면이 줄어든다. <br>
인터넷 요청은 퍼블릭 서브넷의 로드 밸런서·웹 서버가 받고, DB는 내부의 애플리케이션 서버만 접근하도록 방화벽 규칙을 건다. <br>
패치 등으로 DB 쪽에서 외부로 나가야 할 때는 NAT 게이트웨이를 사용한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 클라우드의 네트워크 가상화 서비스는 AWS의 VPC, GCP의 VPC, Azure의 VNet으로, 이용자 전용의 격리된 가상 네트워크에 서브넷·라우팅·방화벽·게이트웨이를 구성해 가상 서버를 배치하며, AWS·Azure는 리전 단위이고 GCP는 글로벌 단위라는 점과 서브넷 범위가 다르다
