# SDN

> SDN (Software Defined Networking) : 네트워크의 **제어 기능을 장비에서 분리**해 소프트웨어로 중앙에서 정의·제어하는 기술

## SDN이란

**기존 네트워크의 문제**

- 스위치·라우터 한 대 한 대가 경로 계산(제어)과 패킷 전달(전송)을 모두 수행
- 구성을 바꾸려면 장비마다 접속해 개별 설정 → 느리고 실수하기 쉬움, 제조사마다 명령어가 다름

**SDN의 구조**

| 평면 | 역할 | 위치 |
|---|---|---|
| 컨트롤 플레인 (제어) | 경로 결정, 정책 관리 — "어디로 보낼지" 판단 | **SDN 컨트롤러** (중앙) |
| 데이터 플레인 (전송) | 지시받은 대로 패킷 전달 | 스위치·라우터 |

```
        [ 애플리케이션 ]      네트워크 관리·자동화 도구
              │  노스바운드 API
        [ SDN 컨트롤러 ]      네트워크 전체를 파악하고 제어
              │  사우스바운드 API (OpenFlow 등)
   [스위치]  [스위치]  [스위치]   패킷 전달만 담당
```

| 장점 | 단점 |
|---|---|
| 중앙에서 네트워크 전체를 일괄 설정 | 컨트롤러 장애 시 영향이 큼 → 이중화 필수 |
| 프로그램으로 자동화, 빠른 구성 변경 | 컨트롤러가 공격 대상이 됨 |
| 트래픽 상황에 따른 유연한 경로 제어 | 기존 장비·운용 방식에서 전환 비용 |
| 제조사에 덜 의존 | 소프트웨어 개발·운용 역량 필요 |

**구현 방식**

| 방식 | 내용 |
|---|---|
| 홉 바이 홉 | 경로상의 모든 스위치를 컨트롤러가 제어 (OpenFlow) — 대응 장비 필요 |
| 오버레이 | 기존 물리 네트워크는 그대로 두고 끝단의 가상 스위치를 제어해 터널 구성 (VXLAN) |

## OpenFlow란

> SDN 컨트롤러와 스위치 사이의 **통신 규약** — 대표적인 사우스바운드 프로토콜

| 구성 요소 | 내용 |
|---|---|
| OpenFlow 컨트롤러 | 플로 테이블을 작성해 스위치에 내려보냄 |
| OpenFlow 스위치 | 플로 테이블에 따라 패킷 처리 |
| 플로 테이블 | "이런 패킷은 이렇게 처리하라"는 규칙(플로 엔트리)의 모음 |

**플로 엔트리**

| 항목 | 내용 |
|---|---|
| 매치 필드 (조건) | 수신 포트, MAC 주소, VLAN ID, IP 주소, 포트 번호 등 |
| 액션 (처리) | 특정 포트로 전달, 폐기, 헤더 수정, 컨트롤러로 전달 |
| 카운터 (통계) | 일치한 패킷 수·바이트 수 |

**동작 순서**

1. 스위치가 패킷 수신 → 플로 테이블에서 조건이 일치하는 엔트리 검색
2. 일치 → 액션대로 처리
3. 불일치 → 컨트롤러에 문의 (**Packet-In**)
4. 컨트롤러가 처리 방법을 결정해 플로 엔트리 등록 (**Flow-Mod**) → 이후 같은 패킷은 스위치가 바로 처리

<details><summary>기존 스위치의 MAC 주소 테이블과 플로 테이블은 무엇이 다를까?</summary>

MAC 주소 테이블은 목적지 MAC 주소 하나만 보고 내보낼 포트를 정하며, 스위치가 스스로 학습한다. <br>
플로 테이블은 L1~L4의 여러 필드를 조합해 조건을 만들 수 있고, 전달 외에 폐기·수정 같은 다양한 처리를 지정하며, <br>
내용을 중앙의 컨트롤러가 정한다. 그래서 스위치 한 대가 스위치·라우터·방화벽처럼 동작할 수 있다.
</details>

## 🔑 최종 정리

> 한 줄 요약: SDN은 경로를 결정하는 컨트롤 플레인을 장비에서 분리해 중앙의 컨트롤러가 소프트웨어로 네트워크 전체를 제어하고 장비는 패킷 전달(데이터 플레인)만 맡는 구조이며, OpenFlow는 컨트롤러가 조건·액션·카운터로 이루어진 플로 테이블을 스위치에 내려보내는 대표적인 제어 프로토콜이다
