# 서버 가상화의 원리

> 서버 가상화 : 한 대의 물리 서버에 여러 대의 **가상 서버**를 구축해, 각각이 독립된 컴퓨터처럼 동작하게 하는 기술

## 서버 가상화란

- **가상화 소프트웨어**가 물리 서버의 CPU·메모리·디스크·NIC를 나누어 가상 하드웨어로 제공
- 가상 서버(가상 머신, VM)는 가상 하드웨어 위에서 자신만의 OS를 실행

| 용어 | 내용 |
|---|---|
| 호스트 | 가상 서버를 실행하는 물리 서버 (또는 그 OS) |
| 게스트 | 가상 서버 (또는 그 안의 OS) |
| 가상 머신 (VM) | 가상 CPU·메모리·디스크·NIC로 구성된 논리적 컴퓨터 |
| 하이퍼바이저 | 가상 머신을 만들고 물리 자원을 배분·관리하는 소프트웨어 |

**자원을 나누는 원리**

| 자원 | 방식 |
|---|---|
| CPU | 물리 코어의 실행 시간을 가상 CPU(vCPU)에 **시분할** 할당 |
| 메모리 | 물리 메모리 일부를 가상 서버에 매핑 — 합계가 물리 용량을 넘게 할당하기도 함 (**오버커밋**) |
| 디스크 | 가상 디스크를 호스트의 **파일**(이미지)로 저장 |
| 네트워크 | 가상 NIC를 **가상 스위치**에 연결 → 물리 NIC를 통해 외부와 통신 |

<details><summary>가상 서버 안의 OS는 자신이 가상 환경에 있다는 것을 알까?</summary>

완전 가상화에서는 모른다. 하이퍼바이저가 실제 하드웨어처럼 동작하는 가상 하드웨어를 보여 주므로 OS를 수정 없이 그대로 설치할 수 있다. <br>
반면 준가상화에서는 게스트 OS가 가상 환경임을 알고 하이퍼바이저를 직접 호출해 성능을 높인다. <br>
요즘은 CPU의 가상화 지원 기능(Intel VT-x, AMD-V) 덕분에 완전 가상화도 오버헤드가 작다.
</details>

## 서버 가상화의 종류

| 구분 | 호스트 OS형 | 하이퍼바이저형 | 컨테이너형 |
|---|---|---|---|
| 구조 | 하드웨어 → 호스트 OS → 가상화 SW → 게스트 OS | 하드웨어 → 하이퍼바이저 → 게스트 OS | 하드웨어 → 호스트 OS → 컨테이너 엔진 → 컨테이너 |
| 게스트 OS | 필요 | 필요 | 불필요 (커널 공유) |
| 오버헤드 | 큼 | 작음 | 매우 작음 |
| 기동 속도 | 느림 (분 단위) | 느림 (분 단위) | 빠름 (초 단위) |
| 격리 수준 | 높음 | 높음 | 상대적으로 낮음 |
| 주 용도 | 개인 PC의 개발·검증 | 서버·데이터 센터·클라우드 | 애플리케이션 배포·실행 |
| 대표 제품 | VirtualBox, VMware Workstation | ESXi, Hyper-V, KVM, Xen | Docker |

## 🔑 최종 정리

> 한 줄 요약: 서버 가상화는 가상화 소프트웨어가 물리 서버의 CPU·메모리·디스크·네트워크를 나누어 독립된 가상 머신으로 제공하는 기술이며, 호스트 OS 위에서 동작하는 호스트 OS형, 하드웨어 위에서 직접 동작하는 하이퍼바이저형, 커널을 공유하고 실행 환경만 격리하는 컨테이너형으로 나뉜다
