# SD-WAN

> SD-WAN (Software Defined WAN) : SDN의 개념을 WAN에 적용해 **거점 간 연결을 소프트웨어로 중앙 집중 관리**하는 기술

## SD-WAN이란

**기존 WAN의 문제**

- 본사·지사·데이터 센터를 전용선·IP-VPN으로 연결 → 비용이 높고 회선 증설에 시간이 걸림
- 거점마다 라우터를 개별 설정 → 거점이 늘수록 운용 부담 증가
- 클라우드·SaaS 이용 증가 → 모든 통신이 본사(데이터 센터)를 거쳐 인터넷으로 나가 **본사 회선이 병목**

**SD-WAN의 구조**

| 구성 요소 | 역할 |
|---|---|
| SD-WAN 컨트롤러 (오케스트레이터) | 전 거점의 설정·정책을 중앙에서 관리, 상태 감시 |
| SD-WAN 에지 장비 | 각 거점에 설치 — 컨트롤러의 정책에 따라 통신 제어 |
| 오버레이 네트워크 | 전용선·인터넷·LTE 등 여러 회선 위에 가상 WAN 구성 |

```
                 [ SD-WAN 컨트롤러 ]
                 /        |        \
        [본사 에지]   [지사 에지]   [지사 에지]
            ║            ║            ║
     ═══ IP-VPN / 인터넷 / LTE 위의 가상 WAN ═══
```

| 구분 | 기존 WAN | SD-WAN |
|---|---|---|
| 설정 | 거점별 개별 설정 | 중앙에서 일괄 설정 |
| 회선 | 전용선·IP-VPN 중심 | 여러 종류의 회선을 조합 |
| 경로 | 고정 | 애플리케이션·회선 상태에 따라 동적 선택 |
| 거점 추가 | 기술자 방문 설정 | 장비 연결만으로 자동 설정 |

## SD-WAN의 기능

| 기능 | 내용 |
|---|---|
| 중앙 집중 관리 | 관리 화면 하나로 전 거점의 설정·정책 변경, 통신 상태 가시화 |
| 제로 터치 프로비저닝 | 장비를 회선에 연결하면 컨트롤러에서 설정을 **자동으로** 내려받음 — 현지에 기술자 불필요 |
| 하이브리드 WAN | IP-VPN·인터넷·모바일 회선을 묶어 사용 — 한 회선 장애 시 자동 전환 |
| 애플리케이션 식별 | 통신이 어떤 애플리케이션의 것인지 판별 |
| 동적 경로 제어 | 애플리케이션 중요도와 회선 품질(지연·손실)에 따라 최적 회선 선택 |
| 로컬 브레이크아웃 | 특정 클라우드·SaaS 통신은 본사를 거치지 않고 **거점에서 인터넷으로 직접** 내보냄 |
| 보안 | 거점 간 통신 암호화(IPsec), 방화벽 기능 |

**로컬 브레이크아웃**

```
기존:   지사 ──▶ 본사 ──▶ 인터넷 ──▶ SaaS      (본사 회선에 집중)
SD-WAN: 지사 ──────────▶ 인터넷 ──▶ SaaS      (신뢰하는 SaaS는 직접)
        지사 ──▶ 본사 ──▶ 사내 시스템          (업무 시스템은 기존 경로)
```

<details><summary>로컬 브레이크아웃을 하면 보안상 어떤 점을 주의해야 할까?</summary>

본사의 방화벽·프록시를 거치지 않고 거점에서 바로 인터넷으로 나가므로 본사에 집중해 둔 보안 대책이 적용되지 않는다. <br>
그래서 직접 내보낼 대상을 신뢰할 수 있는 서비스로 한정하고, <br>
거점 에지 장비의 보안 기능이나 클라우드형 보안 서비스를 함께 사용해야 한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: SD-WAN은 SDN 개념을 WAN에 적용해 컨트롤러가 각 거점의 에지 장비를 중앙에서 관리하는 기술로, 제로 터치 프로비저닝으로 거점을 쉽게 추가하고 여러 회선을 묶어 애플리케이션별로 최적 경로를 선택하며 로컬 브레이크아웃으로 클라우드 통신의 본사 병목을 해소한다
