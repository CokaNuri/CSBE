# 호스트 OS형 가상화

> 호스트 OS에 **가상화 소프트웨어를 애플리케이션처럼 설치**하고, 그 위에서 여러 대의 게스트 OS를 동작시키는 방식

## 호스트 OS형 가상화란



- 평소 쓰는 OS(Windows, macOS, Linux)에 프로그램을 설치하는 것만으로 가상 환경 구축
- 게스트 OS의 하드웨어 접근은 가상화 소프트웨어 → **호스트 OS** → 하드웨어 순으로 전달

| 장점 | 단점 |
|---|---|
| 설치가 쉬움 — 기존 PC에 바로 도입 | 호스트 OS를 거치므로 **오버헤드가 큼** |
| 호스트 OS의 다른 앱과 함께 사용 | 호스트 OS가 자원을 따로 소비 |
| 호스트 OS가 지원하는 하드웨어를 그대로 활용 | 호스트 OS 장애·재부팅 시 게스트 OS 전체 중단 |
| 스냅샷으로 실험 후 원상 복구 | 대규모 서버 운용에는 부적합 |

**주 용도**

- 다른 OS에서의 동작 확인 (macOS에서 Windows·Linux 실행)
- 개발·테스트 환경 구축, 학습용 실습 환경
- 의심스러운 프로그램을 격리된 환경에서 실행

<details><summary>호스트 OS형이 하이퍼바이저형보다 느린 이유는?</summary>

게스트 OS의 입출력 요청이 가상화 소프트웨어와 호스트 OS를 모두 거쳐야 하드웨어에 도달하기 때문이다. <br>
또 호스트 OS 입장에서 가상 머신은 여러 애플리케이션 중 하나일 뿐이어서 <br>
다른 프로세스와 CPU·메모리를 경쟁하고, 호스트 OS 자체가 쓰는 자원만큼 게스트에 줄 몫이 줄어든다.
</details>

## 호스트 OS형 가상화 소프트웨어

| 소프트웨어 | 개발사 | 특징 |
|---|---|---|
| VirtualBox | Oracle | 오픈 소스, Windows·macOS·Linux 지원, 무료 |
| VMware Workstation | VMware (Broadcom) | Windows·Linux용, 기능 풍부 |
| VMware Fusion | VMware (Broadcom) | macOS용 |
| Parallels Desktop | Parallels | macOS용, Windows와의 통합 기능 |

## 🔑 최종 정리

> 한 줄 요약: 호스트 OS형 가상화는 호스트 OS에 가상화 소프트웨어를 애플리케이션으로 설치해 게스트 OS를 실행하는 방식으로, 도입이 쉬워 개인 PC의 개발·검증 용도에 적합하지만 호스트 OS를 거치는 오버헤드가 커서 서버 운용에는 맞지 않으며 VirtualBox·VMware Workstation이 대표적이다
