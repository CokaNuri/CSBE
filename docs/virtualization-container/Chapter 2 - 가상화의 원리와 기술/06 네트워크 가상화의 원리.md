# 네트워크 가상화의 원리

> 네트워크 가상화 : 물리적 배선·장비 구성과는 다른 **논리적 네트워크**를 소프트웨어로 구성하는 기술

## 네트워크 가상화란

- 물리 네트워크 : 케이블·스위치·라우터의 실제 연결 형태
- 논리 네트워크 : 통신하는 쪽에서 보이는 네트워크 구성 — 물리 구성과 달라도 됨

| 방향 | 내용 | 예 |
|---|---|---|
| 분할 | 하나의 물리 네트워크를 여러 논리 네트워크로 나눔 | VLAN |
| 통합 | 여러 물리 회선·장비를 하나처럼 묶음 | 링크 애그리게이션, 스택 |
| 덧씌움 | 물리 네트워크 위에 별도의 논리 네트워크를 얹음 | 오버레이, VPN |

**필요성**

- 서버 가상화로 가상 서버가 수 분 만에 생기고 물리 서버 사이를 이동 → 네트워크도 **같은 속도로** 바뀌어야 함
- 장비마다 수작업으로 설정하면 느리고 실수가 잦음 → 소프트웨어로 제어·자동화
- 클라우드에서는 수많은 이용자의 네트워크를 서로 **격리**해야 함

| 장점 | 단점 |
|---|---|
| 배선 변경 없이 구성 변경 | 물리·논리 두 계층을 함께 이해해야 함 |
| 이용자·부서별 네트워크 분리 | 장애 원인 추적이 어려움 |
| 중앙 관리·자동화 | 캡슐화 등으로 인한 오버헤드 |
| 장비 수·비용 절감 | 컨트롤러 등 제어부가 단일 장애 지점이 될 수 있음 |

## 네트워크 가상화의 기술

| 기술 | 가상화 대상 | 핵심 |
|---|---|---|
| VLAN | LAN (L2) | 스위치 포트·태그로 LAN을 논리적으로 분할 |
| 오버레이 네트워크 | L2/L3 | 터널링으로 물리 네트워크 위에 가상 네트워크 구성 (VXLAN) |
| VPN | WAN | 공용 회선 위에 암호화된 가상 전용선 |
| SDN | 네트워크 제어 | 제어 기능을 분리해 소프트웨어로 중앙 제어 |
| NFV | 네트워크 기기 | 라우터·방화벽 기능을 범용 서버의 소프트웨어로 구현 |
| SD-WAN | 거점 간 WAN | SDN 개념을 WAN에 적용해 중앙 관리 |

**서버 내부의 가상 네트워크**

| 요소 | 내용 |
|---|---|
| 가상 NIC | 가상 서버에 달린 소프트웨어 NIC — 고유한 MAC 주소를 가짐 |
| 가상 스위치 | 하이퍼바이저 안에서 가상 NIC들을 연결하는 소프트웨어 스위치 |
| 물리 NIC (업링크) | 가상 스위치를 외부 물리 네트워크와 연결 |

<details><summary>같은 물리 서버에 있는 두 가상 서버가 통신할 때 패킷은 물리 스위치를 거칠까?</summary>

같은 가상 스위치·같은 네트워크에 연결되어 있다면 거치지 않는다. <br>
하이퍼바이저 안의 가상 스위치가 메모리상에서 프레임을 전달하므로 물리 NIC 밖으로 나가지 않는다. <br>
그래서 물리 스위치에서의 감시·필터링이 적용되지 않을 수 있다는 점에 주의해야 한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 네트워크 가상화는 물리 구성과 다른 논리 네트워크를 소프트웨어로 구성하는 기술로, 가상 서버의 빠른 생성·이동과 이용자 간 격리 요구에 대응하기 위해 필요하며 VLAN·오버레이·VPN·SDN·NFV·SD-WAN과 서버 내부의 가상 NIC·가상 스위치가 이를 구현한다
