# 하이퍼바이저형 가상화

> 하드웨어 위에 **하이퍼바이저를 직접 설치**하고 그 위에서 게스트 OS를 동작시키는 방식 — 호스트 OS가 필요 없다

## 하이퍼바이저형 가상화란



- 하이퍼바이저가 하드웨어를 직접 제어 → 호스트 OS를 거치지 않아 **오버헤드가 작음**
- 하드웨어에 바로 올라간다는 뜻에서 **베어메탈형**이라고도 함

| 장점 | 단점 |
|---|---|
| 호스트 OS가 없어 성능이 좋고 자원 낭비가 적음 | 전용 물리 서버 필요 — 기존 PC에 간단히 설치 불가 |
| 가상 서버 간 격리 수준이 높음 | 하이퍼바이저가 지원하는 하드웨어만 사용 가능 |
| 라이브 마이그레이션·HA 등 운용 기능 풍부 | 도입·운용에 전문 지식 필요 |
| 여러 물리 서버를 통합 관리 | 가상 서버마다 게스트 OS가 필요해 컨테이너보다 무거움 |

**하이퍼바이저의 분류**

| 분류 | 내용 | 대응 |
|---|---|---|
| Type 1 (네이티브) | 하드웨어에서 직접 실행 | 하이퍼바이저형 |
| Type 2 (호스트) | 호스트 OS 위에서 실행 | 호스트 OS형 |

**가상화 방식**

| 방식 | 내용 |
|---|---|
| 완전 가상화 | 하드웨어를 완전히 흉내 냄 → 게스트 OS 수정 불필요 |
| 준가상화 | 게스트 OS를 수정해 하이퍼바이저를 직접 호출 → 빠르지만 OS 대응 필요 |
| 하드웨어 지원 가상화 | CPU의 가상화 기능(Intel VT-x, AMD-V)을 이용해 완전 가상화의 오버헤드를 줄임 |

## 하이퍼바이저형 가상화 소프트웨어

| 소프트웨어 | 개발사 | 특징 |
|---|---|---|
| VMware ESXi (vSphere) | VMware (Broadcom) | 기업 환경에서 널리 쓰임, vCenter로 통합 관리 |
| Hyper-V | Microsoft | Windows Server에 포함, Azure의 기반 |
| KVM | 오픈 소스 | **리눅스 커널**에 통합 — 리눅스 자체를 하이퍼바이저로 사용, 클라우드에서 널리 채택 |
| Xen | 오픈 소스 | 준가상화로 유명, 초기 AWS의 기반 |

<details><summary>KVM은 리눅스 위에서 돌아가는데 왜 하이퍼바이저형으로 분류할까?</summary>

KVM은 리눅스에 설치하는 애플리케이션이 아니라 리눅스 커널에 포함된 모듈이다. <br>
모듈을 올리면 리눅스 커널 자체가 하이퍼바이저로 동작해 CPU의 가상화 지원 기능을 직접 사용하므로, <br>
호스트 OS를 한 번 더 거치는 호스트 OS형과 달리 하이퍼바이저형(Type 1)으로 본다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 하이퍼바이저형 가상화는 하드웨어에 하이퍼바이저를 직접 설치해 호스트 OS 없이 게스트 OS를 실행하는 방식으로, 오버헤드가 작고 격리·운용 기능이 뛰어나 서버·클라우드 환경의 표준이며 ESXi·Hyper-V·KVM·Xen이 대표적이다
