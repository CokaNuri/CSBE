# VPN

> VPN (Virtual Private Network) : 인터넷 같은 공용 회선 위에 **가상의 전용선**을 구축해 안전하게 통신하는 기술

## VPN이란

- 전용선 : 거점 간을 물리적으로 독점 연결 — 안전하고 품질이 좋지만 **비쌈**
- VPN : 공용 회선을 쓰면서 전용선처럼 안전한 통신 → 저렴

| 종류 | 사용 회선 | 특징 |
|---|---|---|
| 인터넷 VPN | 인터넷 | 가장 저렴, 품질·속도는 인터넷 상황에 좌우 |
| IP-VPN | 통신사의 폐쇄망 | 인터넷과 분리되어 안전·안정적, 비용 높음 |
| 광역 이더넷 | 통신사의 폐쇄망 (L2) | 거점을 하나의 LAN처럼 연결, 설계 자유도 높음 |

| 접속 형태 | 내용 | 예 |
|---|---|---|
| 사이트 간 VPN | 거점의 **라우터끼리** 연결 — 단말은 VPN을 의식하지 않음 | 본사 ↔ 지사, 온프레미스 ↔ 클라우드 |
| 원격 접속 VPN | 개별 **단말**이 VPN 장비에 접속 | 재택근무, 외부에서 사내망 접속 |

---

## VPN의 원리

> 터널링 + 캡슐화 + 암호화 + 인증으로 공용 회선에서 안전한 통로를 만듦

| 기술 | 역할 |
|---|---|
| 터널링 | 두 지점 사이에 가상의 통로를 만듦 |
| 캡슐화 | 원래 패킷을 다른 패킷에 감싸 터널로 전송 |
| 암호화 | 도청당해도 내용을 알 수 없게 함 (기밀성) |
| 인증 | 접속 상대가 정당한지 확인, 데이터 변조 여부 검증 (무결성) |

```
[사내 PC] ─ [VPN 장비] ══════ 인터넷 (암호화된 터널) ══════ [VPN 장비] ─ [사내 서버]
```

**주요 프로토콜**

| 프로토콜 | 계층 | 특징 |
|---|---|---|
| IPsec | L3 | IP 패킷을 암호화 — 사이트 간 VPN의 표준 |
| SSL/TLS VPN | L4~L7 | 웹 브라우저·전용 클라이언트로 접속 — 원격 접속에 많이 쓰임 |
| L2TP/IPsec | L2 + L3 | L2TP로 터널, IPsec으로 암호화 |
| WireGuard | L3 | 구조가 단순하고 빠른 최신 프로토콜 |

**IPsec의 구성**

| 요소 | 내용 |
|---|---|
| IKE | 암호 키를 안전하게 교환하고 접속 조건을 협상 |
| ESP | 패킷 암호화 + 인증 |
| AH | 인증만 수행 (암호화 없음) |
| 터널 모드 | 원래 IP 패킷 **전체**를 암호화하고 새 IP 헤더를 붙임 — 사이트 간 VPN |
| 트랜스포트 모드 | 데이터 부분만 암호화 — 단말 간 통신 |

<details><summary>VPN을 쓰면 통신이 느려지는 이유는?</summary>

패킷마다 암호화·복호화 연산이 들어가고, 캡슐화로 헤더가 추가되어 한 번에 보낼 수 있는 데이터 양이 줄어든다. <br>
또 모든 통신이 VPN 장비를 거치므로 그 장비의 처리 능력과 회선이 병목이 된다. <br>
재택근무자가 몰리면 VPN 장비에 부하가 집중되어 느려지는 것이 이 때문이다.
</details>

## 🔑 최종 정리

> 한 줄 요약: VPN은 공용 회선 위에 터널링·캡슐화·암호화·인증으로 가상의 전용선을 만드는 기술로, 회선에 따라 인터넷 VPN과 IP-VPN, 접속 형태에 따라 사이트 간 VPN과 원격 접속 VPN으로 나뉘며 IPsec과 SSL/TLS VPN이 대표 프로토콜이다
