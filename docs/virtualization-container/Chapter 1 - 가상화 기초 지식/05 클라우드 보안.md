# 클라우드 보안

> 클라우드는 안전성이 높지만, 리스크도 존재한다.

## 클라우드 보안

- 최신 보안 대책으로 적절하게 관리
- 그러나, 클라우드를 통째로 도용하면 호스트 컴퓨터까지 침입할 가능성 존재
---

## 실제로 발생한 취약성의 예

> VENOM (Virtualized Environment Neglected Operations Manipulation) : 2015년 5월 13일 미국 보안 기업 CrowdStrike가 공표한 취약점

- 클라우드 서비스 **전체가 탈취**될 수 있는 매우 위험한 취약점
- 하이퍼바이저형 가상화와 관련한 취약점

**공격 흐름**

1. 공격자가 공격 대상 클라우드 서비스에 일반 사용자로 가입
2. 가상 서버의 관리자로 로그인
3. 가상 플로피 디스크 드라이브의 취약점 공격 (**버퍼 오버플로**)
4. 게스트 OS뿐만 아니라 게스트 OS를 탑재한 **호스트 OS**까지 공격 범위 확대

- 결과 : 같은 클라우드를 쓰는 모든 사용자에게 피해를 줄 가능성

---

## 편의성과 보안 문제의 절충

- 온라인 스토리지는 이용 중인 모든 단말이 악성 코드에 감염되기 쉬움 → 편리성과 맞붙어 있는 **양날의 검**
- 클라우드 서비스 제공 업체 : 높은 보안 대책 기술을 보유하고 취약점을 항상 숙지해야 함
- 클라우드 서비스 이용 기업 : 사내에 보안 관리자를 두고, 클라우드 장애에 대처할 수 있는 인재 육성
- 가상화의 편의성 때문에 피해가 심각해질 수 있으므로 최신 취약 정보를 살펴봐야 함

---

## 🔑 최종 정리

> 한 줄 요약: 클라우드는 사업자의 전문적인 보안으로 안전성이 높지만 책임 공유 모델에 따라 OS·데이터·권한 설정은 이용자 책임이며, VM·컨테이너 탈출이나 CPU 취약점처럼 격리가 깨지는 위험과 설정 실수로 인한 유출이 클라우드 특유의 리스크이므로, 최소 권한·MFA·암호화·감시로 편의성과 보안의 균형을 잡아야 한다
