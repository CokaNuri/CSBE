# 가상화의 장단점

> 효율·운용성 관점에서 물리 환경과 비교 — 자원을 **모아서 효율적으로** 쓰는 대신 **오버헤드와 복잡성**이 생긴다

## 가상화의 장점

| 장점 | 내용 |
|---|---|
| 자원 효율 향상 | 서버마다 남는 CPU·메모리를 모아 사용 → 물리 서버의 이용률 상승 |
| 비용 절감 | 물리 서버 대수 감소 → 장비비·전력·냉각·설치 공간 절감 (**서버 통합**) |
| 신속한 구축 | 장비 조달 없이 가상 서버를 수 분 만에 생성, 템플릿으로 복제 |
| 유연한 확장 | 부하에 맞춰 사양·대수를 조정 |
| 가용성 향상 | 라이브 마이그레이션, 자동 재시작, 스냅샷 |
| 운용 효율 | 관리 도구로 여러 가상 서버를 한곳에서 관리, 자동화 용이 |
| 구형 환경 유지 | 오래된 OS·시스템을 새 하드웨어 위에서 계속 실행 |

- 물리 환경에서는 서버마다 **최대 부하**에 맞춰 사양을 잡음 → 평소에는 대부분의 자원이 놀게 됨
- 가상화하면 여러 서버의 여유 자원을 공유 → 같은 장비로 더 많은 일을 처리

---

## 가상화의 단점

| 단점 | 내용 |
|---|---|
| 성능 오버헤드 | 가상화 계층을 거치므로 물리 환경보다 처리 성능이 떨어질 수 있음 |
| 자원 경합 | 같은 물리 서버의 가상 서버끼리 CPU·디스크·네트워크를 다툼 (**시끄러운 이웃**) |
| 장애 영향 범위 확대 | 물리 서버 한 대가 고장 나면 그 위의 가상 서버가 **모두** 멈춤 |
| 운용 복잡성 | 물리 계층 + 가상 계층을 모두 관리, 장애 원인 추적이 어려움 |
| 전문 지식 필요 | 가상화 소프트웨어·네트워크·스토리지 설계 지식 요구 |
| 라이선스 비용 | 가상화 소프트웨어, 가상 환경용 OS·미들웨어 라이선스 |
| 보안 | 가상화 소프트웨어 자체의 취약점이 모든 가상 서버에 영향 |

<details><summary>가상 서버를 너무 쉽게 만들 수 있다는 것이 왜 문제가 될 수 있을까?</summary>

필요할 때마다 만들고 지우지 않아 관리되지 않는 가상 서버가 계속 늘어나는 현상(VM 스프롤)이 생긴다. <br>
쓰이지 않는 서버가 자원과 라이선스를 차지하고, 패치되지 않은 채 방치되어 보안 구멍이 된다. <br>
생성·폐기 절차와 자원 현황 관리가 함께 필요하다.
</details>

## 물리 환경과 비교

| 관점 | 물리 환경 | 가상 환경 |
|---|---|---|
| 자원 이용률 | 낮음 (서버별 여유 자원 낭비) | 높음 (자원 공유) |
| 성능 | 하드웨어 성능을 그대로 사용 | 오버헤드·경합 가능 |
| 구축 속도 | 느림 | 빠름 |
| 장애 영향 | 해당 서버만 | 물리 서버 위 가상 서버 전체 |
| 복구 | 장비 수리·교체 | 다른 물리 서버에서 재기동 |
| 운용 | 단순하지만 대수가 많음 | 계층이 늘어 복잡하지만 중앙 관리 |

- 높은 성능이 꼭 필요한 DB·특수 하드웨어를 쓰는 시스템은 물리 환경(베어메탈)을 선택하기도 함

## 🔑 최종 정리

> 한 줄 요약: 가상화는 서버 통합으로 자원 이용률을 높이고 비용을 줄이며 구축·확장·복구를 빠르게 하지만, 가상화 계층의 오버헤드와 자원 경합, 물리 서버 장애 시 영향 범위 확대, 운용 복잡성이라는 단점이 있어 시스템 특성에 맞게 선택해야 한다
