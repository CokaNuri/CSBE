# 입출력 시스템

> 입출력 시스템 : 속도가 제각각인 주변장치들과 CPU·메모리 사이의 데이터 이동을 효율적으로 처리하는 구조

## 입출력장치와 채널

- 주변장치는 **데이터 전송 속도**에 따라 나뉨

| 구분 | 전송 단위 | 예 |
|---|---|---|
| 저속 주변장치 | 문자(character) 단위 | 키보드, 마우스 |
| 고속 주변장치 | 블록(block) 단위 | 하드디스크, 그래픽카드 |

- **채널(channel)** : 입출력 전용 통로. 속도가 비슷한 장치끼리 묶어 같은 채널에 배정
- 채널을 나누면 느린 장치가 빠른 장치의 전송을 방해하지 않음

---

## 입출력 버스의 구조

**발전 과정**

| 단계 | 구조 | 문제/개선 |
|---|---|---|
| 초기 | CPU가 **폴링(polling)** 으로 장치 상태를 주기적 확인 | CPU 낭비 심함 |
| 발전 | **입출력 제어기**와 입출력 버스 도입, 인터럽트 방식 전환 | CPU는 작업 지시만 하고 결과는 인터럽트로 통보받음 |
| 현대 | 버스를 **메인 버스 / 입출력 버스**로 분리, 다시 고속(그래픽)·저속 버스로 세분화 | 느린 장치가 빠른 버스를 점유하는 문제 해결 |

- 메인 버스 : CPU ↔ 메모리 (가장 빠름)
- 입출력 버스 : 주변장치 ↔ 입출력 제어기

---

## 직접 메모리 접근

> DMA(Direct Memory Access) : CPU를 거치지 않고 입출력장치가 메모리에 직접 읽고 쓰는 방식

- 원래 메모리 접근 권한은 CPU에만 있음 → 모든 전송에 CPU가 끼면 낭비
- **DMA 제어기**에 메모리 접근 권한을 부여 → 대량 데이터 전송을 CPU 없이 수행
- 전송이 끝나면 인터럽트로 CPU에 완료 통보
- CPU용 메모리 공간과 DMA용 공간을 구분해 관리하는 것 = **메모리 매핑 입출력(memory-mapped I/O)**

<details><summary>DMA가 없으면 어떤 문제가 생기는가?</summary>

디스크에서 1GB를 읽을 때 모든 바이트가 CPU를 거쳐 메모리로 가야 한다. <br>
CPU가 단순 데이터 운반에 묶여 정작 연산을 못 하게 되므로, <br>
대량 전송은 DMA 제어기에 맡기고 CPU는 완료 인터럽트만 받는다.
</details>

## 인터럽트

> 인터럽트 : 입출력 완료 등 사건 발생을 CPU에 알리는 신호 — 폴링의 CPU 낭비를 해결

**처리 흐름**

1. CPU가 입출력 제어기에 작업 지시 후 다른 일 수행
2. 장치가 작업 완료 → **인터럽트 발생** (장치마다 고유한 **인터럽트 번호**)
3. CPU는 **인터럽트 벡터**에서 번호에 해당하는 처리 루틴을 찾음
4. **인터럽트 핸들러(ISR)** 실행 → 원래 작업 복귀

| 용어 | 내용 |
|---|---|
| 인터럽트 번호 | 어떤 장치의 인터럽트인지 구분하는 번호 |
| 인터럽트 벡터 | 인터럽트 번호 → 처리 함수 위치를 담은 표 |
| 인터럽트 핸들러 | 해당 인터럽트를 실제로 처리하는 함수(ISR) |

## 단일 버퍼와 이중 버퍼

> 버퍼 : 속도가 다른 두 장치 사이의 데이터를 모아 한꺼번에 전송하는 임시 저장 공간

| 방식 | 동작 | 한계/장점 |
|---|---|---|
| 단일 버퍼 | 버퍼 하나를 채우고 → 비우고 반복 | 채우는 동안 소비자는 대기 (번갈아 멈춤) |
| 이중 버퍼 | 버퍼 두 개 — 하나는 **채우고** 동시에 다른 하나는 **비움** | 생산·소비가 동시에 진행, 효율 상승 |

- 영상 렌더링의 더블 버퍼링과 같은 원리 (한 화면 표시 중 다음 화면 준비)

---

## 🔑 최종 정리

> 한 줄 요약: 입출력 시스템은 저속(문자)·고속(블록) 장치를 채널과 분리된 버스로 묶고, 폴링 대신 인터럽트(번호→벡터→핸들러)로 완료를 통보받으며, 대량 전송은 DMA가 CPU 없이 메모리에 직접 수행하고, 속도 차이는 버퍼(단일→이중)로 완화한다
