# 저장장치

> 저장장치 : 전원이 꺼져도 데이터를 보관하는 장치 — 구조를 알아야 디스크 스케줄링·파일 시스템이 이해된다

## 저장장치의 종류

**자기 디스크 계열 (하드디스크)**

| 구성 요소 | 내용 |
|---|---|
| 플래터 (platter) | 데이터가 기록되는 원판 — 여러 장이 겹쳐 있음 |
| 트랙 (track) | 플래터 위의 동심원 |
| 섹터 (sector) | 트랙을 나눈 조각 — **최소 저장(전송) 단위** |
| 실린더 (cylinder) | 여러 플래터에서 같은 위치의 트랙 묶음 |
| 헤드 (head) | 데이터를 읽고 쓰는 부품 — 모든 헤드는 함께 움직임 |

**디스크 회전 방식**

| 방식 | 내용 | 예 |
|---|---|---|
| CAV (각속도 일정) | 회전 속도 일정 — 바깥 트랙일수록 데이터 밀도 낮음(낭비) | 하드디스크 |
| CLV (선속도 일정) | 트랙 위치에 따라 회전 속도 조절 — 밀도 일정 | CD/DVD |

**기타 저장장치**

| 장치 | 특징 |
|---|---|
| SSD | 플래시 메모리 기반 — 기계 부품 없음 → 빠르고 조용, 충격에 강함, 쓰기 횟수 제한 |
| 광디스크 (CD/DVD/블루레이) | 레이저로 읽음, 저장 밀도 차이로 용량 구분 |
| 자기 테이프 | 순차 접근만 가능 — 백업·아카이브용 |

---

## 디스크 장치의 데이터 전송 시간

> 디스크 접근 시간 = 탐색 시간 + 회전 지연 시간 + 전송 시간

| 구성 | 내용 | 비중 |
|---|---|---|
| 탐색 시간 (seek time) | 헤드를 목표 **트랙(실린더)** 까지 이동하는 시간 | **가장 큼** |
| 회전 지연 시간 (rotational latency) | 목표 **섹터**가 헤드 아래로 회전해 올 때까지 기다리는 시간 | 중간 |
| 전송 시간 (transfer time) | 실제로 데이터를 읽어 전송하는 시간 | 작음 |

- 성능 개선의 핵심 = **탐색 시간 최소화** → 디스크 스케줄링 알고리즘의 목표
- SSD는 헤드·회전이 없으므로 탐색 시간·회전 지연이 **0** → 임의 접근이 빠른 이유

<details><summary>디스크 스케줄링이 탐색 시간에 집중하는 이유는?</summary>

세 구성 요소 중 헤드의 물리적 이동(탐색 시간)이 가장 느리기 때문이다. <br>
헤드 이동 거리를 줄이도록 요청 순서를 재배열하면 <br>
전체 접근 시간이 가장 크게 줄어든다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 하드디스크는 플래터·트랙·섹터·실린더·헤드로 구성되고 접근 시간은 탐색+회전 지연+전송 시간의 합인데 탐색 시간이 가장 커서 디스크 스케줄링의 대상이 되며, SSD는 기계 부품이 없어 탐색·회전 지연 없이 빠르다
