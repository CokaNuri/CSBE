# 교착 상태의 개요

> 교착 상태 : 둘 이상의 프로세스가 서로 상대가 가진 자원을 기다리며 무한히 멈춘 상태

## 교착 상태의 정의

> 두 개 이상의 프로세스가 서로 점유한 자원을 기다리느라 어느 것도 진행하지 못하는 상황

- 각 프로세스는 자원을 쥔 채 상대가 쥔 자원을 기다림 → 아무도 양보하지 않아 영원히 멈춤
- **일상 비유** : 좁은 다리 위에서 마주 온 두 차가 서로 물러서지 않아 둘 다 못 가는 상황

**교착 상태와 아사(기아)의 차이**

| 구분 | 교착 상태 | 아사(starvation) |
|---|---|---|
| 원인 | 프로세스들이 서로의 자원을 물고 물려 대기 | 우선순위에 계속 밀림 |
| 대상 | 여러 프로세스가 함께 묶임 | 특정 프로세스만 못 받음 |
| 해결 | 자원 할당 정책 자체를 바꿔야 함 | 에이징 등으로 완화 가능 |

---

## 자원 할당 그래프

> 프로세스와 자원의 할당·요청 관계를 그림으로 나타내 교착 상태를 파악하는 도구

**표기법**

| 기호 | 의미 |
|---|---|
| 원 (○) | 프로세스 |
| 사각형 (□) | 자원 (안의 점은 자원의 개수) |
| 자원 → 프로세스 | 자원이 프로세스에 **할당**됨 |
| 프로세스 → 자원 | 프로세스가 자원을 **요청**(대기)함 |

- 그래프에 **사이클(순환)** 이 생기면 교착 상태를 의심
- 자원이 하나씩만 있을 때 : **사이클 = 교착 상태**
- 자원이 여러 개일 때 : 사이클이 있어도 교착 상태가 아닐 수 있음 (여분 자원으로 풀릴 수 있음)

<details><summary>사이클이 있어도 교착 상태가 아닐 수 있는 이유는?</summary>

자원의 개수가 여러 개면, 사이클에 묶이지 않은 다른 프로세스가 <br>
자원을 반납할 때 대기 중인 프로세스가 그 여분을 받아 진행할 수 있기 때문이다. <br>
따라서 사이클은 교착 상태의 필요조건일 뿐 충분조건은 아니다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 교착 상태는 여러 프로세스가 서로 점유한 자원을 물고 물려 기다리며 무한히 멈춘 상황으로, 자원 할당 그래프의 사이클로 파악하지만 자원이 여러 개면 사이클이 있어도 교착 상태가 아닐 수 있다
