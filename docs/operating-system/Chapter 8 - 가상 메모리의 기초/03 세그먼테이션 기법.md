# 세그먼테이션 기법

> 세그먼테이션 : 프로세스를 의미 단위의 덩어리(세그먼트)로 나눠 매핑하는 가변 분할 방식의 가상 메모리 기법

## 세그먼테이션 기법의 구현

- 프로세스를 **크기가 제각각인 세그먼트** 단위로 나눔 (코드, 데이터, 스택처럼 의미 있는 단위)
- 매핑 정보는 **세그먼테이션 테이블**에 기록

| 테이블 항목 | 내용 |
|---|---|
| base address | 세그먼트가 물리 메모리에서 시작하는 주소 |
| limit | 세그먼트의 크기 (침범 검사용) |

- 가변 분할 방식이므로 물리 메모리에 **외부 단편화** 발생 가능
- 세그먼트가 스왑 영역에 있으면 테이블에 `invalid` 표시

---

## 세그먼테이션 기법의 주소 변환

> 가상 주소 VA = <S, D> (S: 세그먼트 번호, D: 세그먼트 안에서의 거리)

**변환 절차** (세그먼트 0, 거리 32라면)

1. 세그먼테이션 테이블에서 세그먼트 0의 base address와 limit 조회
2. **D > limit 이면 트랩(trap) 발생** — 메모리 침범 차단, 프로세스 강제 종료
3. 통과하면 물리 주소 = base address + D

| 용어 | 내용 |
|---|---|
| 트랩 | 프로그램 내부에서 발생한 예외 상황을 알리는 인터럽트 (limit 초과 = 메모리 침범) |

**페이징과 비교**

| 구분 | 페이징 | 세그먼테이션 |
|---|---|---|
| 분할 기준 | 같은 크기 (고정 분할) | 의미 단위, 크기 가변 (가변 분할) |
| 단편화 | 내부 단편화 | 외부 단편화 |
| 관리 | 단순 (페이지 번호→프레임 번호) | base + limit 관리, 침범 검사 명확 |
| 보호·공유 | 페이지 단위라 어색함 | 의미 단위라 자연스러움 |

<details><summary>limit 검사가 세그먼테이션에서 특히 중요한 이유는?</summary>

세그먼트 크기가 제각각이라 거리 D가 세그먼트 범위를 벗어나면 <br>
곧바로 다른 프로세스의 영역을 침범하게 되기 때문이다. <br>
그래서 변환 전에 반드시 limit과 비교하고, 초과하면 트랩을 걸어 프로세스를 종료한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 세그먼테이션은 프로세스를 의미 단위의 가변 크기 세그먼트로 나눠 base address와 limit으로 관리하는 기법으로, 주소 변환은 base+D이고 D가 limit을 넘으면 트랩으로 침범을 막으며, 보호·공유에 유리하지만 외부 단편화가 생긴다
