# 캐시 매핑 기법

> 캐시 매핑 : 큰 메모리의 데이터를 작은 캐시의 어느 자리에 둘지 정하는 규칙 — 직접·연관·집합-연관 세 가지

## 캐시 매핑의 전제

- 캐시는 메모리보다 훨씬 작음 → 메모리의 여러 블록이 캐시 한 자리를 나눠 써야 함
- 메모리 주소를 보고 "캐시의 어느 자리에 있을까"를 빠르게 찾는 규칙이 매핑 기법
- 캐시에 있으면 **캐시 히트**, 없으면 **캐시 미스** (메모리에서 가져옴)

---

## 캐시 직접 매핑

> 메모리 블록마다 들어갈 수 있는 캐시 자리가 딱 하나로 정해진 방식

- 캐시 자리 = 메모리 블록 번호 % 캐시 블록 수
- 메모리 주소를 **태그(tag) + 캐시 위치(index) + offset**으로 나눔
- 같은 자리를 쓰는 블록들은 **태그**로 구분

| 장점 | 단점 |
|---|---|
| 구현 간단, 검색 빠름 (한 자리만 확인) | 같은 자리를 두 블록이 번갈아 쓰면 계속 미스 발생 (충돌) |

---

## 캐시 연관 매핑

> 메모리 블록이 캐시의 아무 자리에나 들어갈 수 있는 방식

- 자리 제약이 없어 캐시 공간을 **최대로 활용**
- 대신 데이터를 찾으려면 **캐시 전체를 검색**해야 함 (모든 태그 비교)

| 장점 | 단점 |
|---|---|
| 충돌 없음, 공간 활용 최고 | 전체 검색 비용 — 하드웨어가 복잡하고 비쌈 |

---

## 캐시 집합-연관 매핑

> 직접 매핑 + 연관 매핑의 절충 — 캐시를 몇 개의 집합으로 나누고, 집합 안에서는 자유롭게 배치

- 메모리 블록은 정해진 **집합(set)** 에만 들어감 (직접 매핑 성질)
- 집합 안의 여러 자리 중에는 아무 데나 들어감 (연관 매핑 성질)
- 집합 하나에 자리가 K개면 **K-way 집합-연관 매핑**

| 기법 | 자리 결정 | 검색 범위 | 특징 |
|---|---|---|---|
| 직접 매핑 | 딱 1곳 | 1곳 | 빠르지만 충돌 잦음 |
| 연관 매핑 | 아무 곳 | 전체 | 유연하지만 느리고 비쌈 |
| 집합-연관 매핑 | 정해진 집합 안 아무 곳 | 집합 내부만 | 둘의 절충 — 실제 CPU가 사용 |

<details><summary>실제 CPU가 집합-연관 매핑을 쓰는 이유는?</summary>

직접 매핑의 충돌 문제와 연관 매핑의 검색 비용을 동시에 줄일 수 있기 때문이다. <br>
집합으로 범위를 좁혀 검색은 빠르게 하고, 집합 안에 자리를 여러 개 둬서 <br>
같은 자리를 다투는 충돌 미스를 완화한다.
</details>

---

## 🔑 최종 정리

> 한 줄 요약: 캐시 매핑은 메모리 블록을 캐시 어디에 둘지 정하는 규칙으로, 직접 매핑은 자리가 하나(빠름·충돌), 연관 매핑은 아무 자리(유연·전체 검색), 집합-연관 매핑은 집합 안에서 자유(절충)이며 실제 CPU는 집합-연관을 쓴다
