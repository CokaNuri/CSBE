# 가상 메모리의 개요

> 가상 메모리 : 물리 메모리 크기와 상관없이, 프로세스에게 무한에 가까운 메모리 공간을 제공하는 기술

## 가상 메모리 시스템

- 물리 메모리는 유한하지만, 프로세스는 메모리 크기를 신경 쓰지 않고 실행되고 싶어 함
- 가상 메모리는 **실제 물리 메모리 + 스왑 영역**을 합쳐 하나의 큰 메모리처럼 보이게 함
- 프로세스는 **가상 주소(논리 주소)** 만 사용하고, 실제 위치는 메모리 관리자가 알아서 처리

| 구분 | 내용 |
|---|---|
| 가상 주소 공간 | 프로세스 입장에서 보이는 메모리 (0번지부터 시작, 크기 제한 없음) |
| 물리 주소 공간 | 실제 메모리(RAM)의 주소 |
| 가상 메모리의 크기 | 이론상 CPU의 비트 수로 결정 (32bit → 2³² = 4GB) |
| 부족한 공간 | 스왑 영역으로 보충 (저장장치의 일부를 메모리처럼 사용) |

- 가상 메모리에서도 메모리 분할 방식을 사용
    - **가변 분할 방식 → 세그먼테이션**
    - **고정 분할 방식 → 페이징**

<details><summary>가상 메모리가 물리 메모리보다 커질 수 있는 이유는?</summary>

메모리가 부족하면 당장 사용하지 않는 영역을 스왑 영역으로 옮기기 때문이다. <br>
프로세스 입장에서는 (물리 메모리 + 스왑 영역) 전체가 하나의 메모리처럼 보인다.
</details>

## 매핑 테이블의 필요성과 역할

> 매핑 테이블 : 가상 주소가 물리 메모리의 어디에 있는지 기록한 변환 표

- 프로세스가 사용하는 가상 주소를 실제 물리 주소로 바꾸는 작업 = **동적 주소 변환(DAT)**
- 변환 정보를 담은 표가 **매핑 테이블** — 메모리 관리자가 관리

| 기법 | 테이블 이름 |
|---|---|
| 페이징 | 페이지 매핑 테이블 (페이지 테이블) |
| 세그먼테이션 | 세그먼테이션 매핑 테이블 (세그먼테이션 테이블) |

- 매핑 테이블 덕분에 프로세스는 물리 메모리 구조를 몰라도 됨 (연속된 메모리처럼 사용)
- 데이터가 스왑 영역에 있는지 여부도 매핑 테이블로 확인

## 지역성

> 지역성(locality) : 기억장치 접근이 한곳에 몰리는 경향 — 캐시와 페이지 교체 알고리즘의 이론적 근거

| 종류 | 내용 | 예 |
|---|---|---|
| 공간의 지역성 | 현재 위치와 **가까운 데이터**에 접근할 확률이 높음 | 배열 순회 |
| 시간의 지역성 | **방금 접근한 데이터**에 다시 접근할 확률이 높음 | 반복문의 변수 |
| 순차적 지역성 | 명령어가 **순서대로** 실행되는 경향 | 분기 없는 코드 실행 |

- 캐시 : 지역성이 높은 데이터를 미리 가져오면 히트율 상승
- 페이지 교체 : 앞으로 쓸 확률이 낮은(지역성에서 먼) 페이지를 내보내면 성능 유리

<details><summary>지역성이 가상 메모리에서 중요한 이유는?</summary>

메모리 전체를 올리지 않고 일부만 올려도 실행이 잘 되는 근거이기 때문이다. <br>
프로세스는 어차피 한동안 특정 영역만 집중적으로 쓰므로(지역성), <br>
그 부분만 메모리에 두고 나머지는 스왑 영역에 둬도 성능 손해가 적다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 가상 메모리는 물리 메모리와 스왑 영역을 합쳐 프로세스에게 큰 가상 주소 공간을 제공하는 기술로, 가상 주소→물리 주소 변환은 매핑 테이블이 담당하며, 일부만 메모리에 올려도 잘 동작하는 근거는 지역성이다
