# 페이징 기법

> 페이징 : 가상 주소 공간과 물리 메모리를 같은 크기의 조각(페이지/프레임)으로 나눠 매핑하는 고정 분할 방식의 가상 메모리 기법

## 페이징 기법의 구현

| 용어 | 내용 |
|---|---|
| 페이지 (page) | 가상 주소 공간을 일정한 크기로 나눈 조각 (0번부터 번호) |
| 프레임 (frame) | 물리 메모리를 같은 크기로 나눈 조각 |
| 페이지 테이블 | 어떤 페이지가 어떤 프레임에 있는지 기록한 매핑 테이블 |

- **페이지 크기 = 프레임 크기** → 어떤 페이지든 어떤 프레임에나 들어갈 수 있음
- 페이지가 물리 메모리에 없으면 테이블에 `invalid` 표시 (스왑 영역에 있다는 뜻)
- 프로세스마다 페이지 테이블이 하나씩 존재

---

## 페이징 기법의 주소 변환

> 가상 주소 VA = <P, D> → 물리 주소 PA = <F, D>

| 기호 | 의미 |
|---|---|
| P | 페이지 번호 |
| F | 프레임 번호 |
| D | 페이지(프레임) 안에서의 거리(offset) — 변환 전후 동일 |

**변환 절차** (페이지 크기 = 10B, 가상 주소 32번지라면)

1. 페이지 번호 P = 32 / 10 = **3** (몫)
2. 거리 D = 32 % 10 = **2** (나머지)
3. 페이지 테이블에서 페이지 3의 프레임 번호 F 조회 (예: F = 1)
4. 물리 주소 = 프레임 1의 시작 주소 + 2

- 실제 컴퓨터는 페이지 크기가 2의 거듭제곱(예: 4KB)이라 나눗셈 없이 **비트 분리**로 처리

<details><summary>페이지 크기를 2의 거듭제곱으로 하는 이유는?</summary>

주소를 비트 단위로 자르기만 하면 페이지 번호와 offset이 바로 나오기 때문이다. <br>
예: 4KB(2¹²) 페이지라면 하위 12bit가 D, 나머지 상위 bit가 P — 나눗셈 연산이 필요 없다.
</details>

## 페이지 테이블 관리

> 페이지 테이블 자체도 메모리에 있다 — 테이블이 커지면 그 자체가 부담

- 프로세스 수가 많아지면 페이지 테이블 총량도 커져 **메모리를 잠식**
- 페이지 테이블의 시작 주소는 **페이지 테이블 기준 레지스터(PTBR)** 가 보관 (각 프로세스의 PCB에 저장)
- 물리 메모리가 부족하면 페이지 테이블 일부도 스왑 영역으로 옮겨질 수 있음

**주소 변환 속도 문제와 해결**

| 방식 | 내용 |
|---|---|
| 문제 | 메모리 접근 1회마다 (테이블 조회 1회 + 실제 접근 1회) = 2회 접근 → 느림 |
| TLB (변환 색인 버퍼) | 자주 쓰는 변환 결과를 담는 **하드웨어 캐시**. TLB 히트 시 테이블 조회 생략 |
| 다단계 페이지 테이블 | 테이블을 여러 단계로 쪼개 **쓰는 부분만** 메모리에 유지 |
| 역 페이지 테이블 | 프레임 기준으로 테이블 하나만 유지 (<프로세스 ID, 페이지 번호>) → 크기 획기적 감소, 검색은 느림 |

<details><summary>TLB 미스가 나면 어떻게 되는가?</summary>

메모리에 있는 페이지 테이블을 직접 조회해 변환하고, <br>
그 결과를 TLB에 새로 등록한다(지역성 덕분에 다음엔 히트할 확률이 높다). <br>
따라서 TLB 미스가 잦으면 메모리 접근이 사실상 2배로 늘어 성능이 떨어진다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 페이징은 가상 공간을 페이지, 물리 메모리를 같은 크기의 프레임으로 나눠 페이지 테이블로 매핑하는 기법으로, 주소 변환은 VA=<P,D>→PA=<F,D>로 이뤄지며, 테이블이 커지고 느려지는 문제는 TLB·다단계·역 페이지 테이블로 보완한다
