# 인터럽트 처리 (심화학습)

> 인터럽트 : CPU가 하던 일을 멈추고 급한 사건을 먼저 처리하게 하는 신호 — 현대 운영체제는 인터럽트 기반으로 동작한다

## 인터럽트의 개념

- 폰노이만 구조에서 CPU는 명령어를 순차적으로 실행하지만, 실행 도중 **예기치 않은 사건**이 발생할 수 있음
- 입출력 완료, 0으로 나누기, 하드웨어 고장, 사용자의 강제 종료(Ctrl+C) 등
- 이런 사건을 CPU에 알려 처리하게 하는 메커니즘이 **인터럽트**

---

## 동기적 인터럽트와 비동기적 인터럽트

| 구분 | 동기적 인터럽트 | 비동기적 인터럽트 |
|---|---|---|
| 발생 시점 | 프로세스가 **실행 중인 명령어 때문에** 발생 (실행 흐름과 동기) | 실행 중인 명령어와 **무관하게** 임의 시점에 발생 |
| 다른 이름 | 예외, 트랩 | 하드웨어 인터럽트 |
| 예 | 0으로 나누기, 잘못된 메모리 접근(세그멘테이션 폴트), 오버플로, 시스템 호출 | 입출력 완료, 키보드 입력, 하드웨어 고장, 타이머(클록) 인터럽트 |

---

## 인터럽트 처리 과정

1. 인터럽트 발생 → CPU는 실행 중인 명령어를 마친 뒤 하던 일을 멈춤
2. 현재 프로세스의 상태(레지스터, PC 등)를 **PCB에 저장** (재개를 위해)
3. **인터럽트 벡터**에서 발생한 인터럽트의 종류 확인
4. 해당 인터럽트를 처리하는 **인터럽트 핸들러(ISR)** 실행
5. 처리가 끝나면 저장해 둔 상태를 복원하여 원래 프로세스 재개 (또는 스케줄러가 다른 프로세스 선택)

| 용어 | 내용 |
|---|---|
| 인터럽트 벡터 | 인터럽트 종류별 핸들러의 주소를 담은 테이블 |
| 인터럽트 핸들러 (ISR) | 각 인터럽트의 처리 방법을 구현한 함수 |

- 처리 과정이 문맥 교환과 유사 — 인터럽트가 문맥 교환을 유발하는 대표 계기

## 인터럽트와 이중 모드

> 이중 모드 : CPU가 **사용자 모드**와 **커널 모드**를 오가며 동작하는 것

| 구분 | 사용자 모드 | 커널 모드 |
|---|---|---|
| 실행 주체 | 사용자 프로세스 | 운영체제(커널) |
| 권한 | 제한적 — 하드웨어 직접 접근 불가 | 모든 명령어·자원 접근 가능 |

**모드 전환**

- 사용자 프로세스가 자원(파일, 입출력 등)을 쓰려면 **시스템 호출**로 커널에 요청 → 커널 모드로 전환
- 시스템 호출은 동기적 인터럽트의 일종 — 인터럽트 메커니즘으로 모드가 전환됨
- 커널이 작업을 마치면 다시 사용자 모드로 복귀

<details><summary>왜 이중 모드가 필요한가?</summary>

사용자 프로세스가 하드웨어와 자원에 직접 접근하면 다른 프로세스의 영역을 침범하거나 시스템을 망가뜨릴 수 있다. <br>
그래서 위험한 작업은 모두 커널만 할 수 있게 막고, 사용자 프로세스는 시스템 호출이라는 정해진 창구로만 요청하게 한다. <br>
이중 모드는 운영체제가 시스템을 보호하는 핵심 장치다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 인터럽트는 명령어 실행이 원인인 동기적 인터럽트와 외부 사건이 원인인 비동기적 인터럽트로 나뉘며, CPU는 상태 저장 → 인터럽트 벡터 확인 → 핸들러 실행의 과정으로 처리하고, 시스템 호출 역시 인터럽트를 통해 사용자 모드에서 커널 모드로 전환하며 이루어진다
