# 스케줄링 시 고려 사항

> 스케줄링 방식(선점/비선점), 프로세스의 성격(우선순위, CPU/입출력 집중, 전면/후면)에 따라 CPU 배분 전략이 달라진다

## 선점형 스케줄링과 비선점형 스케줄링

| 구분 | 선점형 | 비선점형 |
|---|---|---|
| 정의 | 운영체제가 실행 중인 프로세스로부터 CPU를 강제로 빼앗을 수 있음 | 한 번 CPU를 잡으면 스스로 반환할 때까지 빼앗지 못함 |
| 장점 | 응답성 좋음 — 대화형·시분할 시스템에 적합 | 문맥 교환 적음 → 오버헤드 적음 |
| 단점 | 문맥 교환 오버헤드 큼 | 긴 작업이 CPU를 독점하면 다른 프로세스가 오래 기다림 |
| 사용 | 오늘날 운영체제 대부분 | 과거 일괄 작업(배치) 시스템 |
| 예 | 라운드 로빈, SRT, 다단계 피드백 큐 | FCFS, SJF, HRN |

- 인터럽트, 타임 슬라이스 만료가 선점의 대표 계기

---

## 프로세스 우선순위

> 모든 프로세스는 우선순위를 가지며, 높은 프로세스가 CPU를 먼저·더 오래 얻는다

| 구분 | 커널 프로세스 | 일반 프로세스 |
|---|---|---|
| 역할 | 운영체제의 중요한 작업 수행 | 사용자 프로그램 |
| 우선순위 | 높음 | 낮음 |

- 우선순위가 높다 = 더 빨리, 더 자주 실행된다
- 대기 상태에서도 우선순위 높은 프로세스의 입출력이 먼저 처리됨

**정적 우선순위와 동적 우선순위**

| 구분 | 내용 |
|---|---|
| 정적 우선순위 | 프로세스 생성 시 부여된 우선순위가 끝까지 유지 — 구현 쉬움, 시스템 변화 미반영 |
| 동적 우선순위 | 상황에 따라 우선순위가 변함 — 구현 어려우나 시스템 효율 향상 (예 : 오래 기다린 프로세스 우선순위 상승) |

---

## CPU 집중 프로세스와 입출력 집중 프로세스

> 프로세스는 CPU 사용 구간(CPU 버스트)과 입출력 대기 구간(입출력 버스트)의 비중에 따라 성격이 나뉜다

| 구분 | CPU 집중 프로세스 | 입출력 집중 프로세스 |
|---|---|---|
| 특징 | 수학 연산처럼 CPU를 오래 사용 (CPU 버스트가 많음) | 파일 읽기·저장처럼 입출력 대기가 많음 (입출력 버스트가 많음) |
| CPU 사용 패턴 | 길게 붙잡음 | 잠깐 쓰고 입출력으로 넘어감 |

> **입출력 집중 프로세스에 CPU를 먼저 배정하는 것이 유리하다**

- 입출력 집중 프로세스는 CPU를 잠깐만 쓰고 바로 입출력(대기)으로 넘어감
- 먼저 처리해 주면 입출력장치와 CPU가 **동시에** 일하게 되어 시스템 효율 상승 — "사이클 훔치기"처럼 자원 활용 극대화

---

## 전면 프로세스와 후면 프로세스

| 구분 | 전면 프로세스 | 후면 프로세스 |
|---|---|---|
| 정의 | 화면에 보이며 사용자와 상호작용하는 프로세스 | 사용자와 상호작용 없이 뒤에서 실행되는 프로세스 |
| 성격 | 대화형 프로세스 | 일괄 작업 프로세스 |
| 우선순위 | 높음 (응답성이 중요) | 낮음 |
| 예 | 지금 입력 중인 워드프로세서 | 백업, 바이러스 검사 |

---

## 정리 : CPU 우선 배정 기준

| 우선 배정 | 이유 |
|---|---|
| 커널 프로세스 > 일반 프로세스 | 시스템 안정성 |
| 전면 프로세스 > 후면 프로세스 | 응답성 (사용자 경험) |
| 대화형 프로세스 > 일괄 작업 프로세스 | 응답성 |
| 입출력 집중 프로세스 > CPU 집중 프로세스 | 자원 활용 효율 |

## 🔑 최종 정리

> 한 줄 요약: 스케줄링은 선점형/비선점형이라는 방식의 선택 위에서, 커널·전면·대화형·입출력 집중 프로세스에 우선권을 주는 방향으로 설계되어 응답성과 시스템 효율을 함께 노린다
