# 스케줄링의 개요

> CPU 스케줄러 : 여러 프로세스 중 어떤 프로세스에 CPU를 배정할지 결정하는 운영체제의 핵심 요소

## 레스토랑 관리자의 스케줄링

- 요리사(CPU)가 여러 주문(프로세스)을 어떤 순서로 처리할지 관리자가 결정하는 것에 비유
- 단순히 들어온 순서대로 처리하는 것이 항상 최선은 아님 — 급한 주문, 간단한 주문, VIP 손님 등을 고려
- 스케줄링의 목표 : **모든 손님(프로세스)이 만족하도록 CPU를 공평하고 효율적으로 배분**

---

## CPU 스케줄링

> 스케줄링은 결정하는 단계(수준)에 따라 고수준·중간 수준·저수준으로 나뉜다

| 구분 | 다른 이름 | 결정 내용 |
|---|---|---|
| 고수준 스케줄링 | 장기 스케줄링, 잡 스케줄링, 승인 스케줄링 | 시스템에 작업을 몇 개나 받아들일지 (전체 작업 수 조절) |
| 중간 수준 스케줄링 | 중기 스케줄링 | 어떤 프로세스를 보류하고 재시작할지 (활성 프로세스 수 조절) |
| 저수준 스케줄링 | 단기 스케줄링 | 어떤 프로세스에 CPU를 할당할지, 어떤 프로세스를 대기 상태로 보낼지 |

- 고수준 : 전체 시스템의 부하를 조절 (배치 시스템 시절의 개념, 오늘날엔 역할 축소)
- 중간 수준 : 저수준 스케줄링이 원만하게 이루어지도록 완충 역할
- 저수준 : 가장 빈번하게 일어나며, 보통 "CPU 스케줄링"이라 하면 저수준을 말함

<details><summary>세 수준의 스케줄링을 레스토랑에 비유하면?</summary>

고수준은 예약을 몇 팀이나 받을지 결정하는 것, <br>
중간 수준은 가게가 붐빌 때 일부 손님을 대기실로 안내하는 것, <br>
저수준은 요리사가 지금 어떤 주문을 요리할지 정하는 것이다.
</details>

## 스케줄링의 목적

> 모든 프로세스가 공평하게, 시스템 자원은 낭비 없이, 응답은 빠르게

| 목적 | 내용 |
|---|---|
| 공평성 | 모든 프로세스가 자원을 공평하게 배정받아야 하며, 배정 과정에서 특정 프로세스가 배제되면 안 됨 |
| 효율성 | 시스템 자원이 유휴 시간 없이 사용되도록 하고, 유휴 자원을 사용하려는 프로세스에 우선권을 줌 |
| 안정성 | 우선순위를 사용하여 중요한 프로세스(커널 등)가 먼저 처리되도록 함 |
| 확장성 | 프로세스가 늘어나도 시스템이 안정적으로 작동해야 함 |
| 반응 시간 보장 | 응답이 없으면 사용자는 시스템이 멈춘 것으로 인식 — 적절한 시간 안에 응답해야 함 |
| 무한 연기 방지 | 특정 프로세스의 작업이 무한히 연기(아사)되어서는 안 됨 |

## 🔑 최종 정리

> 한 줄 요약: CPU 스케줄링은 고수준(작업 승인)·중간 수준(보류/재시작)·저수준(CPU 할당)으로 나뉘며, 공평성·효율성·안정성·반응 시간 보장 등을 목표로 한정된 CPU를 여러 프로세스에 배분하는 일이다
