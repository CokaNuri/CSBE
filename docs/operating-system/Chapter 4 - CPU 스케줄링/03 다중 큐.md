# 다중 큐

> 준비 상태와 대기 상태의 프로세스들은 하나의 큐가 아니라 여러 개의 큐(다중 큐)로 관리된다

## 준비 상태의 다중 큐

> 우선순위에 따라 여러 개의 준비 큐를 두고, 프로세스는 자신의 우선순위에 해당하는 큐에 들어간다

- 준비 상태에 들어온 프로세스의 PCB는 자기 우선순위 큐의 마지막에 연결됨
- CPU 스케줄러는 **가장 높은 우선순위 큐의 맨 앞 프로세스**부터 CPU에 배정
- 큐를 우선순위별로 나누면 높은 우선순위 프로세스를 빨리 찾을 수 있음

**우선순위 운영 방식**

| 방식 | 내용 | 문제 |
|---|---|---|
| 고정 우선순위 | 부여된 우선순위 유지 (정적) | 시스템 상황 변화 반영 못 함 |
| 변동 우선순위 | 일정 시간마다 우선순위 재조정 (동적) | 구현 복잡 |

- 유닉스의 nice 값처럼, 오늘날 운영체제는 변동 우선순위를 응용해 사용

---

## 대기 상태의 다중 큐

> 같은 입출력장치를 기다리는 프로세스끼리 모아 장치별 큐를 만든다

- 하드디스크 큐, 프린터 큐, 키보드 큐 … 장치마다 대기 큐가 따로 존재
- 입출력이 완료되면 해당 장치의 큐에서 기다리던 프로세스에 **인터럽트**로 알려 준비 상태로 옮김 (웨이크업)

**준비 큐와 대기 큐의 차이**

| 구분 | 준비 큐 | 대기 큐 |
|---|---|---|
| 나누는 기준 | 우선순위 | 입출력장치 종류 |
| 나가는 방식 | 큐의 앞에서 하나씩 디스패치 | 입출력이 끝난 프로세스가 (순서 무관하게) 동시에 여러 개 나갈 수 있음 |

<details><summary>대기 큐에서는 왜 여러 PCB가 한꺼번에 나올 수 있는가?</summary>

인터럽트 벡터는 여러 인터럽트를 묶어서 알려주기 때문에, 한 번의 인터럽트 처리로 <br>
입출력이 끝난 여러 프로세스가 동시에 준비 상태로 이동할 수 있다. <br>
그래서 대기 큐는 준비 큐처럼 앞에서부터 순서대로 빠지는 구조가 아니다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 준비 상태는 우선순위별 다중 큐로 관리되어 스케줄러가 높은 우선순위 프로세스를 빠르게 고르게 하고, 대기 상태는 입출력장치별 다중 큐로 관리되어 인터럽트가 오면 해당 프로세스들을 준비 큐로 돌려보낸다
