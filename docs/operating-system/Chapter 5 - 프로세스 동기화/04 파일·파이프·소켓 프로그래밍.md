# 파일·파이프·소켓 프로그래밍

> 프로세스 간 통신을 실제 코드로 구현하는 세 가지 대표 방법 — 파일, 파이프, 네트워크 소켓

## 파일

> 프로세스들이 같은 파일을 매개로 데이터를 주고받는 가장 단순한 통신 방법

- 한 프로세스가 파일에 쓰고(write), 다른 프로세스가 그 파일을 읽어(read) 데이터를 공유
- 저장장치를 거치므로 통신 속도가 느림
- 여러 프로세스가 같은 파일을 동시에 읽고 쓰면 **경쟁 조건**이 생김 → **파일 잠금(file lock)** 으로 보호 필요
- 프로세스가 종료돼도 데이터가 파일에 남는다는 장점 (영속성)

---

## 파이프

> 한 프로세스의 출력을 다른 프로세스의 입력으로 연결하는 통로 — 단방향 통신

**파이프의 종류**

| 종류 | 내용 |
|---|---|
| 익명 파이프 | 부모–자식처럼 **혈연 관계**가 있는 프로세스끼리 통신 — 단방향 |
| 지명(명명) 파이프 | 이름을 가진 파이프(FIFO)로, **관계없는** 프로세스끼리도 통신 가능 |

- 익명 파이프는 이름이 없어 부모가 자식에게 파이프를 물려주는 방식으로만 연결됨
- 양방향으로 통신하려면 파이프 **두 개**를 사용해야 함
- 리눅스 셸의 `|` (예 : `ls | grep txt`)가 익명 파이프의 대표 예 — 앞 명령의 출력이 뒤 명령의 입력이 됨

---

## 네트워킹 (소켓)

> 네트워크로 연결된 서로 다른 컴퓨터의 프로세스끼리 통신하는 양방향 방법

- **소켓** : 네트워크 통신의 양 끝점(endpoint) — IP 주소 + 포트 번호로 상대를 지정
- 메시지 전달 방식이라 동기화 문제가 적고, 원격 통신이 가능
- 통신 구조 : **서버–클라이언트 모델**

| 역할 | 동작 순서 |
|---|---|
| 서버 | 소켓 생성 → 주소 바인딩(bind) → 연결 대기(listen) → 연결 수락(accept) |
| 클라이언트 | 소켓 생성 → 서버에 연결 요청(connect) |
| 공통 | 연결 후 send/recv로 데이터를 주고받고 close로 종료 |

<details><summary>파이프와 소켓의 결정적 차이는?</summary>

파이프는 같은 컴퓨터 안의 프로세스끼리만 통신하는 단방향 통로다. <br>
소켓은 IP·포트로 상대를 지정하므로 다른 컴퓨터의 프로세스와도 <br>
양방향으로 통신할 수 있다. 즉 네트워크 통신은 소켓으로 한다.
</details>

---

## 통신 방법 비교

| 방법 | 범위 | 방향 | 특징 |
|---|---|---|---|
| 파일 | 같은 시스템 | 양방향(간접) | 느리지만 데이터가 영속됨 |
| 파이프 | 같은 시스템 | 단방향 | 프로세스 간 간단한 통로 |
| 소켓 | 네트워크(다른 컴퓨터 가능) | 양방향 | 서버–클라이언트 원격 통신 |

---

## 🔑 최종 정리

> 한 줄 요약: 프로세스 간 통신은 느리지만 영속되는 파일, 같은 시스템 내 단방향 통로인 파이프(익명·지명), 다른 컴퓨터와도 양방향으로 통신하는 소켓(서버–클라이언트)으로 구현된다
