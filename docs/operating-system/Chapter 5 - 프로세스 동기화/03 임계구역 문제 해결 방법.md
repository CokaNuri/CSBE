# 임계구역 문제 해결 방법

> 상호 배제를 실제로 구현하는 방법들 — 소프트웨어적 시도부터 세마포어·모니터까지

## 기본 코드 소개

> 임계구역을 잠금(lock) 변수 하나로 지키려는 가장 단순한 시도

```
while (lock == true) ;   // 잠겨 있으면 기다림
lock = true;             // 잠금
   // 임계구역
lock = false;            // 잠금 해제
```

- 문제 : 잠금을 **검사(while)** 하고 **설정(lock = true)** 하는 두 동작 사이에 다른 프로세스가 끼어들 수 있음
- 두 프로세스가 동시에 `lock == false`를 보고 둘 다 임계구역에 진입 → **상호 배제 실패**
- 원인 : 검사와 설정이 **하나의 원자적(atomic) 동작**이 아니기 때문

---

## 임계구역 문제 해결 조건을 고려한 코드 설계

> 조건을 하나씩 맞춰가며 코드를 개선하지만, 매번 다른 조건이 깨진다

| 시도 | 방법 | 깨지는 조건 |
|---|---|---|
| 잠금만 사용 | lock 변수 하나 | 상호 배제 실패 (검사·설정 분리) |
| 서로 양보 | `turn` 변수로 차례를 지정 | 진행의 융통성 부족 — 상대가 없어도 자기 차례가 아니면 못 들어감 |
| 서로 준비 상태 표시 | `flag[]` 배열로 진입 의사 표시 | 둘 다 flag를 세우면 **교착 상태**로 서로 무한 대기 |

- 소프트웨어만으로 세 조건을 모두 만족시키기가 매우 까다롭다는 것을 보여줌

---

## 피터슨 알고리즘

> `turn`(양보)과 `flag[]`(진입 의사)를 함께 사용해 두 프로세스의 상호 배제를 해결

```
flag[i] = true;          // 나 들어가고 싶다
turn = j;                // 하지만 상대에게 양보
while (flag[j] && turn == j) ;   // 상대가 원하고 상대 차례면 대기
   // 임계구역
flag[i] = false;         // 나 나감
```

- 상호 배제·진행·유한 대기 세 조건을 모두 만족
- **한계** : 두 개의 프로세스에서만 동작 (셋 이상으로 확장 어려움)

---

## 데커 알고리즘

> 최초로 임계구역 문제를 소프트웨어만으로 해결한 알고리즘

- `flag[]`(진입 의사)와 `turn`(양보)을 조합하되, 충돌 시 `turn`을 보고 한쪽이 물러남
- 피터슨 알고리즘과 마찬가지로 두 프로세스의 상호 배제를 보장
- 코드가 피터슨보다 복잡함 → 오늘날은 더 간결한 피터슨 알고리즘이 더 잘 알려짐

<details><summary>데커·피터슨 같은 소프트웨어 방식의 공통 한계는?</summary>

두 프로세스에만 적용되고, 대기하는 동안 while 루프를 계속 도는 <br>
**바쁜 대기(busy waiting)** 로 CPU를 낭비한다. <br>
그래서 실제 운영체제는 세마포어·모니터 같은 상위 도구를 사용한다.
</details>

## 세마포어

> 정수 변수 하나와 두 연산(P·V)으로 상호 배제와 동기화를 처리하는 도구

| 연산 | 별칭 | 동작 |
|---|---|---|
| P (wait) | 감소 | 세마포어 값을 1 줄임 — 값이 0 이하면 대기(잠금) |
| V (signal) | 증가 | 세마포어 값을 1 늘림 — 대기 중인 프로세스를 깨움(해제) |

```
P(S);        // 자원 획득 (없으면 대기)
   // 임계구역
V(S);        // 자원 반납
```

- 세마포어 값의 의미 : 사용 가능한 자원의 개수
    - 값이 1이면 → **이진 세마포어**(뮤텍스), 상호 배제에 사용
    - 값이 N이면 → **계수 세마포어**, N개의 자원 관리에 사용
- P·V 연산 자체는 **원자적으로** 실행됨 → 기본 코드의 검사·설정 분리 문제를 해결
- 대기하는 프로세스는 큐에 들어가 잠들었다가 V 연산 때 깨어남 → 바쁜 대기 회피
- **주의** : P·V를 순서를 잘못 쓰거나 빠뜨리면 교착 상태·상호 배제 실패가 발생 (프로그래머 실수에 취약)

---

## 모니터

> 세마포어의 사용상 위험을 없애기 위해, 공유 자원과 접근 함수를 하나로 묶은 상위 수준 동기화 도구

- 공유 자원에 직접 접근하지 못하게 막고, **모니터가 제공하는 함수를 통해서만** 접근하게 함
- 모니터 안에는 **한 번에 하나의 프로세스만** 들어갈 수 있음 (상호 배제가 자동 보장)
- 프로그래머가 P·V를 직접 다루지 않아도 되므로 실수 위험이 적음
- **조건 변수**와 `wait`/`signal` 연산으로 프로세스 간 동기화(순서 제어)를 처리
- 자바의 `synchronized` 키워드가 모니터 개념의 대표적 구현

| 구분 | 세마포어 | 모니터 |
|---|---|---|
| 수준 | 저수준 (정수 변수 + P·V) | 고수준 (언어·컴파일러 차원) |
| 상호 배제 | 프로그래머가 P·V로 직접 구현 | 자동 보장 |
| 실수 위험 | 높음 (순서·누락) | 낮음 |

---

## 🔑 최종 정리

> 한 줄 요약: 임계구역 해결은 잠금 변수의 검사·설정 분리 문제에서 출발해, 소프트웨어 방식(피터슨·데커)으로 두 프로세스의 상호 배제를 이뤘고, 원자적 P·V 연산을 쓰는 세마포어를 거쳐, 상호 배제를 자동 보장하고 실수를 줄인 모니터로 발전했다
