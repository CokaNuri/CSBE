# 프로세스 간 통신

> 프로세스 간 통신(IPC) : 독립적으로 실행되는 프로세스들이 데이터를 주고받는 것

## 프로세스 간 통신의 개념

- 프로세스는 기본적으로 서로의 메모리에 접근할 수 없다 (독립성 보장)
- 하지만 협력해서 일하려면 데이터를 주고받아야 함 → 운영체제가 통신 수단을 제공
- 통신 상대에 따른 구분

| 구분 | 내용 |
|---|---|
| 프로세스 내부 통신 | 하나의 프로세스 안에서 함수·전역 변수를 통해 데이터 공유 |
| 프로세스 간 통신 | 서로 다른 프로세스 사이의 통신 (파이프, 소켓 등) |
| 네트워크 간 통신 | 다른 컴퓨터의 프로세스와 통신 (소켓) |

---

## 프로세스 간 통신의 분류

> 통신 방식은 **통신 방향**과 **매개 여부**로 나뉜다

**통신 방향에 따른 분류**

| 방식 | 내용 | 예 |
|---|---|---|
| 양방향 통신 | 데이터를 동시에 양쪽으로 주고받음 | 소켓 |
| 반양방향 통신 | 한 번에 한 방향씩만 주고받음 | 무전기 |
| 단방향 통신 | 한쪽으로만 데이터가 흐름 | 파이프, 전역 변수 |

**매개 여부에 따른 분류**

| 방식 | 내용 |
|---|---|
| 대기가 있는 통신 (동기화 O) | 한쪽이 데이터를 보낼 때까지 다른 쪽이 기다림 |
| 대기가 없는 통신 (동기화 X) | 상대의 상태와 관계없이 통신 진행 |

---

## 프로세스 간 통신의 종류

| 종류 | 방식 | 설명 |
|---|---|---|
| 전역 변수 | 공유 메모리 | 부모–자식 프로세스가 같은 전역 변수를 공유 — 단방향, 구현 단순하나 동기화 문제 발생 |
| 파이프 | 공유 메모리 | 한 프로세스가 쓰고 다른 프로세스가 읽는 통로 — 단방향 |
| 소켓 | 메시지 전달 | 네트워크로 연결된 프로세스 간 양방향 통신 |

- **공유 메모리 방식** : 공동의 메모리 영역을 두고 그곳에 데이터를 읽고 씀 → 빠르지만 **동기화(임계구역) 문제**가 생김
- **메시지 전달 방식** : 운영체제를 거쳐 메시지를 주고받음 → 느리지만 동기화 문제가 적음

<details><summary>공유 메모리 방식이 빠른데도 메시지 전달 방식을 쓰는 이유는?</summary>

공유 메모리는 여러 프로세스가 같은 영역에 동시에 접근하므로 <br>
누가 먼저 읽고 쓰느냐에 따라 결과가 달라지는 **임계구역 문제**가 생긴다. <br>
메시지 전달은 운영체제가 중개해 이 문제를 원천적으로 피할 수 있어 안전하다.
</details>

---

## 🔑 최종 정리

> 한 줄 요약: 프로세스 간 통신(IPC)은 독립된 프로세스들이 데이터를 주고받는 방법으로, 통신 방향(단·반양·양방향)과 매개 여부(동기화)로 나뉘며, 빠르지만 동기화 문제가 있는 공유 메모리 방식과 안전한 메시지 전달 방식으로 구현된다
