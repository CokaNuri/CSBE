# 공유 자원과 임계구역

> 여러 프로세스가 함께 쓰는 자원에 동시에 접근하면 문제가 생긴다 — 이 위험 구간이 임계구역

## 공유 자원에 대한 접근

> 공유 자원 : 여러 프로세스가 함께 사용하는 변수·메모리·파일·장치 등

- 여러 프로세스가 공유 자원에 **동시에 접근**하면 실행 순서에 따라 결과가 달라짐
- **경쟁 조건(race condition)** : 둘 이상의 프로세스가 공유 자원을 동시에 접근하려고 경쟁하는 상황 → 실행 순서에 따라 결과가 예측 불가

**예시 : 두 프로세스가 공유 변수 `balance`(초기 100)를 각각 +10 하는 경우**

- 정상 : 100 → 110 → 120
- 경쟁 조건 발생 시 : 둘 다 100을 읽은 뒤 각자 110을 써서 결과가 **110** (10이 사라짐)

---

## 임계구역

> 임계구역(critical section) : 공유 자원에 접근하는 코드 영역 — 한 번에 하나의 프로세스만 들어가야 하는 구간

- 임계구역 문제의 핵심은 **상호 배제(mutual exclusion)** : 한 프로세스가 임계구역에 있으면 다른 프로세스는 못 들어오게 막는 것
- 임계구역을 제대로 보호하지 못하면 경쟁 조건으로 데이터가 손상됨

**프로세스 코드의 구조**

| 구간 | 내용 |
|---|---|
| 진입 구역 | 임계구역에 들어가도 되는지 검사 · 잠금(lock)을 획득 |
| 임계구역 | 공유 자원에 실제로 접근하는 부분 |
| 퇴출 구역 | 임계구역에서 나오며 잠금(lock)을 해제 |
| 나머지 구역 | 임계구역과 무관한 나머지 코드 |

## 생산자-소비자 문제

> 임계구역 문제를 설명하는 대표적인 모델

| 역할 | 내용 |
|---|---|
| 생산자 | 데이터(물건)를 만들어 **버퍼**에 넣음 |
| 소비자 | 버퍼에서 데이터를 꺼내 사용 |
| 버퍼 | 생산자와 소비자가 공유하는 저장 공간 |

- 생산자와 소비자가 **버퍼(공유 자원)** 를 동시에 조작하면서 문제 발생
- 버퍼의 내용물 개수를 세는 변수 `count`(공유 변수)를 양쪽이 동시에 건드리면 값이 어긋남
- 버퍼가 가득 찼는데 생산자가 넣거나, 비었는데 소비자가 꺼내는 상황도 막아야 함

<details><summary>생산자-소비자 문제가 임계구역 문제인 이유는?</summary>

생산자와 소비자가 공유 버퍼(특히 개수 변수 count)에 동시에 접근하기 때문이다. <br>
버퍼가 곧 공유 자원이고, 이를 조작하는 코드가 임계구역이므로 <br>
상호 배제로 보호하지 않으면 데이터 개수가 어긋나는 경쟁 조건이 발생한다.
</details>

## 임계구역 문제 해결 조건

> 올바른 임계구역 해결책이라면 아래 세 조건을 모두 만족해야 한다

| 조건 | 내용 |
|---|---|
| 상호 배제 | 한 프로세스가 임계구역에 있으면 다른 프로세스는 들어갈 수 없다 |
| 진행(한정 대기) | 임계구역이 비어 있으면 들어가려는 프로세스는 곧 들어갈 수 있어야 한다 (무한 대기 금지) |
| 유한 대기(제한된 대기) | 한 프로세스가 무한정 기다리지 않도록, 대기 시간에 한계가 있어야 한다 (아사 방지) |

- 세 조건을 모두 지켜야 안전하고 공평한 동기화가 된다

## 🔑 최종 정리

> 한 줄 요약: 여러 프로세스가 공유 자원에 동시에 접근하면 실행 순서에 따라 결과가 달라지는 경쟁 조건이 생기며, 이를 막으려면 공유 자원에 접근하는 임계구역을 상호 배제·진행·유한 대기 세 조건을 만족하도록 보호해야 한다
