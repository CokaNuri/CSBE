# 스레드

> 스레드 : 프로세스 내부의 실행 단위 — CPU 스케줄러가 CPU에 전달하는 작업의 단위

## 스레드의 개념

| 구분 | 프로세스 | 스레드 |
|---|---|---|
| 역할 | 자원을 소유하는 단위 (운영체제 관점의 작업 단위) | 실제로 실행되는 단위 (CPU 관점의 작업 단위) |
| 소유 | 코드·데이터·힙·자원(파일 등) | 스택, 레지스터, 프로그램 카운터 |

- 하나의 프로세스는 **하나 이상의 스레드**를 가짐
- 프로세스 = 스레드들의 컨테이너

**관련 용어 정리**

| 용어 | 내용 |
|---|---|
| 멀티스레드 | 하나의 프로세스 안에 여러 스레드를 두어 동시 작업 |
| 멀티태스킹 | 운영체제가 CPU에 여러 작업(스레드)을 번갈아 배정 (시분할) |
| 멀티프로세싱 | 여러 CPU(코어)로 여러 스레드를 병렬 처리 |
| CPU 멀티스레드 | 하나의 코어가 여러 스레드를 동시에 처리하는 하드웨어 기법 (하이퍼스레드) |

---

## 멀티스레드의 구조와 예

> 스레드들은 프로세스의 코드·데이터·힙 영역을 공유하고, 스택은 각자 따로 가진다

| 영역 | 공유 여부 |
|---|---|
| 코드 영역 | 공유 |
| 데이터 영역 | 공유 |
| 힙 영역 | 공유 |
| 스택·레지스터·PC | 스레드마다 별도 |

**예 : 워드프로세서**

- 입력을 받는 스레드 + 맞춤법을 검사하는 스레드 + 주기적으로 자동 저장하는 스레드
- 셋이 하나의 문서(데이터)를 공유하면서 동시에 동작

<details><summary>같은 작업을 멀티프로세스로 하면 왜 비효율적인가?</summary>

프로세스를 여러 개 만들면 코드·데이터가 통째로 복사되어 메모리가 낭비되고, <br>
프로세스 간에는 메모리가 분리되어 있어 데이터를 주고받으려면 별도의 프로세스 간 통신(IPC)이 필요하다. <br>
멀티스레드는 메모리를 공유하므로 생성 비용도 낮고 데이터 교환도 자유롭다.
</details>

## 멀티스레드의 장단점

**장점**

| 장점 | 내용 |
|---|---|
| 응답성 향상 | 한 스레드가 입출력으로 대기해도 다른 스레드는 계속 작업 |
| 자원 공유 | 코드·데이터·자원을 공유하여 낭비 없이 협업 |
| 효율성(경제성) 향상 | 프로세스 생성·문맥 교환보다 스레드 생성·교환이 훨씬 가벼움 |
| 다중 CPU 지원 | 스레드들을 여러 코어에 나누어 진짜 병렬 처리 가능 |

**단점**

- 한 스레드에 문제가 생기면 **프로세스 전체가 영향**을 받음 (자원을 공유하므로)
- 공유 데이터에 여러 스레드가 동시 접근하면 동기화 문제 발생 (→ Chapter 5 프로세스 동기화)

## 멀티스레드 모델

> 사용자 레벨 스레드와 커널 레벨 스레드를 어떻게 연결(매핑)하느냐에 따른 구분

| 모델 | 매핑 | 특징 |
|---|---|---|
| 사용자 레벨 (N:1) | 사용자 스레드 여러 개 : 커널 스레드 1개 | 라이브러리가 스레드 관리. 문맥 교환 가벼움. 한 스레드가 블록되면 전체가 블록, 멀티코어 활용 불가 |
| 커널 레벨 (1:1) | 사용자 스레드 1개 : 커널 스레드 1개 | 커널이 직접 관리. 한 스레드가 블록돼도 나머지 동작, 멀티코어 활용 가능. 문맥 교환 비용 큼 |
| 멀티레벨 (M:N) | 사용자 스레드 M개 : 커널 스레드 N개 (M ≥ N) | 두 방식의 절충. 유연하지만 구현 복잡 |

## 🔑 최종 정리

> 한 줄 요약: 스레드는 프로세스 안에서 코드·데이터·힙을 공유하며 스택만 따로 갖는 실행 단위로, 가벼운 생성·교환과 자원 공유로 응답성과 효율을 높이지만 하나의 오류가 프로세스 전체에 번지는 위험을 안고 있다
