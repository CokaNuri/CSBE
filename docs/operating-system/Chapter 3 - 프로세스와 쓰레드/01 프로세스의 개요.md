# 프로세스의 개요

> 프로세스 : 실행 중인 프로그램 — 운영체제가 작업을 관리하는 기본 단위

## 프로세스의 개념

| 구분 | 프로그램 | 프로세스 |
|---|---|---|
| 상태 | 저장장치에 저장된 정적인 상태 | 메모리에 올라와 실행 중인 동적인 상태 |
| 존재 | 파일 형태 | 실행 주체 (PCB를 가짐) |

- 하나의 프로그램에서 여러 개의 프로세스가 만들어질 수 있다 (예 : 메모장 여러 개 실행)

---

## 요리사 모형의 비유

| 요리사 모형 | 컴퓨터 |
|---|---|
| 요리사 | CPU |
| 레시피 (요리법) | 프로그램 |
| 요리하는 과정 | 프로세스 |
| 주문서 | 프로세스 제어 블록 (PCB) |

- 손님의 주문(프로그램 실행 요청)이 들어오면 주문서(PCB)가 발행되고, 요리사(CPU)는 주문서에 따라 요리(프로세스 실행)를 진행한다
- 요리가 끝나면(프로세스 종료) 주문서(PCB)도 폐기된다

---

## 프로그램에서 프로세스로의 전환

> 프로그램이 프로세스가 되려면 ① 메모리에 올라오고 ② 운영체제로부터 PCB를 받아야 한다

**프로세스 제어 블록 (PCB)**

> 프로세스를 실행하는 데 필요한 정보를 보관하는 자료 구조

- 모든 프로세스는 고유의 PCB를 가짐
- 프로세스 생성 시 만들어지고 종료 시 폐기됨
- 프로그램이 메모리에 올라와도 PCB가 없으면 프로세스가 아니다

**프로세스의 메모리 영역**

| 영역 | 내용 |
|---|---|
| 코드 (텍스트) 영역 | 실행할 프로그램 코드 |
| 데이터 영역 | 전역 변수, 정적 변수 등 프로그램이 사용하는 데이터 |
| 스택 영역 | 함수 호출 정보, 지역 변수 등 운영 정보 |

## 프로세스의 상태

### 5상태 모델 (활성 상태)

| 상태 | 내용 |
|---|---|
| 생성 | 메모리에 올라와 PCB를 할당받은 상태 |
| 준비 | 실행을 기다리는 상태 — 준비 큐에서 자기 차례를 대기 |
| 실행 | CPU를 할당받아 명령어를 실행 중인 상태 |
| 대기 | 입출력을 요청하고 완료를 기다리는 상태 |
| 완료 | 실행이 끝나 메모리와 PCB가 정리되는 상태 |

**상태 전이**

| 전이 | 내용 |
|---|---|
| 디스패치 | 준비 → 실행 : CPU 스케줄러가 프로세스를 선택해 CPU 할당 |
| 타임아웃 | 실행 → 준비 : 타임 슬라이스를 다 쓰면 다시 준비 상태로 |
| 블록 | 실행 → 대기 : 입출력 요청 시 |
| 웨이크업 | 대기 → 준비 : 입출력이 완료되면 (인터럽트 발생) |

<details><summary>왜 입출력이 끝난 프로세스는 실행 상태가 아니라 준비 상태로 가는가?</summary>

CPU는 이미 다른 프로세스가 사용 중일 수 있기 때문이다. <br>
입출력 완료 인터럽트를 받은 프로세스는 준비 큐로 이동해 다시 자기 차례(디스패치)를 기다린다.
</details>

**타임 슬라이스**

> 프로세스가 한 번에 CPU를 사용할 수 있는 시간

- 시분할 시스템에서 여러 프로세스가 CPU를 번갈아 쓰도록 하는 기준 단위

### 휴식 상태와 보류 상태

| 상태 | 내용 |
|---|---|
| 휴식 | 프로세스가 작업을 일시적으로 쉬는 상태 — 메모리에 그대로 있음 (예 : Ctrl+Z) |
| 보류 | 프로세스가 메모리에서 쫓겨나 스왑 영역에 보관된 상태 |

**보류 상태가 되는 경우**

- 메모리가 꽉 차서 일부 프로세스를 내보낼 때
- 프로그램에 오류가 있어 대기시킬 때
- 바이러스 등 악의적 공격이 의심될 때
- 매우 긴 주기로 실행되는 프로세스일 때
- 입출력을 기다리는 프로세스의 입출력이 계속 지연될 때

- 보류 상태는 **보류 준비 상태**와 **보류 대기 상태**로 나뉨 (어느 상태에서 쫓겨났는지에 따라)
- 다시 메모리로 돌아오는 것 : **재시작**

## 🔑 최종 정리

> 한 줄 요약: 프로세스는 메모리에 올라와 PCB를 부여받은 실행 중인 프로그램이며, 준비·실행·대기 상태를 오가며(디스패치·타임아웃·블록·웨이크업) CPU를 나누어 사용한다
