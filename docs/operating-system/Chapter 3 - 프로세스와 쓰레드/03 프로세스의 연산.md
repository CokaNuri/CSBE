# 프로세스의 연산

> 프로세스의 생성(fork)·전환(exec)과 프로세스 간 계층 구조

## 프로세스의 구조

| 영역 | 내용 | 특징 |
|---|---|---|
| 코드 (텍스트) 영역 | 프로그램의 본문 | 읽기 전용 |
| 데이터 영역 | 전역 변수, 정적 변수 | 읽기/쓰기 가능 |
| 스택 영역 | 함수 호출 정보(복귀 주소), 지역 변수 | 운영체제가 관리, 사용자에게 보이지 않음 |

---

## 프로세스의 생성과 복사 — fork()

> fork() : 실행 중인 프로세스로부터 새로운 프로세스를 복사하는 시스템 호출

- 실행하던 프로세스가 **부모 프로세스**, 새로 만들어진 프로세스가 **자식 프로세스**

**복사되는 것과 달라지는 것**

| 구분 | 내용 |
|---|---|
| 그대로 복사 | 코드 영역, 데이터 영역, 스택 영역, PCB 대부분 |
| 달라짐 | PID, 메모리 위치, PPID·CPID (부모-자식 관계 정보) |

**fork()의 장점**

- 프로세스 생성 속도가 빠름 — 이미 메모리에 있는 것을 복사하므로 저장장치 접근 불필요
- 추가 작업 없이 자원을 상속할 수 있음 (부모가 열어 둔 파일 등)
- 시스템 관리를 효율적으로 할 수 있음 — 부모-자식 관계로 자원 회수가 체계적

---

## 프로세스의 전환 — exec()

> exec() : 기존 프로세스를 새로운 프로세스로 전환하는 시스템 호출

- fork()가 "복사"라면 exec()는 "**리모델링**" — 프로세스는 그대로 두고 내용물만 교체
- 코드 영역과 데이터 영역이 새 프로그램의 것으로 덮어써짐
- PID, PPID, 메모리 위치는 그대로 유지

**exec()를 사용하는 이유**

- 새 프로세스를 처음부터 만들려면 PCB 생성, 메모리 할당 등 번거로운 작업 필요
- exec()는 **이미 만들어진 PCB와 메모리 영역을 재활용**

<details><summary>fork()와 exec()는 왜 함께 쓰이는가?</summary>

유닉스에서 새 프로그램을 실행하는 표준 패턴이 fork() + exec()이다. <br>
쉘에서 명령어를 입력하면, 쉘이 fork()로 자신을 복사한 뒤 자식 프로세스가 exec()로 해당 명령어 프로그램으로 전환한다. <br>
이렇게 하면 PCB 생성·메모리 할당이라는 무거운 작업 없이 새 프로그램을 실행할 수 있다.
</details>

## 프로세스의 계층 구조

> 유닉스에서 모든 프로세스는 최초 프로세스로부터 fork()로 만들어진 자식들이다 — 트리 형태의 계층 구조

- 부팅 시 커널이 최초 프로세스(**init**, 현대 리눅스는 systemd)를 만들고, 이후 모든 프로세스는 그 자손
- 계층 구조의 장점 : 부모가 자식의 자원을 회수하는 등 **체계적인 자원 관리** 가능

### 고아 프로세스와 좀비 프로세스

| 구분 | 고아 프로세스 | 좀비 프로세스 |
|---|---|---|
| 정의 | 부모가 먼저 종료된 자식 프로세스 | 종료했지만 부모가 종료 처리(자원 회수)를 안 해준 프로세스 |
| 처리 | init 프로세스가 새 부모가 되어 정리 | 부모가 wait()를 호출해야 정리됨 |
| 문제 | — | PCB 등이 메모리에 남아 자원 낭비 |

---

## 🔑 최종 정리

> 한 줄 요약: 프로세스는 fork()로 자신을 복사해 자식을 만들고 exec()로 내용만 교체하며, 이렇게 만들어진 부모-자식 트리 구조 덕분에 운영체제는 자원을 체계적으로 회수·관리할 수 있다
