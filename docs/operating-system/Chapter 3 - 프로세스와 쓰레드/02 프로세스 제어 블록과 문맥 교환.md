# 프로세스 제어 블록과 문맥 교환

> PCB는 프로세스의 신분증, 문맥 교환은 CPU를 쓰는 프로세스를 교체하는 작업

## 프로세스 제어 블록 (PCB)

> 프로세스를 실행하는 데 필요한 중요한 정보를 보관하는 자료 구조 — 프로세스마다 하나씩 존재

### PCB의 주요 구성

| 구성 요소 | 내용 |
|---|---|
| 포인터 | 준비 큐·대기 큐 등에서 PCB를 연결하는 데 사용 |
| 프로세스 상태 | 생성·준비·실행·대기·보류 등 현재 상태 |
| 프로세스 구분자 (PID) | 프로세스를 구분하는 고유 번호 |
| 프로그램 카운터 (PC) | 다음에 실행할 명령어의 위치 |
| 프로세스 우선순위 | CPU 스케줄링의 기준이 되는 중요도 |
| 각종 레지스터 정보 | 실행 중 사용하던 레지스터 값들 (중간값 보관) |
| 메모리 관리 정보 | 프로세스가 위치한 메모리 주소, 경계·한계 레지스터 값 등 |
| 할당된 자원 정보 | 사용 중인 파일, 입출력장치 등 |
| 계정 정보 | 계정 번호, CPU 할당 시간, 사용 시간 등 |
| PPID / CPID | 부모 프로세스 구분자 / 자식 프로세스 구분자 |

<details><summary>왜 레지스터 값을 PCB에 저장해야 하는가?</summary>

프로세스가 타임 슬라이스를 다 쓰고 실행을 멈추면, 계산 중이던 중간값이 레지스터에 남아 있다. <br>
이 값을 PCB에 저장해 두지 않으면 다음에 다시 CPU를 받았을 때 이어서 작업할 수 없다. <br>
즉 PCB는 프로세스가 "하던 일을 이어서 하기 위한" 스냅숏 보관소다.
</details>

- 포인터의 용도 : 대기 상태에서는 같은 입출력장치를 기다리는 프로세스의 PCB들이 포인터로 연결됨

## 문맥 교환

> CPU를 차지하던 프로세스가 나가고 새로운 프로세스가 들어오는 작업

### 동작 과정

1. 실행 중이던 프로세스 A의 현재 상태(레지스터 값 등)를 **A의 PCB에 저장**
2. 다음에 실행할 프로세스 B의 **PCB 내용을 CPU 레지스터에 복원**
3. 프로세스 B 실행 시작 (A는 준비 또는 대기 상태로)

### 문맥 교환이 발생하는 경우

- 타임 슬라이스를 모두 사용했을 때 (타임아웃)
- 입출력을 요청했을 때 (블록)
- 인터럽트가 발생했을 때
- 우선순위가 더 높은 프로세스가 도착했을 때 (선점형)

### 문맥 교환의 오버헤드

- PCB 저장·복원, 캐시 초기화, 메모리 관리 정보 갱신 등은 모두 **순수 부가 비용**
- 문맥 교환이 너무 잦으면 실제 작업보다 교환 작업에 시간을 더 쓰게 됨

## 🔑 최종 정리

> 한 줄 요약: PCB는 프로세스의 상태·PC·레지스터 등 실행 정보를 담은 자료 구조이며, 문맥 교환은 나가는 프로세스의 정보를 PCB에 저장하고 들어오는 프로세스의 PCB를 복원하는 작업으로, 멀티태스킹을 가능하게 하는 대신 오버헤드를 수반한다
