# 동적 할당 영역과 시스템 호출 (심화학습)

> 프로세스의 스택·힙 영역이 실행 중에 어떻게 변하는지, 그리고 프로세스 종료를 처리하는 exit()·wait() 시스템 호출

## 프로세스의 동적 할당 영역

> 코드·데이터 영역은 프로세스 시작 시 크기가 확정되는 **정적 할당 영역**, 스택·힙 영역은 실행 중 크기가 변하는 **동적 할당 영역**

| 영역 | 용도 | 크기 변화 |
|---|---|---|
| 코드 영역 | 프로그램 본문 | 고정 (정적) |
| 데이터 영역 | 전역 변수, 정적 변수 | 고정 (정적) |
| 스택 영역 | 함수 호출 시 복귀 주소·지역 변수 저장 | 함수 호출 깊이에 따라 증가/감소 |
| 힙 영역 | malloc() 등으로 사용자가 직접 할당하는 공간 | 요청에 따라 증가/감소 |

- 스택은 메모리의 높은 주소에서 아래로, 힙은 낮은 주소에서 위로 자라며 서로를 향해 커짐

**스택 영역의 동작**

- 함수를 호출하면 복귀 주소와 지역 변수가 스택에 쌓이고(push), 함수가 끝나면 제거됨(pop)
- 재귀 호출이 너무 깊으면 스택이 넘침 → **스택 오버플로**

**힙 영역의 동작**

- `malloc()`으로 할당, `free()`로 반환
- 반환하지 않으면 사용하지 않는 메모리가 계속 쌓임 → **메모리 누수**

<details><summary>지역 변수는 스택에, malloc은 힙에 — 왜 나누는가?</summary>

지역 변수는 함수가 끝나는 시점이 명확하므로 스택에 쌓았다가 자동으로 제거하면 된다. <br>
반면 실행 중에 크기가 정해지거나 함수가 끝난 뒤에도 살아 있어야 하는 데이터는 수명이 코드 구조와 무관하므로, <br>
사용자가 직접 할당(malloc)·해제(free)하는 힙 영역이 필요하다.
</details>

## exit()와 wait() 시스템 호출

### exit()

> 프로세스가 작업을 마치고 종료할 때 호출하는 시스템 호출 — 자신이 종료됨을 부모에게 알림

- `exit(0)` : 정상 종료, `exit(-1)` 등 : 비정상 종료 (인수로 종료 상태 전달)
- C의 main() 함수 `return 0;` 도 결국 exit(0)의 효과

### wait()

> 부모 프로세스가 자식 프로세스가 끝나기를 기다리는 시스템 호출

- 자식이 exit()로 보낸 종료 상태를 부모가 wait()로 받아 자원을 회수
- 부모-자식 간 **동기화** 역할 : 부모가 자식보다 먼저 끝나버리는 상황 방지

**exit() · wait()와 좀비/고아 프로세스**

| 상황 | 결과 |
|---|---|
| 자식이 exit() 했는데 부모가 wait()를 안 함 | 자식이 **좀비 프로세스**로 남음 (PCB 미회수) |
| 부모가 wait() 없이 먼저 종료 | 자식이 **고아 프로세스**가 됨 → init이 거둬 감 |
| 부모가 wait()로 종료 상태 회수 | 자식의 PCB가 정상 정리됨 |

## 🔑 최종 정리

> 한 줄 요약: 스택과 힙은 실행 중 크기가 변하는 동적 할당 영역으로 각각 함수 호출과 사용자 할당을 담당하며, 프로세스는 exit()로 종료를 알리고 부모는 wait()로 이를 회수해야 좀비 프로세스 없이 자원이 정리된다
