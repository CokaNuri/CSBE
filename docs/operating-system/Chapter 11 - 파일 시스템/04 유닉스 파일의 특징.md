# 유닉스 파일의 특징

> 유닉스 철학 : **모든 것은 파일이다** — 장치·디렉터리·파이프까지 파일 인터페이스로 다룸

## 파일의 종류

| 종류 | `ls -l` 표시 | 내용 |
|---|---|---|
| 일반 파일 | `-` | 텍스트, 실행 파일 등 |
| 디렉터리 | `d` | 파일 이름 + i-node 번호 목록 |
| 심볼릭 링크 | `l` | 다른 파일 경로를 담은 파일 |
| 문자 장치 파일 | `c` | 키보드, 터미널 등 — 문자 단위 입출력 |
| 블록 장치 파일 | `b` | 디스크 등 — 블록 단위 입출력 |
| 파이프 / 소켓 | `p` / `s` | 프로세스 간 통신 |

- 장치 파일은 `/dev` 아래 위치 (예 : `/dev/sda`, `/dev/tty`)
- 장치도 `open`, `read`, `write`, `close` 같은 **동일한 시스템 호출**로 사용

---

## 파일 디스크립터

- 프로세스가 연 파일마다 부여되는 **정수 번호**
- 기본으로 열려 있는 3개

| 번호 | 이름 | 대상 |
|---|---|---|
| 0 | 표준 입력 (stdin) | 키보드 |
| 1 | 표준 출력 (stdout) | 모니터 |
| 2 | 표준 에러 (stderr) | 모니터 |

- 리다이렉션(`>`, `<`)과 파이프(`|`)는 이 번호를 다른 파일로 바꿔 끼우는 것

## 접근 권한

```
-rwxr-x---  1 nuri  staff  1024  note.sh
 └┬┘└┬┘└┬┘
 소유자 그룹 기타
```

| 문자 | 의미 | 파일 | 디렉터리 | 숫자 |
|---|---|---|---|---|
| r | 읽기 | 내용 읽기 | 목록 보기 | 4 |
| w | 쓰기 | 내용 수정 | 파일 생성·삭제 | 2 |
| x | 실행 | 프로그램 실행 | 디렉터리 진입 | 1 |

- 대상 3그룹 : **소유자(user) / 그룹(group) / 기타(others)**
- 8진수로 표현 : `rwxr-x---` = 7 5 0 → `chmod 750 note.sh`

<details><summary>디렉터리에 x 권한이 없으면 어떻게 될까?</summary>

r 권한이 있으면 안에 있는 파일 이름 목록은 볼 수 있지만, <br>
x 권한이 없으면 그 디렉터리로 cd 하거나 안의 파일에 접근할 수 없다. <br>
디렉터리의 x는 "통과(검색) 권한"이다.
</details>

## i-node

- 파일마다 하나씩 갖는 **파일 정보 구조체** (파일 디스크립터 역할)
- 저장 내용 : 파일 종류, 권한, 소유자, 크기, 시간 정보, **링크 수**, 데이터 블록 포인터
- **파일 이름은 i-node에 없음** → 이름은 디렉터리 항목에 있음
- 그래서 같은 i-node에 이름을 여러 개 붙이는 **하드 링크** 가능 — 링크 수가 0이 되면 실제 삭제

## 🔑 최종 정리

> 한 줄 요약: 유닉스는 장치·디렉터리·파이프까지 모두 파일로 다뤄 같은 시스템 호출로 사용하며, 프로세스는 파일 디스크립터 번호(0·1·2는 표준 입출력·에러)로 파일에 접근하고, 권한은 소유자·그룹·기타별 rwx(8진수)로 관리하며, 파일 정보는 이름을 제외하고 i-node에 저장된다
