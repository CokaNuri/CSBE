# 디렉터리의 구조

> 디렉터리 : 관련 있는 파일을 하나로 묶어 관리하는 단위 — 그 자체도 **파일**

## 디렉터리의 개념

| 용어 | 내용 |
|---|---|
| 루트 디렉터리 | 최상위 디렉터리 — 유닉스 `/`, 윈도우 `C:\` |
| 현재 디렉터리 | 지금 작업 중인 디렉터리 — `.` |
| 상위 디렉터리 | 한 단계 위 디렉터리 — `..` |
| 서브 디렉터리 | 디렉터리 안의 디렉터리 |

---

## 디렉터리 파일

- 디렉터리도 하나의 **파일** — 내용물이 일반 데이터가 아니라 **파일 정보 목록**
- 각 항목 : 파일 이름 + 파일 정보(또는 정보 위치)
    - 윈도우(FAT) : 디렉터리 항목에 이름·크기·시작 블록 등 직접 저장
    - 유닉스 : 디렉터리 항목엔 **이름 + i-node 번호**만, 나머지 정보는 i-node에
- 파일을 찾을 때 루트부터 디렉터리 파일을 차례로 읽어 내려감

---

## 경로

| 경로 | 기준 | 예 |
|---|---|---|
| 절대 경로 | **루트 디렉터리**부터 전체 경로 | `/home/nuri/os/note.md` |
| 상대 경로 | **현재 디렉터리** 기준 | `../os/note.md` |

- 구분자 : 유닉스 `/`, 윈도우 `\`

---

## 디렉터리 구조

| 구조 | 내용 | 문제 |
|---|---|---|
| 1단계 (단일) | 루트 아래 모든 파일을 한 곳에 | 파일 이름 중복 불가, 관리 어려움 |
| 2단계 | 사용자별 디렉터리 하나씩 | 사용자 안에서 다시 분류 불가 |
| 트리 (계층) | 디렉터리 안에 디렉터리를 무한히 | 대부분 운영체제의 기본 구조 |
| 그래프 | 트리 + **링크**로 다른 위치의 파일 공유 | 순환이 생기면 탐색·삭제 시 무한 루프 위험 |

- 그래프 구조의 링크
    - **하드 링크** : 같은 i-node를 가리키는 또 다른 이름
    - **심볼릭 링크 (바로 가기)** : 원본 경로를 담은 별도 파일
- 순환을 막으려 **비순환 그래프**로 제한하는 경우가 많음

<details><summary>하드 링크와 심볼릭 링크는 원본 삭제 시 어떻게 다를까?</summary>

하드 링크는 같은 i-node를 공유하므로 원본 이름을 지워도 링크 수가 0이 될 때까지 데이터가 남는다. <br>
심볼릭 링크는 경로만 기억하므로 원본이 지워지면 가리킬 대상이 없는 깨진 링크가 된다.
</details>

## 마운트

> 다른 저장장치(파일 시스템)를 현재 디렉터리 트리의 한 지점에 **연결**하는 것

- 연결되는 지점 = **마운트 포인트** (예 : `/mnt/usb`)
- 마운트 후엔 별도 장치라도 하나의 트리처럼 경로로 접근
- 유닉스 계열은 모든 장치를 루트 아래에 마운트 / 윈도우는 장치마다 드라이브 문자(`D:`)를 붙이는 방식
- 네트워크 저장장치도 마운트 가능 (NFS 등)

## 🔑 최종 정리

> 한 줄 요약: 디렉터리는 파일 정보 목록을 담은 특별한 파일로, 경로는 루트 기준(절대)과 현재 위치 기준(상대)으로 나타내며, 구조는 1단계 → 2단계 → 트리 → 링크를 허용한 그래프로 발전했고, 다른 파일 시스템은 마운트로 트리의 한 지점에 연결해 사용한다
