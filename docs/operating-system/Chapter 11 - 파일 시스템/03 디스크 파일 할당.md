# 디스크 파일 할당

> 파일을 디스크의 어떤 블록들에 저장하고, 그 위치를 어떻게 기록할 것인가

## 할당 방식

| 방식 | 내용 |
|---|---|
| 연속 할당 | 파일을 **연속된 블록**에 저장 |
| 불연속 할당 | 빈 블록 아무 데나 저장 — 블록 위치를 **연결** 또는 **인덱스**로 추적 |

---

### 연속 할당

- 파일 테이블에 **시작 블록 + 길이**만 기록
- 장점 : 구조 단순, 순차·직접 접근 모두 빠름 (헤드 이동 최소)
- 단점 : 파일 크기 변화에 취약, 삭제 반복 시 **외부 단편화** → 조각 모음 필요
- 현재는 CD-ROM처럼 한 번 쓰고 바뀌지 않는 매체에 적합

---

### 불연속 할당 — 연결 할당 (블록 체인)

- 각 블록 끝에 **다음 블록 주소**를 저장해 체인처럼 연결
- 파일 테이블엔 **시작 블록(+ 마지막 블록)** 만 기록
- 장점 : 외부 단편화 없음, 파일 크기 늘리기 쉬움
- 단점 : 중간 블록 접근 시 처음부터 따라가야 함 (**직접 접근 느림**), 체인 하나 끊기면 뒷부분 유실

---

### 불연속 할당 — 인덱스 할당

- 파일의 블록 주소들을 모은 **인덱스 블록**을 따로 두고, 파일 테이블은 인덱스 블록을 가리킴
- 장점 : 인덱스만 보면 원하는 블록에 **바로 접근**
- 단점 : 인덱스 블록 공간 필요, 큰 파일은 인덱스 블록 하나로 부족

**유닉스 i-node**

> 인덱스 할당을 다단계로 확장한 구조

| 항목 | 가리키는 대상 |
|---|---|
| 직접 블록 포인터 (12개 내외) | 데이터 블록 |
| 단일 간접 포인터 | 데이터 블록 주소를 담은 블록 |
| 이중 간접 포인터 | 간접 블록 주소를 담은 블록 |
| 삼중 간접 포인터 | 이중 간접 블록 주소를 담은 블록 |

- 작은 파일은 직접 포인터만으로 빠르게, 큰 파일은 간접 포인터로 확장

---

### FAT (File Allocation Table)

> 연결 할당의 "다음 블록 주소"를 블록 안이 아니라 **별도의 테이블**에 모은 방식

- FAT 테이블의 각 칸 = 블록 번호, 칸의 값 = **다음 블록 번호** (끝은 EOF 표시)
- 디렉터리 항목엔 시작 블록만 저장 → FAT을 따라가며 블록 위치 확인
- FAT을 메모리에 올려두면 디스크를 오가지 않고 블록 체인 탐색 가능
- FAT 손상 = 파일 시스템 전체 손상 → 보통 **2개 복사본** 유지
- FAT 뒤 숫자(12/16/32) = 블록 주소 비트 수 → 관리 가능한 최대 용량 결정

| 방식 | 직접 접근 | 단편화 | 추가 공간 |
|---|---|---|---|
| 연속 할당 | 빠름 | 외부 단편화 | 없음 |
| 연결 할당 | 느림 | 없음 | 블록마다 포인터 |
| 인덱스 할당 (i-node) | 빠름 | 없음 | 인덱스 블록 |
| FAT | 테이블 탐색 | 없음 | FAT 테이블 |

---

## 빈 공간 관리

- 파일 삭제 시 데이터 블록을 실제로 지우지 않고 파일 테이블에서 **빈 블록으로 표시**만 함
    - 지우는 데 시간이 오래 걸리기 때문
    - 그래서 덮어쓰기 전이라면 **삭제 파일 복구** 가능
- 빈 블록을 관리하는 방법

| 방법 | 내용 |
|---|---|
| 비트맵 | 블록마다 1비트 — 사용 중/빈 블록 표시 |
| 연결 리스트 | 빈 블록끼리 체인으로 연결 |
| 그룹화 | 빈 블록 하나에 여러 빈 블록 주소를 모아 저장 |
| FAT 방식 | FAT 테이블 값이 0이면 빈 블록 |

<details><summary>파일을 삭제했는데 복구 프로그램으로 살릴 수 있는 이유는?</summary>

삭제 시 파일 테이블에서 "빈 블록"으로 표시만 하고 블록 내용은 그대로 두기 때문이다. <br>
새 파일이 그 블록을 덮어쓰기 전이라면 데이터를 읽어 복구할 수 있다. <br>
완전히 지우려면 블록을 0이나 난수로 덮어써야 한다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 디스크 파일 할당은 연속 할당(빠르지만 외부 단편화)과 불연속 할당으로 나뉘며, 불연속은 블록끼리 잇는 연결 할당, 주소를 모은 인덱스 할당(유닉스 i-node), 연결 정보를 별도 테이블로 뺀 FAT이 있고, 빈 공간은 삭제 시 블록을 지우지 않고 빈 블록으로 표시해 비트맵·연결 리스트 등으로 관리한다
