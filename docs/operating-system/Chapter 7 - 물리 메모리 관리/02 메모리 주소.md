# 메모리 주소

> 메모리의 모든 칸에는 주소가 매겨져 있고, 프로세스가 보는 주소와 실제 주소는 다르다

## 32비트 CPU와 64비트 CPU의 차이

> 여기서 비트 수는 CPU가 **한 번에 처리하는 데이터의 크기 = 주소를 표현하는 비트 수**를 뜻한다

| 구분 | 32비트 CPU | 64비트 CPU |
|---|---|---|
| 한 번에 처리 | 32비트 | 64비트 |
| 레지스터·버스 크기 | 32비트 | 64비트 |
| 표현 가능한 주소 수 | 2³² = 약 43억 개 | 2⁶⁴ (사실상 무제한) |
| 최대 메모리 | 약 **4GB** | 이론상 약 16EB |

- 32비트 CPU는 주소를 32비트로 표현하므로 **최대 4GB**까지만 메모리를 인식 → 그 이상은 꽂아도 못 씀
- 64비트 CPU는 훨씬 큰 메모리를 다룰 수 있고, 한 번에 더 많은 데이터를 처리해 성능이 높음

<details><summary>32비트 CPU가 4GB까지만 쓸 수 있는 이유는?</summary>

주소를 32비트로 표현하므로 서로 다른 주소를 2³²개(약 43억)만 만들 수 있다. <br>
한 주소가 1바이트를 가리키므로 2³² 바이트 = 4GB가 표현 한계이고, <br>
그보다 큰 메모리는 주소를 붙일 수 없어 인식하지 못한다.
</details>

## 논리 주소와 물리 주소

> 프로세스가 사용하는 주소(논리)와 실제 메모리의 주소(물리)를 분리한다

| 구분 | 논리 주소(가상 주소) | 물리 주소 |
|---|---|---|
| 기준 | 프로세스(사용자) 입장 | 실제 하드웨어 메모리 입장 |
| 시작 | 프로세스마다 0번지부터 시작 | 메모리 전체에서의 실제 위치 |
| 사용 주체 | 프로그래머·프로세스 | 메모리 관리자 |

- 프로세스는 자신이 항상 0번지부터 메모리를 쓴다고 생각(논리 주소)하지만, 실제로는 메모리의 다른 위치(물리 주소)에 올라가 있음
- 이 분리 덕분에 프로그래머는 실제 물리 위치를 몰라도 프로그램을 작성할 수 있음

**주소 변환 (논리 → 물리)**

> **MMU(메모리 관리 장치)** 가 논리 주소를 물리 주소로 변환한다

- **재배치 레지스터(기준 레지스터)** : 프로세스가 실제로 올라간 물리 메모리의 시작 주소를 저장
- 변환식 : **물리 주소 = 논리 주소 + 재배치 레지스터 값**
- 예 : 논리 주소 100번지, 재배치 레지스터 5000 → 실제 물리 주소는 5100번지
- **한계 레지스터** : 프로세스가 자기 영역을 벗어나 접근하지 못하게 경계를 검사 (메모리 보호)

## 🔑 최종 정리

> 한 줄 요약: CPU 비트 수는 표현 가능한 주소 범위를 정해 32비트는 최대 4GB까지만 쓸 수 있고, 프로세스가 0번지부터 쓴다고 여기는 논리 주소는 MMU가 재배치 레지스터를 더해 실제 물리 주소로 변환하며 한계 레지스터로 침범을 막는다
