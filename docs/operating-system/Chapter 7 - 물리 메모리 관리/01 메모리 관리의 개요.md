# 메모리 관리의 개요

> 메모리 관리 : 한정된 물리 메모리를 여러 프로세스가 효율적·안전하게 나눠 쓰도록 관리하는 일

## 메모리 관리의 이해

- 프로그램이 실행되려면 반드시 **메모리(RAM)** 에 올라와야 한다
- 메모리는 크기가 한정돼 있으므로, 여러 프로세스가 겹치거나 침범하지 않게 나눠 써야 함
- 운영체제의 **메모리 관리자(MMU 포함)** 가 이 일을 담당

**메모리 관리자가 지켜야 할 원칙**

| 원칙 | 내용 |
|---|---|
| 보호 | 한 프로세스가 다른 프로세스(특히 운영체제)의 영역을 침범하지 못하게 함 |
| 효율 | 메모리 낭비 없이 촘촘히 사용 |
| 공평 | 여러 프로세스에 메모리를 고르게 배분 |

---

## 메모리 관리의 이중성

> 프로세스는 메모리를 **많이·편하게** 쓰고 싶고, 운영체제는 **아껴서·질서 있게** 쓰게 하고 싶다 — 이 상충하는 두 요구

| 입장 | 요구 |
|---|---|
| 프로세스(사용자) | 넉넉한 메모리를 자유롭게, 빠르게 쓰고 싶음 |
| 운영체제(관리자) | 한정된 메모리를 여러 프로세스에 나눠 낭비 없이 관리하고 싶음 |

- 이 둘의 요구가 충돌하는 성질을 **메모리 관리의 이중성**이라 함
- 메모리 관리 기법(가상 메모리, 페이징 등)은 이 이중성을 절충하려는 노력의 산물

## 소스코드의 번역과 실행

> 사람이 쓴 소스코드가 실행 가능한 프로세스가 되기까지의 과정

**컴파일 방식의 단계**

| 단계 | 담당 | 내용 |
|---|---|---|
| 컴파일 | 컴파일러 | 소스코드 → 목적 코드(오브젝트 파일)로 번역, 문법 오류 검사 |
| 링킹(링크) | 링커 | 목적 코드 + 라이브러리를 묶어 하나의 실행 파일 생성 |
| 로딩(적재) | 로더 | 실행 파일을 메모리에 올림 |
| 실행 | CPU | 메모리의 명령어를 실행 |

**번역 방식의 두 종류**

| 방식 | 내용 | 예 |
|---|---|---|
| 컴파일러 | 전체를 한 번에 번역해 실행 파일 생성 (실행 빠름) | C, C++ |
| 인터프리터 | 한 줄씩 번역하며 즉시 실행 (수정·이식 편함) | Python, JavaScript |

## 메모리 관리자의 작업

> 메모리 관리자가 프로세스에 메모리를 배정하며 하는 세 가지 핵심 작업

| 작업 | 질문 | 내용 |
|---|---|---|
| 가져오기 (fetch) | 언제 가져올까? | 프로세스와 데이터를 언제 메모리로 가져올지 결정 (요청 시 vs 미리) |
| 배치 (placement) | 어디에 둘까? | 가져온 프로세스를 메모리의 어느 위치에 놓을지 결정 |
| 재배치 (replacement) | 무엇을 내보낼까? | 메모리가 꽉 찼을 때 어떤 프로세스를 내보낼지 결정 |

<details><summary>메모리 관리자가 '재배치' 작업까지 하는 이유는?</summary>

메모리는 유한하므로 언젠가 가득 찬다. <br>
새 프로세스를 올리려면 기존의 무언가를 스왑 영역으로 내보내야 하는데, <br>
무엇을 내보내야 성능 손해가 가장 적은지 고르는 것이 재배치(교체) 작업이다.
</details>

## 🔑 최종 정리

> 한 줄 요약: 메모리 관리는 한정된 물리 메모리를 여러 프로세스가 보호·효율·공평하게 나눠 쓰게 하는 일로, 프로세스와 운영체제의 상충하는 요구(이중성)를 절충하며, 소스코드는 컴파일·링킹·로딩을 거쳐 실행되고 관리자는 가져오기·배치·재배치 작업을 수행한다
