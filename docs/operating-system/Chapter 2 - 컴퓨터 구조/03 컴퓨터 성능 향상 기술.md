# 컴퓨터 성능 향상 기술

> 장치 간 속도 차이를 극복하고 시스템 전체의 작업 속도를 올리기 위한 기술

## 버퍼

> 속도에 차이가 있는 두 장치 사이에서 그 차이를 완화하는 임시 저장 공간

- 느린 장치에서 데이터를 읽을 때마다 **일정량의 데이터를 모아 한꺼번에 전송**해 CPU가 기다리지 않게 함
- 예 : 하드디스크의 버퍼, 동영상 스트리밍의 버퍼링

**스풀**

> 버퍼를 소프트웨어적으로 구현한 것

- 예 : 프린터의 **스풀러**
- 인쇄할 내용을 스풀러에 저장해 두고, CPU는 다른 작업 수행 가능
- 버퍼와 달리 **한 작업이 끝날 때까지 다른 작업이 끼어들 수 없음** - 프로그램 간 독립성 보장

---

## 저장장치의 계층 구조

> 속도가 빠르고 비싼 장치를 CPU 가까운 쪽에, 느리고 싼 장치를 먼 쪽에 배치하여 <br> 속도와 비용의 균형을 맞추는 구조

```
레지스터  >  캐시  >  메인메모리  >  저장장치
(빠름·비쌈·소용량)  ←──────→  (느림·쌈·대용량)
```

### 캐시

> 메모리와 CPU 간의 속도 차이를 완화하기 위해 메모리의 데이터를 미리 가져다 놓는 임시 저장 공간

- CPU는 메모리에 접근하기 전에 캐시를 먼저 확인
- **캐시 히트** : 원하는 데이터가 캐시에 있어 바로 사용
- **캐시 미스** : 캐시에 없어 메모리까지 가서 가져옴
- 캐시는 CPU 안에 L1, L2 캐시 형태로 존재

**캐시의 쓰기 정책**

| 방식 | 동작 | 장단점 |
|---|---|---|
| 즉시 쓰기 | 캐시에 쓸 때마다 메모리에도 즉시 반영 | 데이터 일관성 유지, 성능 저하 |
| 지연 쓰기 | 캐시에 모았다가 주기적으로 메모리에 반영 | 성능 향상, 일시적 불일치 발생 |

## 인터럽트

> 입출력 장치가 작업을 완료했을 때 CPU에 알려주는 신호


| 구분 | 폴링 | 인터럽트 |
|---|---|---|
| 동작 | CPU가 주기적으로 장치 상태를 직접 확인 | 장치가 작업 완료 시 CPU에 신호를 보냄 |
| CPU 효율 | 확인하는 동안 다른 작업 방해 → 낭비 | 완료 신호가 올 때까지 다른 작업 가능 |

### 인터럽트 방식의 동작 과정

1. CPU가 입출력 관리자에게 입출력 명령을 내림
2. 입출력 관리자가 데이터 전송을 수행
3. 전송이 끝나면 입출력 관리자가 **인터럽트**를 발생시켜 CPU에 알림

**관련 용어**

| 용어 | 내용 |
|---|---|
| 인터럽트 번호 (IRQ) | 어떤 장치에서 인터럽트가 발생했는지 구분하는 번호 |
| 인터럽트 벡터 | 여러 인터럽트를 하나로 묶은 데이터 구조  |
| 인터럽트 핸들러 | 인터럽트 종류별 처리 방법을 담은 함수 |

---

## 직접 메모리 접근 (DMA)

> 입출력 관리자가 CPU의 도움 없이 메모리에 직접 접근할 수 있게 하는 것

- 원래 메모리 접근 권한은 CPU에만 있음
- 데이터 전송을 CPU 없이 처리하려면, 입출력 관리자에게 메모리 접근 권한이 필요 → **DMA**

---

## 메모리 맵 입출력 

> 메모리의 일정 공간을 입출력장치에 할당하는 기법

- DMA가 CPU가 쓰는 메모리 공간을 침범하지 않도록, <br> **CPU가 사용하는 공간과 DMA가 사용하는 공간을 분리**
- 메모리 주소 공간 일부를 입출력장치용으로 나누어 관리

---

## 사이클 훔치기

> CPU와 DMA가 동시에 메모리에 접근하려 할 때, CPU가 양보하여 DMA에 우선권을 주는 것

- CPU 보다 입출력 장치의 속도가 더 느리기 때문

---

## 🔑 최종 정리
