# CPU와 메모리

> CPU는 명령어를 해석하고 실행하는 장치, 메모리는 실행 중인 프로그램과 데이터를 보관하는 장치

## CPU의 구성과 동작

### CPU의 구성 요소

| 구성 요소 | 역할 |
|---|---|
| 산술논리 연산장치 (ALU) | 덧셈·뺄셈 등 산술 연산과 AND·OR 같은 논리 연산 수행 |
| 제어장치 | 명령어를 해석하고 각 장치에 작업 지시 |
| 레지스터 | CPU 내부의 임시 데이터 보관 장소 |

### 레지스터의 종류

**사용자 가시 레지스터** — 프로그램이 직접 사용

| 레지스터 | 역할 |
|---|---|
| 데이터 레지스터 (DR) | 연산에 사용할 데이터 보관 (범용 레지스터) |
| 주소 레지스터 (AR) | 데이터가 위치한 메모리 주소 보관 |

**사용자 불가시 레지스터** — CPU가 내부적으로 사용

| 레지스터 | 역할 |
|---|---|
| 프로그램 카운터 (PC) | 다음에 실행할 명령어의 메모리 주소 보관 |
| 명령어 레지스터 (IR) | 현재 실행 중인 명령어 보관 |
| 메모리 주소 레지스터 (MAR) | 메모리에서 데이터를 가져오거나 보낼 주소 보관 |
| 메모리 버퍼 레지스터 (MBR) | 메모리에서 가져온 데이터나 보낼 데이터를 임시 보관 |
| 프로그램 상태 레지스터 (PSR) | 연산 결과의 상태(양수/음수/오버플로 등) 보관 |

<details><summary>명령어 하나가 실행되는 과정은?</summary>

① PC가 가리키는 주소의 명령어를 MAR·MBR을 거쳐 IR로 가져온다 (fetch) <br>
② 제어장치가 IR의 명령어를 해석한다 (decode) <br>
③ ALU가 연산을 수행하고 결과를 레지스터나 메모리에 저장한다 (execute) <br>
④ PC가 다음 명령어 주소로 증가하고 과정을 반복한다
</details>

### CPU의 명령어 실행 예

`z = x + y` (x=2, y=3) 를 어셈블리로 표현하면 :

```
LOAD  mem(100), register 2;   // 메모리 100번지 값 x를 레지스터 2에 로드
LOAD  mem(120), register 3;   // 메모리 120번지 값 y를 레지스터 3에 로드
ADD   register 5, register 2, register 3;  // 두 값을 더해 레지스터 5에 저장
MOVE  register 5, mem(160);   // 결과를 메모리 160번지(z)로 이동
```

- CPU는 메모리의 값을 레지스터로 가져와 연산하고, 결과를 다시 메모리에 저장한다

### 버스의 종류

| 버스 | 역할 | 방향 |
|---|---|---|
| 제어 버스 | 제어장치의 제어 신호 이동 (읽기/쓰기 지시 등) | 양방향 |
| 주소 버스 | 접근할 메모리 주소·주변장치 번호 이동 | 단방향 (CPU → 외부) |
| 데이터 버스 | 실제 데이터 이동 | 양방향 |

- **버스의 대역폭** : 한 번에 전달할 수 있는 데이터의 최대 크기 — CPU가 한 번에 처리할 수 있는 데이터 크기(워드)와 같음
- 32bit CPU / 64bit CPU 는 버스 대역폭·레지스터 크기·CPU가 한 번에 처리하는 데이터의 크기가 각각 32bit / 64bit 라는 뜻

## 메모리의 종류와 부팅

### 메모리의 종류

**RAM (휘발성 메모리)** — 읽기/쓰기 가능

| 종류 | 특징 |
|---|---|
| DRAM | 일정 시간마다 재생(refresh) 필요. 메인메모리에 사용 |
| SRAM | 전력이 공급되는 동안 데이터 유지. 빠르고 비쌈 → 캐시에 사용 |
| SDRAM | 클록틱에 동기화되어 동작하는 DRAM |

**ROM (비휘발성 메모리)** — 전력이 없어도 데이터 유지

| 종류 | 특징 |
|---|---|
| 마스크 ROM | 제조 시 데이터를 기록, 수정 불가 |
| PROM | 사용자가 한 번만 기록 가능 |
| EPROM | 지우고 다시 기록 가능 |

### 메모리 보호

> 멀티프로그래밍 환경에서 한 프로그램이 다른 프로그램(특히 운영체제)의 영역을 침범하지 못하게 막는 것

- **경계 레지스터** : 작업이 사용할 메모리의 시작 주소 저장
- **한계 레지스터** : 작업이 사용할 메모리의 크기(범위) 저장
- 모든 메모리 접근 시 두 레지스터의 범위를 벗어나는지 하드웨어적으로 검사 → 벗어나면 인터럽트 발생 후 프로그램 강제 종료

### 부팅

> 컴퓨터를 켰을 때 운영체제를 메모리에 올리는 과정

1. 전원을 켜면 ROM에 저장된 **BIOS**가 실행됨
2. BIOS가 하드웨어 이상 유무 검사 — **POST** (Power-On Self-Test)
3. 이상이 없으면 저장장치의 **마스터 부트 레코드(MBR)**에 있는 **부트스트랩** 코드를 메모리로 가져와 실행
4. 부트스트랩이 운영체제를 메모리로 불러옴 → 부팅 완료

## 🔑 최종 정리
