    파일과 파일 시스템¶

    파일 시스템 : 저장장치에 파일을 저장·관리하는 운영체제의 체계 — 사용자는 블록 위치를 몰라도 이름으로 파일에 접근

    파일 시스템의 개요¶

    • 파일 관리자 : 파일 시스템을 운영하는 운영체제의 구성 요소
    • 사용자 → 파일 이름으로 요청 → 파일 관리자가 파일 테이블을 보고 실제 블록 위치로 변환
    기능 내용
    파일 생성·수정·삭제 파일과 디렉터리 관리
    접근 제어 권한 있는 사용자만 접근 허용
    저장 위치 관리 파일이 저장된 블록 주소를 파일 테이블로 관리
    백업·복구, 암호화 데이터 손실·유출 방지

    대표 파일 시스템

    파일 시스템 사용 환경 특징
    FAT (FAT16, FAT32) MS-DOS, 초기 Windows, USB 단순 — 파일 최대 4GB 제한 (FAT32)
    NTFS Windows NT 이후 대용량 지원, 접근 권한·암호화·저널링
    ext (ext2/3/4) 리눅스 i-node 기반, ext3부터 저널링
    HFS+ / APFS macOS APFS는 SSD 최적화
    파일 시스템마다 같은 디스크를 쓰는데 왜 서로 호환이 안 될까? 파일 테이블의 구조(블록 위치를 기록하는 방식)가 파일 시스템마다 다르기 때문이다.
    데이터 블록 자체는 같아도 "어느 블록이 어느 파일인지" 해석하는 규칙이 달라
    해당 파일 시스템을 이해하는 드라이버가 없으면 읽을 수 없다.

    파일¶

    파일의 구성

    구성 내용
    파일 이름 사용자가 파일을 식별하는 이름 (+ 확장자)
    데이터 실제 내용 — 실행 파일 / 데이터 파일
    속성 (메타데이터) 크기, 생성·수정 시간, 소유자, 접근 권한 등

    파일 디스크립터 (파일 제어 블록, FCB)

    운영체제가 파일을 관리하기 위해 유지하는 파일 정보 구조체

    • 파일 이름, 저장 위치(블록 주소), 크기, 접근 권한, 생성 시간 등 보관
    • 사용자는 직접 볼 수 없고 운영체제만 관리
    • 파일을 open 하면 파일 디스크립터를 메모리에 올리고 번호(핸들)를 반환 → 이후 이 번호로 읽기·쓰기

    파일 작업 (시스템 호출)

    작업 내용
    create 파일 생성
    open 파일 디스크립터 확보 — 접근 준비
    read / write 데이터 읽기·쓰기 (파일 포인터 기준)
    close 파일 디스크립터 반환 — 버퍼 내용 반영
    delete / rename 삭제, 이름 변경

    파일의 유형

    유형 내용
    일반 파일 텍스트, 실행 파일 등 사용자 데이터
    디렉터리 파일 다른 파일들의 정보를 담은 파일
    특수 파일 장치를 파일처럼 다루는 파일 — 문자 장치 / 블록 장치

    접근 방식

    방식 내용 예
    순차 접근 앞에서부터 차례로 읽기·쓰기 테이프, 로그 파일
    직접(랜덤) 접근 원하는 위치로 바로 이동해 접근 디스크의 일반 파일, DB

    저장장치 관리 기법¶

    블록

    • 디스크는 섹터 단위지만 파일 시스템은 여러 섹터를 묶은 블록(클러스터) 단위로 관리
    • 블록이 크면 입출력 횟수 감소 / 작은 파일의 내부 단편화 증가

    볼륨과 파티션

    용어 내용
    파티션 하나의 물리 디스크를 여러 논리 영역으로 나눈 것
    볼륨 운영체제가 하나의 저장 공간으로 인식하는 단위 — 여러 디스크를 합쳐 하나로 만들 수도 있음

    포맷

    • 디스크에 파일 테이블을 만들고 빈 공간을 초기화하는 작업
    • 포맷 시 어떤 파일 시스템(FAT, NTFS, ext4…)을 쓸지 결정
    • 빠른 포맷 : 파일 테이블만 새로 만듦 → 데이터 영역은 그대로라 복구 가능

    조각 모음 (defragmentation)

    • 파일 생성·삭제가 반복되면 파일 블록이 디스크 여기저기 흩어짐 (단편화)
    • 흩어진 블록을 연속되게 재배치 → 헤드 이동 감소, 접근 속도 향상
    • SSD는 탐색 시간이 없어 조각 모음 효과가 거의 없고 수명만 줄임

    파일 구조¶

    파일에 저장된 레코드를 어떻게 배치하고 찾을 것인가

    구조 방식 장점 단점
    순차 파일 구조 레코드를 차례대로 저장 공간 낭비 없음, 구조 단순 특정 레코드 검색·삽입·삭제 느림
    인덱스 파일 구조 순차 구조 + 인덱스 테이블 순차·직접 접근 모두 가능 인덱스 저장 공간 필요
    직접 파일 구조 해시 함수로 저장 위치 계산 검색이 매우 빠름 해시 충돌 처리 필요, 공간 낭비 가능
    인덱스 파일 구조가 순차 접근과 직접 접근을 모두 지원하는 이유는? 데이터는 순서대로 저장되어 있으므로 처음부터 차례로 읽을 수 있고,
    인덱스 테이블에서 원하는 키의 위치를 찾아 바로 이동할 수도 있기 때문이다.
    책의 본문(순차)과 찾아보기(인덱스)를 함께 가진 구조와 같다.

    🔑 최종 정리¶

    한 줄 요약: 파일 시스템은 파일 관리자가 파일 테이블로 블록 위치를 관리해 사용자가 이름만으로 파일을 쓰게 해주며, 운영체제는 파일 디스크립터로 파일 정보를 관리하고, 디스크는 파티션·볼륨으로 나누고 포맷으로 파일 테이블을 만들며, 파일 내부는 순차·인덱스·직접(해시) 구조로 레코드를 배치한다
