    분산 시스템¶

    분산 시스템 : 네트워크로 연결된 여러 컴퓨터가 협력해 하나의 시스템처럼 동작하는 구조

    분산 시스템의 개요¶

    장점

    장점 내용
    자원 공유 다른 컴퓨터의 파일·프린터·연산 능력 사용
    연산 속도 향상 작업을 나눠 여러 컴퓨터가 동시에 처리
    신뢰성 한 대가 고장 나도 나머지가 작업 계속
    확장성 컴퓨터를 추가해 성능 확장

    투명성 — 사용자가 분산 사실을 의식하지 않게 하는 성질

    투명성 숨기는 것
    위치 투명성 자원이 어느 컴퓨터에 있는지
    이동 투명성 자원이 다른 곳으로 옮겨졌는지
    복제 투명성 자원이 여러 곳에 복제되어 있는지
    장애 투명성 일부 컴퓨터가 고장 났는지
    병행 투명성 여러 사용자가 동시에 쓰고 있는지
    • 단점 : 구조가 복잡, 네트워크 지연·장애, 보안 취약, 데이터 일관성 유지 어려움

    클라이언트/서버 시스템¶

    서비스를 요청하는 클라이언트와 제공하는 서버로 역할이 나뉜 구조

    • 서버 : 자원·데이터를 갖고 요청을 기다리다 응답 (웹 서버, DB 서버)
    • 클라이언트 : 필요할 때 서버에 요청 (웹 브라우저, 앱)
    • 예 : 웹(HTTP) — 브라우저가 요청, 웹 서버가 HTML 응답
    장점 단점
    데이터가 서버에 모여 관리·보안 용이 요청이 몰리면 서버 과부하
    클라이언트는 가벼워도 됨 서버 장애 시 전체 서비스 중단 (단일 장애 지점)

    P2P 시스템¶

    Peer-to-Peer : 모든 컴퓨터가 클라이언트이자 서버 — 서로 직접 데이터를 주고받음

    • 예 : 토렌트(BitTorrent) — 파일을 조각내 여러 피어에게서 동시에 받고, 받은 조각을 다시 공유
    • 하이브리드 P2P : 사용자 목록·검색은 중앙 서버, 실제 데이터는 피어끼리 (메신저, 초기 냅스터)
    장점 단점
    서버 부하 분산 — 사용자가 늘수록 공급자도 늘어남 데이터 관리·통제 어려움
    단일 장애 지점 없음 불법 공유·저작권, 악성코드 유포 위험
    클라이언트/서버와 P2P는 사용자가 많아질 때 어떻게 다를까? 클라이언트/서버는 사용자가 늘수록 서버 하나에 요청이 몰려 느려진다.
    P2P는 사용자가 곧 데이터 제공자이므로 사용자가 늘수록 받을 수 있는 곳도 늘어
    오히려 전송 속도가 좋아질 수 있다.

    클라우드 컴퓨팅¶

    서버·저장장치·소프트웨어를 직접 갖추지 않고 인터넷을 통해 빌려 쓰는 방식

    • 핵심 기술 : 가상화 — 물리 서버 하나를 여러 가상 머신으로 나눠 제공
    • 쓴 만큼 비용 지불, 필요할 때 자원을 늘리고 줄임 (탄력성)
    서비스 모델 제공 범위 사용자가 관리 예
    IaaS 서버·네트워크·저장장치 (인프라) OS, 미들웨어, 앱 AWS EC2
    PaaS 인프라 + OS·실행 환경 (플랫폼) 앱, 데이터 Heroku, Vercel
    SaaS 완성된 소프트웨어 사용만 Gmail, Google Docs
    배치 모델 내용
    퍼블릭 클라우드 클라우드 업체 자원을 여러 고객이 공유
    프라이빗 클라우드 한 조직 전용
    하이브리드 클라우드 둘을 섞어 사용

    네트워크 저장장치와 고가용성¶

    네트워크 저장장치

    방식 연결 특징
    DAS (Direct Attached Storage) 서버에 직접 연결 빠르고 단순, 다른 서버와 공유 어려움
    NAS (Network Attached Storage) 일반 LAN에 연결 — 파일 단위 공유 여러 서버가 공유, 설치 쉬움, 네트워크 부하에 영향
    SAN (Storage Area Network) 저장장치 전용 네트워크 (광채널) — 블록 단위 고속·대용량, 비쌈

    고가용성 (HA, High Availability)

    장애가 나도 서비스가 멈추지 않고 계속 운영되는 성질

    • 가용성 = 전체 시간 중 정상 운영 시간 비율 — "파이브 나인(99.999%)" = 연간 장애 약 5분
    기법 내용
    이중화 서버·전원·네트워크·디스크(RAID)를 2개 이상 구성
    클러스터링 여러 서버를 묶어 하나처럼 운영
    장애 극복 (failover) 주 서버 장애 시 대기 서버가 자동으로 넘겨받음
    부하 분산 (load balancing) 요청을 여러 서버에 나눠 처리
    하트비트 서버끼리 주기적으로 신호를 주고받아 장애 감지
    구성 내용
    Active-Standby 한 대만 처리, 나머지는 대기 → 장애 시 전환
    Active-Active 모두 처리 → 한 대 장애 시 나머지가 부하 흡수

    🔑 최종 정리¶

    한 줄 요약: 분산 시스템은 여러 컴퓨터를 하나처럼 쓰는 구조로, 서버가 서비스를 제공하는 클라이언트/서버(관리 쉽지만 서버 과부하)와 모두가 서버이자 클라이언트인 P2P(부하 분산, 통제 어려움)가 있고, 클라우드는 가상화로 자원을 빌려 쓰는 IaaS·PaaS·SaaS 모델이며, 저장장치는 DAS·NAS·SAN으로 연결하고 이중화·클러스터링·장애 극복으로 고가용성을 확보한다
